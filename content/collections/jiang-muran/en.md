## 2. vibepanel: A Terminal Console for Heavy AI Agent Users

vibepanel is Jiang Muran's signature work in developer tooling — a web console aimed at users who rely heavily on AI coding agents. The project's core goal is to solve the pain points developers face when running multiple AI agent sessions at once: management chaos, lost state, and difficulty accessing sessions across devices. Unlike traditional terminal multiplexers, vibepanel adopts a front-end/back-end separated architecture, running terminal processes inside a dedicated system service with memory limits and high priority, so that an OOM (out-of-memory) event or crash at the application layer cannot cause session loss. This design philosophy reflects his deep understanding of product stability — for long-running AI agent tasks, session persistence matters far more than a flashy interface.

At the technical architecture level, vibepanel's back end is built in Go and uses tmux as the process manager to keep AI agent sessions persistent. tmux is a terminal multiplexer widely used on servers, capable of keeping processes running after an SSH connection drops; vibepanel folds it into a friendlier web interface, lowering the learning cost of tmux for ordinary developers. The front end is built on a web technology stack and supports accessing the development machine from any device — meaning a developer can start an AI agent task on a desktop at the office, check its progress from a phone on the commute home, or continue interacting from a laptop in the bedroom. This seamless cross-device switching holds significant practical value for developers who need to run model training, code generation, or automated testing tasks for long stretches.

Every aspect of vibepanel's feature design reflects consideration for real work scenarios. The user interface adopts an overall model organized by project and session, presenting the state of every session in every project — finished, running, or waiting for action — in a single unified view. On the right side, an integrated file manager and notepad support transferring files and images via copy and paste, working just as they would on the local machine. At the bottom sits a scratch terminal that lets users inspect files or run other commands while an agent task is running, avoiding the need to interrupt the agent session. vibepanel also includes a dedicated mobile interface with system notification push, and even lets users generate share links to display system status or a comparison of token consumption versus code output on a big screen.

Security design is another hallmark of vibepanel. The project's source code is 100% open source; every release is packaged through a public GitHub Action, producing a dependency-free Go binary that never actively sends any data outward. Upgrading or restarting the panel does not affect running agent sessions. It comes with built-in TLS termination, and access can be restricted with a password or a passkey. Against a backdrop in which AI tools are overwhelmingly cloud-hosted, uploading data to third-party servers, vibepanel's local-first, privacy-first design stands out as genuinely unusual. This "no phoning home" philosophy not only protects users' code and data privacy but also lets enterprise users deploy it safely on internal networks to meet compliance requirements.

The installation and deployment flow has been just as carefully designed, offering multiple installation methods for different network environments: a standard install completes with a single curl command, while a GitHub mirror address is provided for network-restricted environments. Once installed, users can use the `vibepanel service` command family to check status, start, stop, restart, view logs, generate tokens, upgrade, and uninstall; a Docker deployment option is also available. As of September 14, 2026, vibepanel has earned 20 stars and 2 forks on GitHub, with 396 commits in total, released under the MIT license. Judged by star count alone, it has not yet become a phenomenon-level open-source project, but the completeness of its technical architecture and the maturity of its design philosophy already demonstrate a 14-year-old developer's deep understanding of product engineering.

Jiang Muran built three core design principles into vibepanel. First, "the page is a view, not the state" — closing the page, opening it on multiple devices, or reloading it mid-task never affects running sessions; this thorough decoupling of interface from business logic ensures system robustness. Second, "'done' means the process has exited" — completion is not a session going silent and unresponsive, but the process genuinely ending, which avoids misjudgments caused by network latency or interface stutter. Third, "color is never the only way information is conveyed" — ensuring visually impaired users can use it normally, reflecting attention to accessibility design. Together, these three principles — spanning state management, process monitoring, and accessibility — form the design standards a mature developer tool should have.

## 3. ClawFounder: An AI Startup Pipeline Launched with One Sentence

ClawFounder is Jiang Muran's most ambitious project, aiming to provide individual creators and independent developers with a fully automated AI startup support system. A user only needs to hand ClawFounder a startup idea, and the system autonomously completes the entire pipeline: market evaluation, product development, website generation, promotional material production, social media promotion, and progress retrospectives on the product and project. The tech stack is Next.js + FastAPI + Docker + Agents: Next.js provides front-end rendering and routing, FastAPI handles back-end API logic, Docker ensures environment consistency, and Agents orchestrate the execution flow of AI tasks. As an AI collaboration workbench for entrepreneurs, ClawFounder is built around workspaces, containers, and multi-agent pipelines, enabling founders without a technical background to use AI to rapidly validate an idea all the way to a product.

What stands out most about ClawFounder is its tool-integration capability. The system uses Gemini to concretize a vague startup idea into an executable product plan, calls DeepVCode to write code and push it to GitHub, and then has AI agents automatically publish to various platforms. More ingenious still, the system uses ADB (Android Debug Bridge) to let AI control a real phone to complete QR-code scanning and SMS verification, achieving fully automated social media account registration — the entire flow requires no human intervention. In addition, ClawFounder integrates an AI study-assistant feature that can hand multiple textbooks to NotebookLM at once to be consolidated into a thinking framework, generating a podcast for the user to learn from in fragmented time. This design, which connects "startup execution" with "continuous learning," shows his complete understanding of a founder's real workflow.

In March 2026, at the Zhongguancun Latitude Lobster Contest — co-hosted by Zhongguancun Academy and the Zhongguancun AI Research Institute — ClawFounder stood out from hundreds of projects to win the championship of the "Productivity Lobster" track as well as the overall best award, a double honor carrying 200,000 yuan in prize money and a reward of 10 billion tokens. The contest's participants spanned every age group from middle schoolers to PhD students, including veteran entrepreneurs and technical directors at internet companies. During the judges' Q&A at the finals, when Jiang Muran was asked, "If ten thousand entrepreneurs all bought your product, do you think all ten thousand of them would make money?", his answer was clear and calm: "It depends on the initial idea. ClawFounder helps entrepreneurs turn an idea into a product as fast as possible, ahead of everyone else. In the AI era, every gap in capability has been leveled — anyone with AI tools can build a decent product. The biggest difference in ability lies in the idea." The answer revealed his deep understanding of what AI tools fundamentally are: AI is an accelerator, not creativity itself.

## 4. NoteRx: An AI Note-Diagnosis System Built for Xiaohongshu Creators

NoteRx (薯医NoteRx) was developed by the "Page One" team — Jiang Muran together with three peers, Lü Sitong, Yang Xizhe, and Chen Yuxia — at Xiaohongshu's first Hackathon Grand Finals in April 2026. The four members average just 13.5 years old, making them the youngest team in the entire competition. The team name "Page One" evokes "the first page," just as the manifesto they wrote on their poster declares: "Not the creators of the future — we already are, right now."

NoteRx is an AI-powered diagnosis and optimization system for viral notes, with a tech stack of React + FastAPI + AI Agents + ECharts. React builds the responsive user interface, FastAPI provides high-performance back-end services, AI Agents execute content analysis and optimization tasks, and ECharts handles data visualization. Combining data analysis with multi-agent collaboration, the system addresses the real need of Xiaohongshu creators — how to earn more exposure and engagement for their notes — by providing more targeted rewriting suggestions. The technology choices fully account for the product's practical demands: the front end needs a good interactive experience, the back end needs fast responses, the AI part needs flexible agent orchestration, and the data presentation needs intuitive charts.

Across the 48 hours of extreme development, the team demonstrated efficient collaboration and a fast-iterating product mindset: first build a version that was "ugly, but it runs," then correct and iterate bit by bit — ultimately completing the core functionality in under 24 hours and winning the "AI Native" special unit award. This "finish first, perfect later" strategy is the very heart of the hackathon spirit. After the competition, a company approached the team with an offer to buy the project outright, but Jiang Muran and his teammates declined, because they valued the project itself and the team's room to grow more highly.

## 5. A Developer Toolchain: Claude in Box, TypeBox, and AI Document Tools

Around the goal of "letting developers work efficiently in any environment," Jiang Muran has built a series of tool-type projects that together form a complete developer toolchain.

Claude in Box is a portable development environment that packs Claude Code into Docker, with a tech stack of Go + Docker + Claude Code + DevOps. The project supports multiple sessions, hook-driven workflows, web management, and a transparent SOCKS5 proxy — and it can even run directly on a Raspberry Pi. Choosing Go as the core language reflects his command of systems programming; Docker ensures environment consistency and portability; and Raspberry Pi support showcases his interest in embedded systems. The project's practicality lies in letting developers quickly spin up a complete AI development environment on any device, without worrying about dependency installation or environment configuration.

TypeBox is a purely local, offline-first browser toolbox, with a tech stack of Vue 3 + Vite + ffmpeg.wasm + PWA. The project includes a Markdown editor, an image suite, an audio-video workbench (ffmpeg.wasm), a Python IDE, and developer tools — and by default, files never leave the device. Vue 3 provides a reactive front-end framework, Vite ensures a fast development build experience, ffmpeg.wasm brings powerful audio-video processing into the browser, and PWA lets the web app run offline like a native application. TypeBox's design philosophy is of a piece with vibepanel's: local first, privacy first, feature complete.

Three more projects on this toolchain revolve around AI capabilities. Claude Image is an Agent Skill package that teaches Claude Code/Codex to make good use of gpt-image-2, integrating image generation into the coding agent's workflow in a standardized way. AIDocGenius is built around document understanding, summarization, and structured output, helping users quickly extract useful information from unstructured documents. FileHelper Chatbot combines file assistance with conversational capability, letting file management and Q&A happen within the same chat interface.

## 6. Graphics, Hardware, and Voice: WebMC, CNCDraw, and Hachimi

Jiang Muran's project portfolio is not confined to web applications; it extends into lower-level technical domains such as graphics rendering, hardware control, and mobile voice interaction.

WebMC is a from-scratch (clean-room) implementation of a web-based Minecraft, with a tech stack of WebGPU + TypeScript + Graphics + Voxel. The project renders and explores a voxel world directly in the browser, demonstrating his grounding in graphics programming and web technology. WebGPU is the low-level graphics API offered by modern browsers, TypeScript provides a type-safe JavaScript development experience, and voxels are the core data structure of the Minecraft world. Choosing WebGPU over WebGL shows that he keeps pace with the latest developments in web graphics technology and is willing to adopt cutting-edge, not-yet-fully-mainstream technology to build projects.

CNCDraw is a Python toolkit for pen plotters and drawing machines, with a tech stack of Python + FastAPI + G-code + MCP. The project includes a self-developed .tfont trajectory font, typesetting and G-code generation (Grbl/EBB/Marlin), camera closed-loop calibration, and a FastAPI web UI with an MCP agent interface. Python implements the core algorithms, FastAPI provides the web management interface, G-code is the standard command language of CNC equipment, and MCP (Model Context Protocol) is the protocol through which AI agents interact with external systems. This project demonstrates his ability to combine software with hardware, as well as his grasp of industrial control protocols.

Hachimi is a lightweight agent-style voice assistant running on Android, extending the interaction form of AI agents from desktop to mobile. Together with Claude in Box's support for the Raspberry Pi, it embodies his consistent pursuit of "letting AI capabilities run on any device."

## 8. The Engineering Philosophy Running Through 12 Projects

Looking across Jiang Muran's 12 open-source projects, several recurring design principles can be distilled — together they form this young developer's engineering philosophy.

First, local first and privacy first. vibepanel sends no data outward; TypeBox's files never leave the device by default. Against a backdrop in which cloud hosting has become the default choice, this design seems exceptionally clear-headed — tools should belong to their users, not turn users into producers of data.

Second, stability above feature count. vibepanel isolates processes inside a dedicated system service with memory limits; Claude in Box locks in environment consistency with Docker. Both embody the same judgment: a system that runs without problems for a long time is more valuable than a feature-laden one.

Third, separation of interface and state. The principle that "the page is a view, not the state" guarantees robustness across devices and sessions, and it is the architectural foundation that lets vibepanel support seamless switching among phone, tablet, and computer.

Fourth, open source and verifiability. Every project is open-sourced under the MIT license; every release of vibepanel is packaged through a public GitHub Action into a dependency-free Go binary — users don't need to trust the author; they only need to review the code.

Jiang Muran writes on his personal website: "My goal is to find patterns in complex noise, to use algorithms and AI to simulate the texture of reality. From algorithm competitions to the open-source community, from embedded hardware to AI agents, every line of code is my way of conversing with the technical world." This understanding of code as "a logical language for deconstructing the world" goes beyond the instrumental view of programming held by many adult developers. For him, code is not only a means of implementing features but also a medium for understanding the world, expressing ideas, and creating value.

## 10. Reflections on Education in the AI Era

On March 28, 2026, at the AI education session of the third Zhongguancun Forum's "AI Theme Day," Jiang Muran gave a 30-minute talk to an audience of several hundred adult guests. He put forward a deliberately provocative thesis: "In the past, the focus of learning was recording answers. In the future, learning is about asking questions, judging answers, and using the answers in your hands to create new things." The statement cuts straight to the core shift in the educational paradigm of the AI era: when AI can produce an answer to any question within seconds, the value of memorizing and repeating knowledge plummets, while the ability to ask questions, think critically, and apply knowledge creatively becomes the new core competitiveness.

He laid out a methodology for AI-assisted learning along three directions. First, personalized learning: hand textbooks, slide decks, recordings, and online courses all to AI, let it organize the curriculum system and provide one-on-one tutoring on individual knowledge points — "the equivalent of giving every student a top-tier teacher." Second, timely feedback: when studying subjects like physics, you can have AI lead you deep into a knowledge point at any time, connecting chains of thought across disciplines. Third, from doing exercises to doing tasks: use AI to carry out projects, build works, and create videos, making the forms of learning more diverse rather than confined to quantifiable problem sets. Together, these three directions point to one goal: making AI the "scaffolding" of learning, not a "ghostwriter" that replaces thinking.

He takes a clear, unequivocal stand against using AI to complete homework directly, arguing that it outsources thinking and creativity — essentially no different from copying homework with question-search apps — and he describes the practice as "destroying your own future." He admits he was once misled by AI for three days, and he has distilled four methods for keeping from being led astray. First, judgment: AI can spout nonsense with a perfectly straight face and even turn around and question its user, so human judgment is one's own foundation. Second, asking questions: when you can't follow a line of reasoning, you can tell the AI to "pretend to explain it in words an eighty-year-old grandmother could understand." Third, creativity: AI can only polish articles, build websites, and write code; it does not possess genuine creative ability, so the user must be clear about their own goals and break tasks down into concrete steps — AI is essentially a probability machine with limited understanding of the real world. Fourth, action: AI can quickly provide a product prototype, but the path from prototype to launch, promotion, marketing, and the final defense is a complete pipeline; AI can only assist with the tedious segments and cannot connect the whole chain — "with AI you'll only be busier than before, and more efficient; the price is that you'll be doing more things at the same time."

He also offered three suggestions to anxious parents. First, change the way you accompany your child: rather than fixating on whether the child has mastered specific knowledge, parents should ask, "How did you think your way to this layer? What did your chain of thought look like?" Second, don't look only at results — look at the process: judging a child solely by outcomes leads to homogenized abilities; core thinking ability has to be built through one's own effort. Third, Chinese, math, and English are three subjects that cannot be dropped: he candidly admits that his Chinese and math grades are middling-to-lower in his class, which sometimes leaves him unable to describe his requirements clearly to AI; math trains logical reasoning, Chinese trains expression, and English matters because core literature and top-tier AI technology are mostly in English — without English, you can barely move an inch.

At the end of his talk, he posed a question to everyone present: "If AI can give you an answer in ten seconds, are you willing to spend ten minutes thinking it through yourself? If you are, it means you have the foundation to command AI and orchestrate it. If you're not, then you may just be an ordinary person who knows how to use AI." He emphasized: "In the AI era, results are the cheapest thing. What truly matters is your thinking process." This cherishing of the thinking process is inseparable from the informatics training he received from childhood — Zhang Xingang's teaching method of "having him walk through his reasoning from the beginning" was, in essence, cultivating his sensitivity to and control over the thinking process.

## Conclusion

Jiang Muran's story is a sample of the democratization of technology in the AI era. From encountering C++ in fifth grade to becoming a full-stack developer by eighth grade, the 12 open-source projects he built independently cover a broad spectrum — from the browser to the Raspberry Pi, from AI agents to CNC hardware. What these projects share is a local-first, privacy-first, stability-first, open-source ethos — an engineering judgment in technology choices that exceeds his age.

On the educational front, the philosophy he articulates — "use AI as scaffolding, but never outsource the thinking" — underscores the central place of judgment, questioning, creativity, and action in the AI era. His hands-on experience shows that AI can be an accelerator of learning, but it can never replace the process of thinking.

Looking ahead, the questions Jiang Muran faces are how to deepen his professional domains while maintaining technical sensitivity, how to explore sustainable models of collaboration while holding to open-source ideals, and how to preserve his original passion for learning while expanding his influence. But whatever the future holds, he has already proven one thing through action: in the AI era, "you don't have to wait until you grow up to start making things." As the line he wrote on his personal website puts it: "Stay curious, keep building. May you leave your own mark in the waves of technology."
