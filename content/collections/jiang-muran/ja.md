## 2. vibepanel：ヘビーなAIエージェント利用者のためのターミナルコンソール

vibepanelは姜睦然の開発者ツール分野における代表作で、AIコーディングエージェントに強く依存するユーザーのためのWebコンソールという位置づけだ。このプロジェクトの中核的な目標は、複数のAIエージェントセッションを同時に実行する開発者が直面する、管理の混乱、状態の喪失、デバイス間アクセスの困難といったペインポイントを解決することにある。従来のターミナルマルチプレクサとは異なり、vibepanelはフロントエンドとバックエンドを分離したアーキテクチャを採用し、ターミナルプロセスをメモリ上限と高優先度を設定した専用のシステムサービス内で実行する。これにより、アプリケーション層のOOM（メモリ不足）やクラッシュがセッション喪失につながることを防いでいる。この設計哲学は、プロダクトの安定性への深い理解を体現している——長時間実行されるAIエージェントタスクにとって、セッションの永続性はインターフェースの華やかさよりもはるかに重要なのだ。

技術アーキテクチャの面では、vibepanelのバックエンドはGo言語で開発され、プロセスマネージャーとしてtmuxを使ってAIエージェントセッションの永続性を維持している。tmuxはサーバー環境で広く使われるターミナルマルチプレクサで、SSH接続が切れてもプロセスを動かし続けることができる。vibepanelはこれをより使いやすいWebインターフェースに統合し、一般的な開発者がtmuxを使う際の学習コストを下げた。フロントエンドはWeb技術スタックで構築され、あらゆるデバイスから開発マシンにアクセスできる。つまり開発者は、オフィスのデスクトップでAIエージェントタスクを開始し、帰宅途中にスマートフォンで進捗を確認し、寝室のノートパソコンで操作を続行できる。このデバイス間のシームレスな切り替え能力は、モデルの学習、コード生成、自動テストなどの長時間タスクを必要とする開発者にとって、大きな実用価値を持つ。

vibepanelの機能設計には、実際の作業シーンへの配慮が随所に見られる。ユーザーインターフェースはプロジェクトとセッションに基づく全体モデルを採用しており、一つの統合ビューで各プロジェクト内の各セッションの状態——完了、実行中、操作待ち——を直感的に確認できる。右側にはファイルマネージャーとメモ帳が統合され、コピー＆ペーストでファイルや画像を転送でき、操作感はローカルマシンでの操作そのものだ。下部には一時ターミナルがあり、エージェントタスクの実行中にファイルを確認したり別のコマンドを実行したりでき、エージェントセッションを中断する手間を省ける。さらに、vibepanelにはスマートフォン専用の独立インターフェースも用意され、システム通知のプッシュに対応し、共有リンクを生成してシステムの状態やトークン消費量とコード産出量の対比を大画面に表示することさえできる。

セキュリティ設計もvibepanelの大きな特徴だ。プロジェクトのソースコードは100%オープンソースで、各バージョンは公開されたGitHub Actionでパッケージングされ、最終成果物は依存関係のないGoバイナリとなり、外部へデータを自発的に送信することは一切ない。パネルのアップグレードや再起動は実行中のエージェントセッションに影響せず、TLS終端機能を内蔵し、パスワードやパスキー（passkey）でアクセスを制限できる。現在、AIツールの多くがクラウドホスティングを採用し、データを第三者のサーバーにアップロードする中で、vibepanelのローカルファースト、プライバシーファーストの設計は際立ってユニークだ。この「Phone Homeしない」（外部サーバーに自発的に接続しない）という設計理念は、ユーザーのコードとデータのプライバシーを守るだけでなく、企業ユーザーがイントラネット環境で安全にデプロイし、コンプライアンス要件を満たすことも可能にする。

インストールとデプロイの流れも入念に設計されており、異なるネットワーク環境に対応する複数のインストール方法が用意されている。標準インストールはcurlコマンド一発で完了し、ネットワークが制限された環境向けにはGitHubミラーアドレスが提供される。インストール完了後、ユーザーはvibepanel service系コマンドで、状態確認、起動、停止、再起動、ログ確認、トークン生成、アップグレード、アンインストールなどの操作が可能で、Dockerによるデプロイオプションも提供される。2026年9月14日時点で、vibepanelはGitHubで20のStarと2のForkを獲得し、累計396回のコミットがあり、MITライセンスを採用している。Starの数だけ見れば、まだ現象級のオープンソースプロジェクトとは言えないが、その技術アーキテクチャの完成度と設計哲学の成熟さは、14歳の開発者によるプロダクトのエンジニアリングへの深い理解をすでに示している。

姜睦然はvibepanelに三つの中核的設計原則を組み込んだ。第一に「ページはビューであり、状態ではない」——ページを閉じても、複数のデバイスでページを開いても、途中でリロードしても、実行中のセッションには影響しない。このインターフェースとビジネスロジックを徹底的に分離する設計が、システムの堅牢性を担保する。第二に「『完了』とはプロセスが終了したことを意味する」——セッションが無反応になったのではなく、プロセスが本当に終了して初めて完了とみなす。これにより、ネットワーク遅延やインターフェースのカクつきによる誤判定を防ぐ。第三に「色は情報を伝える唯一の手段であってはならない」——視覚に障害のあるユーザーも正常に使えることを保証し、アクセシビリティへの配慮を体現する。この三つの原則は、状態管理、プロセス監視、アクセシビリティという三つの次元から、成熟した開発者ツールに求められる設計規範を構築している。

## 3. ClawFounder：一言で起動するAIスタートアップ・パイプライン

ClawFounderは姜睦然の最も野心的なプロジェクトで、個人クリエイターやインディー開発者に全自動のAI起業支援システムを提供することを目指している。ユーザーはClawFounderに起業アイデアを一つ伝えるだけで、システムが市場評価、プロダクト開発、ウェブサイト生成、プロモーション素材の制作、SNSでの拡散、プロダクトの進捗振り返りまでの全工程を自律的にこなす。技術スタックはNext.js + FastAPI + Docker + Agentsを採用。Next.jsがフロントエンドのレンダリングとルーティングを担い、FastAPIがバックエンドAPIのロジックを処理し、Dockerが環境の一貫性を保証し、AgentsがAIタスクの実行フローをオーケストレーションする。起業家向けのAIコラボレーションワークベンチとして、ClawFounderはワークスペース、コンテナ、マルチエージェントのフローを軸に、技術的なバックグラウンドを持たない起業家でもAIを使ってアイデアからプロダクトまでの高速検証を行えるようにする。

ClawFounderで最も目を引くのは、そのツール統合能力だ。システムはGeminiを使って漠然とした起業アイデアを実行可能なプロダクトプランに具体化し、DeepVCodeを呼び出してコードを書きGitHubにプッシュし、さらにAIエージェントが各プラットフォームへ自動で公開する。さらに巧妙なのは、ADB（Android Debug Bridge）を介してAIが実際のスマートフォンを操作し、QRコードのスキャンやSMS認証を完了させることで、SNSアカウント登録の完全自動化を実現している点だ——プロセス全体に人の介入は不要である。またClawFounderはAI学習アシスタント機能も統合しており、複数の教科書をまとめてNotebookLMに渡して思考フレームワークに統合し、ポッドキャストを生成して、ユーザーが隙間時間に学習できるようにする。この「起業の実行」と「継続的な学習」をつなげる設計は、起業家の実際のワークフローへの全体的な理解を示している。

2026年3月、ClawFounderは中関村学院と中関村人工知能研究院が共催した「中関村北緯ロブスター大会」において、数百のプロジェクトの中から抜きん出て、「プロダクティビティ・ロブスター」部門のトラックチャンピオンと全場ベストの二冠大賞を獲得し、20万元の賞金と100億トークンの報奨を得た。このコンテストの参加者は中学生から博士課程の学生まで幅広い年齢層にわたり、ベテラン起業家やインターネット企業の技術ディレクターも含まれていた。決勝の審査員による質問セッションで、姜睦然が「もし1万人の起業家があなたのプロダクトを買ったら、その1万人全員が稼げると思いますか」と問われたとき、彼の答えは明快で冷静だった——「最初のidea（アイデア）次第です。ClawFounderは、起業家が誰よりも早くアイデアをプロダクトにする手伝いをします。AI時代には、あらゆる能力の溝はすでに埋められていて、AIツールさえあれば誰でもそれなりのプロダクトを作れます。最大の能力差はアイデアにあります」。この回答は、AIツールの本質への深い理解を示している。AIはアクセラレーターであり、創造力そのものではないのだ。

## 4. NoteRx：XiaohongshuクリエイターのためのAIノート診断システム

NoteRxは、姜睦然と呂思彤、楊曦哲、陳宇夏という三人の同年代の仲間で構成される「Page One」チームが、2026年4月のXiaohongshu（RED）第1回ハッカソン頂上大会で開発したプロダクトだ。メンバー四人の平均年齢はわずか13.5歳で、会場で最も若い参加チームだった。チーム名「Page One」は「最初のページ」を意味し、彼らがポスターに記した宣言の通りだ。「未来の創造者ではない。私たちは今すでに創造者だ」。

NoteRxはAIバズノート診断・最適化システムで、技術スタックはReact + FastAPI + AI Agents + ECharts。Reactがレスポンシブなユーザーインターフェースの構築を担い、FastAPIが高性能なバックエンドサービスを提供し、AI Agentsがコンテンツ分析と最適化タスクを実行し、EChartsがデータの可視化を行う。システムはデータ分析とマルチエージェントの協調を組み合わせ、Xiaohongshuクリエイターの実際のニーズ——自分のノートにより多くの露出とインタラクションを得るにはどうすればよいか——に対し、より的を絞ったリライト提案を提供する。この技術選定はプロダクトの実際の要求を十分に考慮したものだ。フロントエンドには優れたインタラクション体験が、バックエンドには高速な応答が、AI部分には柔軟なエージェントオーケストレーションが、データ表示には直感的なチャートが求められる。

48時間の極限の開発の中で、チームは高い協働能力と高速イテレーションのプロダクト思考を見せた。まず「不格好だが動く」バージョンを作り、それから少しずつ修正・改善を重ね、最終的に24時間足らずでコア機能の開発を完了させ、「AIネイティブ」特別部門賞を獲得した。この「まず完成、完璧は後から」という戦略こそ、ハッカソン精神の中核的な体現だ。コンテスト終了後、ある企業がチームに商業買収の意向を示したが、姜睦然とチームメイトたちは断った。彼らがより重視したのは、プロジェクト自体の価値とチームの成長の余地だったからだ。

## 5. 開発者ツールチェーン：Claude in Box、TypeBox、そしてAIドキュメントツール

「開発者がどんな環境でも効率的に働けるようにする」という目標を掲げ、姜睦然は一連のツール型プロジェクトを開発し、それらが一体となって完全な開発者ツールチェーンを構成している。

Claude in Boxは、Claude CodeをDockerに詰め込んだポータブル開発環境で、技術スタックはGo + Docker + Claude Code + DevOps。マルチセッション、Hook駆動、Web管理、透過SOCKS5プロキシをサポートし、Raspberry Pi上で直接動かすことさえできる。中核言語としてGoを選んだことはシステムレベルプログラミングへの習熟を、Dockerは環境の一貫性と移植性を、Raspberry Piへの対応は組み込みシステムへの興味を示している。このプロジェクトの実用性は、開発者がどんなデバイス上でも完全なAI開発環境を素早く構築でき、依存関係のインストールや環境設定を気にする必要がない点にある。

TypeBoxは、完全ローカルでオフラインファーストのブラウザツールボックスで、技術スタックはVue 3 + Vite + ffmpeg.wasm + PWA。Markdownエディター、画像スイート、音声・動画ワークベンチ（ffmpeg.wasm）、Python IDE、開発者ツールを含み、ファイルはデフォルトでデバイスから出ない。Vue 3がリアクティブなフロントエンドフレームワークを提供し、Viteが高速な開発ビルド体験を保証し、ffmpeg.wasmが強力な音声・動画処理能力をブラウザにもたらし、PWAがWebアプリをネイティブアプリのようにオフラインで動作させる。TypeBoxの設計理念はvibepanelと一貫している。ローカルファースト、プライバシーファースト、そして機能の充実だ。

このツールチェーンには、AIの能力を軸にしたプロジェクトがさらに三つある。Claude Imageは、Claude Code／Codexにgpt-image-2を上手に使わせるためのAgent Skillパッケージで、画像生成能力を規範化された形でコーディングエージェントのワークフローに組み込む。AIDocGeniusはドキュメントの理解、要約、構造化出力を軸に構築され、ユーザーが非構造化ドキュメントから有効な情報を素早く抽出するのを助ける。FileHelper Chatbotは、ファイルアシスタントと対話能力を組み合わせ、ファイル管理と質疑応答を同じ会話インターフェースで完結できるようにする。

## 6. グラフィックス、ハードウェア、音声：WebMC、CNCDraw、Hachimi

姜睦然のプロジェクト群はWebアプリケーションにとどまらず、グラフィックスレンダリング、ハードウェア制御、モバイル音声インタラクションといった、より低レイヤーの技術領域にまで及んでいる。

WebMCはゼロから実装した（クリーンルーム方式の）Web版Minecraftで、技術スタックはWebGPU + TypeScript + Graphics + Voxel。ブラウザ上で直接ボクセルの世界をレンダリングし探索するこのプロジェクトは、グラフィックスプログラミングとWeb技術における彼の実力を示している。WebGPUはモダンブラウザが提供する低レベルグラフィックスAPIで、TypeScriptは型安全なJavaScript開発体験をもたらし、Voxel（ボクセル）はMinecraftの世界の中核的データ構造だ。WebGLではなくWebGPUを選んだことは、彼がWebグラフィックス技術の最新動向を追い、先端的だがまだ十分に普及していない技術を進んでプロジェクトに採用することを示している。

CNCDrawは、ペン式ライティングマシン／プロッターのためのPythonツールセットで、技術スタックはPython + FastAPI + G-code + MCP。独自開発の.tfont軌跡フォント、レイアウトとG-code生成（Grbl／EBB／Marlin対応）、カメラによる閉ループキャリブレーション、FastAPIのWeb UIとMCPエージェントインターフェースを備える。Pythonが中核アルゴリズムの実装を担い、FastAPIがWeb管理インターフェースを提供し、G-codeは数値制御装置の標準命令言語、MCP（Model Context Protocol）はAIエージェントが外部システムとやり取りするためのプロトコルだ。このプロジェクトは、ソフトウェアとハードウェアを結びつける彼の能力と、産業制御プロトコルへの習熟を示している。

HachimiはAndroid上で動作する軽量なAgent型音声アシスタントで、AIエージェントのインタラクション形態をデスクトップからモバイルへと拡張した。Claude in BoxのRaspberry Pi対応と併せて、「AIの能力をあらゆるデバイスで動かす」という彼の一貫した追求を体現している。

## 7. セキュリティ実践：ClawGuardとCNNVDへの脆弱性報告

セキュリティは、姜睦然のプロジェクト群の中で見過ごされがちだが、非常に重い比重を持つ部分だ。ClawGuardはホストセキュリティ、環境監査、リスクチェックを中心に設計されたプロジェクトで、まさにその開発経験が、彼の「機能志向」から「安定性とセキュリティ志向」への理念の転換を促した。

2025年、彼はUGREEN（緑聯）製システムのセキュリティ脆弱性を独力で発見・再現し、報告書を国家信息安全漏洞庫（CNNVD）に提出して、中リスク脆弱性の認定証を取得した。中学生が独立した研究者として、脆弱性の発見から再現、規範に則った報告までの全工程を完遂する例は、セキュリティ分野では珍しい。セキュリティの実践は、逆に彼のプロダクト観も形作った——vibepanelの「Phone Homeしない」設計、ローカルファーストのアーキテクチャ、TLS終端とpasskeyによるアクセス制御は、いずれもこのセキュリティ意識が一般的なプロダクトに落とし込まれたものと見ることができる。彼の言葉を借りれば、「長期間問題なく動き続けるものを作るほうが、機能をいくつか増やすよりずっと難しい。かっこよくは聞こえないけれど、誰かがやらなければならない」。

## 8. 12のプロジェクトを貫くエンジニアリング哲学

姜睦然の12のオープンソースプロジェクトを俯瞰すると、繰り返し現れるいくつかの設計原則を抽出できる。それらがこの少年開発者のエンジニアリング哲学を成している。

第一は、ローカルファーストとプライバシーファースト。vibepanelは外部に一切のデータを送信せず、TypeBoxのファイルはデフォルトでデバイスから出ない。この設計は、クラウドホスティングがデフォルトの選択肢となった現在において、とりわけ清醒的だ——ツールは使う人のものであるべきで、使う人をデータの生産者に変えてしまうべきではない。

第二は、機能の数より安定性。vibepanelがプロセスをメモリ上限付きの専用システムサービスに隔離し、Claude in BoxがDockerで環境の一貫性を固定しているのは、いずれも同じ判断の表れだ。長期間問題なく動くシステムは、機能の多いシステムより価値がある。

第三は、インターフェースと状態の分離。「ページはビューであり、状態ではない」という原則が、デバイス間・セッション間の堅牢性を保証し、vibepanelがスマートフォン、タブレット、パソコン間のシームレスな切り替えを実現するアーキテクチャの基盤となっている。

第四は、オープンソースと検証可能性。すべてのプロジェクトがMITライセンスでオープンソース化され、vibepanelの各バージョンは公開されたGitHub Actionでパッケージングされ、成果物は依存関係のないGoバイナリだ——ユーザーは作者を信頼する必要はなく、コードを審査すればよい。

姜睦然は個人サイトにこう記している。「私の目標は、複雑なノイズの中から法則を見つけ出し、アルゴリズムとAIで現実の肌理をシミュレートすることだ。アルゴリズムコンテストからオープンソースコミュニティへ、組み込みハードウェアからAIエージェントへ、一行一行のコードが、私と技術の世界との対話の方法だ」。コードを「世界を解体して理解する論理言語」と見なすこの認識は、プログラミングを道具として捉える多くの成人開発者の理解を超えている。彼にとってコードは、機能を実現する手段であるだけでなく、世界を理解し、思想を表現し、価値を創造するメディアなのだ。

## 10. AI時代の教育への考察

2026年3月28日、第3回中関村フォーラム「人工知能テーマデー」のAI教育特別イベントで、姜睦然は数百人の成人の聴衆を前に30分間の講演を行った。彼は一つの「過激な論」を提起した。「これまでの学習の重点は答えを記録することだった。これからの学習は、問いを立て、答えを判定し、手元にある答えを使って新しいものを創造することだ」。この視点は、AI時代の教育パラダイムの中核的転換を突いている。AIがあらゆる問いの答えを数秒で出せるようになったとき、知識を暗記し復唱する価値は急激に低下し、問いを立て、批判的に考え、創造的に応用する能力が新たな中核競争力となる。

彼はAI補助学習の方法論を三つの方向で具体的に説明した。第一に、パーソナライズド学習。教科書、PPT、録音、オンライン授業をすべてAIに渡し、AIにカリキュラム体系を整理させ、一対一の知識ポイント指導を受ける。「全員にトップレベルの先生が一人ずつつくようなものだ」。第二に、タイムリーなフィードバック。物理などの科目を学ぶ際、いつでもAIに知識ポイントへ深く潜ってもらい、学際的な思考チェーンをつなぐことができる。第三に、問題を解くことからタスクに取り組むことへ。AIを使ってプロジェクトを進め、作品を作り、動画を制作し、学習の形式を、定量化された問題に限定するのではなく多様化する。この三つの方向は、一つの目標を共に指している。AIを学習の「足場」にすることであり、思考を代替する「ゴーストライター」にしてはならない。

彼はAIに宿題を直接やらせることに明確に反対している。それは思考と創造の能力を外部委託することになり、以前の問題検索アプリで宿題を写すのと本質的に同じだと考え、こうした行為を「自らの前途を毀損する」と表現した。彼は自分自身がAIに三日間惑わされた経験を率直に語り、迷走を防ぐ四つの方法をまとめた。一つ目は判断力——AIは真顔でデタラメを言うことがあり、時には利用者に逆に疑問を投げかけてくることさえある。人間の判断力が自分の土台である。二つ目は質問力——理解できない推論に出会ったら、AIに「80歳のおばあちゃんにも分かる言葉で説明するふりをして」と頼むことができる。三つ目は創造力——AIは文章の推敲、ウェブサイトの制作、コードの記述はできるが、真の創造能力は持たない。利用者は自分の目標を明確にし、タスクを具体的なステップに分解しなければならない。AIは本質的に確率機械であり、現実世界の認識には限界がある。四つ目は行動力——AIはプロダクトのプロトタイプを素早く提供できるが、プロトタイプから実装、宣伝、拡販、プレゼンまでが完全なプロセスであり、AIが手伝えるのは煩雑な部分だけで、全チェーンをつなぐことはできない。「AIがあっても、あなたは以前より忙しくなるだけだ。効率は上がるが、その代償として同時により多くのことをこなすことになる」。

彼は不安を抱える親たちにも三つのアドバイスを贈った。まず、寄り添い方を変えること。子どもが具体的な知識を身につけたかどうかにこだわる必要はなく、親は子どもに「どうやってそこまで考えたの？あなたの思考チェーンはどんなものだった？」と尋ねるべきだ。次に、結果だけでなく過程を見ること。結果だけで子どもを評価すると、子どもの能力は画一化してしまう。中核的な思考能力は自分で鍛える必要がある。第三に、国語、数学、英語の三科目は欠かせない。彼は自分の国語と数学がクラスで中の下程度で、そのせいでAIに要件を明確に説明できないことがあると率直に認めている。数学は論理的推論力を鍛え、国語は表現力を鍛え、英語は——中核的な文献や最先端のAI技術の多くが英語であるため——英語力がなければ一歩も進めない。

講演の最後に、彼は会場の全員に一つの問いを投げかけた。「もしAIが10秒で答えを教えてくれるとして、あなたは10分かけて自分で考える気がありますか？もしあるなら、あなたにはAIを乗りこなし、使いこなす素地がある。もしないなら、あなたはAIを使えるだけの普通の人かもしれない」。彼は強調した。「AI時代において、結果は最も安価なものだ。本当に意味があるのは、あなたの思考の過程である」。この思考過程への珍重は、彼が幼い頃から受けてきた情報学の訓練と切り離せない——張新鋼先生の「考え方を最初から話してみなさい」という指導法は、本質的に、思考過程への感受性とコントロール力を培うものだったのだ。

## 結び

姜睦然の物語は、AI時代における技術の民主化の一つのサンプルだ。小学5年生でC++に触れ、中学2年生でフルスタック開発者となり、彼が独力で構築した12のオープンソースプロジェクトは、ブラウザからRaspberry Pi、AIエージェントから数値制御ハードウェアまで、広大なスペクトルをカバーしている。これらのプロジェクトに共通する特徴は、ローカルファースト、プライバシーファースト、安定性ファースト、オープンソースでの共有——技術選択において、年齢を超えたエンジニアリングの判断力が表れている。

教育の面では、彼が提唱する「AIで足場を組むが、思考は外部委託しない」という理念が、AI時代における判断力、質問力、創造力、行動力の中核的地位を強調している。彼の実践経験が示すように、AIは学習のアクセラレーターにはなれるが、思考の過程を代替してはならない。

将来を見据えると、姜睦然が直面する課題は、技術への感度を保ちながら専門領域をどう深めるか、オープンソースの理念を堅持しながら持続可能な協働モデルをどう模索するか、影響力を広げながら学びの初心をどう保つか、である。だが未来がどうなろうと、彼はすでに行動で一点を証明した。AI時代において、「大人になるまで待たなくていい。ものづくりは今始められる」。個人サイトに記したあの言葉の通り——「好奇心を保ち、作り続けよう。技術の波の中に、あなたと私の足跡を残せますように」。
