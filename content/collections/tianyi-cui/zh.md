更为深远的影响来自于他在竞赛训练过程中编写的技术教程。在那个年代,中文互联网上的算法学习资源相对稀缺,系统性的动态规划教材尤其缺乏。崔添翼编写的《背包问题九讲》填补了这一空白。这份教程最初发布于 2007 年下半年,当时他仍是一名学生,使用 Emacs Muse 编写;2011 年,他用 LaTeX 重新制作了 2.0 版本。《背包问题九讲》系统性地拆解了动态规划中的背包问题家族,从基础的 01 背包、完全背包、多重背包,到更复杂的分组背包、二维背包、多维多选择背包等变体,涵盖了状态定义、转移方程、优化技巧和边界条件等核心知识点。这份教程不仅在浙江大学内部广泛流传,更通过 GitHub 和各类博客平台传播到全国乃至全球的算法竞赛社区,成为无数竞赛选手和算法爱好者的入门必读材料。

## Jane Street 九年:量化交易世界的工程淬炼

2013 年本科毕业后,崔添翼做出了一个在当时看来颇为不同寻常的职业选择:他接受了 Jane Street Capital 香港分部的 offer,担任助理量化研究员(Assistant Quantitative Researcher),年薪超过百万人民币。Jane Street 是全球最神秘也最具影响力的量化交易公司之一,以大量使用 OCaml 函数式编程语言构建交易系统而闻名业界。与传统科技公司的软件开发岗位不同,Jane Street 的量化研究员需要同时具备深厚的数学功底、算法设计能力和工程实现技能,直接参与交易系统的架构设计、策略开发和风险管控。崔添翼在 Jane Street 工作了九年,先后在香港和纽约办公室任职,负责股票与固定收益领域的软件开发及研究工作。

这段长达九年的量化交易职业生涯对崔添翼的技术视野产生了深远影响。在 Jane Street,他接触到了真实的交易系统、风控系统、回测系统、交易管道和异常处理机制。量化交易系统对延迟、稳定性和正确性的要求远超普通互联网应用:一笔交易的延迟必须以微秒计算,系统的任何故障都可能导致数百万美元的直接损失,而策略代码中的微小错误可能在极端市场条件下被放大为灾难性后果。这种高压环境下的工程实践培养了崔添翼对系统可靠性、风险控制和异常处理的极度敏感。他深入理解了"生产环境"的真正含义——代码不仅要正确运行,还要在不可预见的边缘情况下优雅降级;系统不仅要高性能,还要具备完善的监控、报警和回滚机制。

尤为重要的是,Jane Street 的技术文化强调"正确的抽象"和"可组合性"。公司大量使用 OCaml 这一强类型函数式编程语言,鼓励工程师构建高度模块化、可测试和可重用的代码组件。这种工程哲学与后来 DeepSeek Harness 的"一切皆插件"架构设计有着内在的契合性。崔添翼在 Jane Street 的经历让他深刻理解到:复杂的系统不是通过堆砌功能实现的,而是通过设计良好的接口和抽象层,让简单的组件能够组合产生复杂的行为。据钛媒体报道,崔添翼在量化交易领域的经验被认为对 AI Agent 的落地具有直接价值,因为他"熟悉量化交易的执行系统、风控系统,其经验可迁移到 AI Agent 的落地中,知道如何构建稳定的执行系统、设置风控规则,避免 Agent 出现失控风险"。

## DeepSeek Harness 的诞生:从模型到智能体的战略转身

崔添翼加入 DeepSeek 的时机,正值中国 AI 产业竞争焦点的重大转变。2026 年初,DeepSeek 已经在基础大模型领域建立了全球声誉,其 V3 和 V4 系列模型在多项基准测试中达到或超越了国际顶尖水平。然而,模型能力的提升并不自动转化为用户价值——如何让大模型从"聊天机器人"进化为能够独立完成复杂任务的"智能体"(Agent),成为整个行业面临的共同挑战。DeepSeek 创始人梁文锋多次公开表示,下一代模型首先要能帮助 DeepSeek 自己开发更先进的模型,这意味着模型必须能够接入真实的软件开发环境,理解代码库结构,执行编译测试,并根据反馈迭代改进。

正是在这一背景下,DeepSeek 于 2026 年 5 月正式组建了 Harness 团队,方向为代码智能体产品,内部对标 Anthropic 旗下的 Claude Code。团队的核心使命可以用一个简单的公式概括:Model + Harness = Agent。在这个公式中,模型(Model)负责推理和决策,而 Harness 则负责将模型的决策转化为可执行的动作,并管理整个执行过程。具体而言,Harness 承担了模型之外的所有工作:上下文管理、工具调用、文件读写、终端执行、结果自修正、权限控制、失败回滚等。如果说模型是智能体的"大脑",那么 Harness 就是它的"手"和"脚",决定了模型的能力上限能在多大程度上被兑现。

崔添翼作为团队负责人的任命颇具深意。与多数 AI 公司选择产品经理或研究科学家领导 Agent 项目不同,DeepSeek 选择了一位拥有九年量化交易系统开发经验的工程师。这一选择反映了 DeepSeek 对 Harness 本质的深刻洞察:AI Agent 的底层逻辑与量化交易系统高度一致——两者都需要在复杂的动态环境中做出决策、执行动作、处理反馈,并在严格的约束条件下(时间、成本、风险)优化长期回报。量化交易中的"滑点"(slippage)概念——即理论策略收益与实际执行收益之间的差距——在 AI Agent 领域同样适用:一个强大的模型如果不能被可靠地接入工作流,其实际价值将大打折扣。崔添翼在 Jane Street 的经验正是关于如何最小化这种"执行滑点",构建稳定、可控、可观测的执行系统。

2026 年 8 月 13 日晚间,DeepSeek 正式发布并开源了 DeepSeek Harness(简称 DSH)开发者预览版 v0.1。项目采用 MIT 许可证,代码以 TypeScript 编写,基于 Cordis 元框架构建。发布当天,崔添翼以个人账号 tianyi 在 X 平台(原 Twitter)上宣布:"DeepSeek Harness was just released with MIT license. The current 0.1.0 version is a developer preview, and may still have many rough edges. Feedback is welcome!"这一发布在开发者社区引发了强烈反响。截至 2026 年 8 月,GitHub 仓库 deepseek-ai/deepseek-harness 已获得 17.6 万颗星标和 1.91 万次复刻,成为当时 GitHub 上增长最快的开源项目之一。Hacker News 上的相关讨论获得了 740 分和 310 条评论,显示出全球开发者对这一项目的浓厚兴趣。

## 技术架构解析:"一切皆插件"的设计理念

DeepSeek Harness 的技术架构可以用其核心口号概括:Everything is a Plugin(一切皆插件)。这一设计理念并非简单的营销话术,而是贯穿于整个系统的架构决策。Harness 基于 Cordis 元框架构建,Cordis 是一个专门管理插件的框架,其核心职责是处理插件的加载、卸载和依赖关系管理,而所有具体的业务能力——包括模型适配、工具注册、会话存储、Agent 循环、UI 渲染等——都以插件形式存在。这种设计的优雅之处在于,它实现了高度的可组合性和可替换性:开发者可以通过修改配置文件,在不触碰 Harness 核心代码的情况下,替换模型后端、添加自定义工具、改变会话存储策略,甚至重写 Agent 的决策循环。

Cordis 框架的核心概念包括 Service、Context、Event 和 Effect。每个插件向共享的 Context 贡献服务(Service),这些服务可以被其他插件依赖和调用;插件之间通过类型化的事件(Event)进行通信;而插件注册的所有副作用(Effect)——包括文件系统操作、网络请求、定时器等——都被 Cordis 追踪和管理,当插件被卸载时,这些副作用会被自动撤销。这种"可逆副作用"机制对于 AI Agent 系统尤为重要,因为它允许系统在执行过程中动态调整能力组合,而不用担心资源泄漏或状态不一致。例如,当用户切换到一个需要不同工具集的项目时,Harness 可以卸载当前项目的插件、加载新项目的插件,而无需重启整个系统。

DeepSeek Harness 提供了四种预设的 Agent 运行模式,以适配不同的使用场景。标准模式(Standard)提供完整的编码 Agent 能力,包括文件编辑、Shell 命令、文件与网页搜索、技能(Skill)、规划(Plan)、目标(Goal)、子 Agent 和工作流等功能,适合在可丢弃的工作空间中进行探索性开发。代码模式(Code Mode,又称 PTC 模式)包含标准模式的全部能力,但工具通过代码模式 SDK 暴露,允许模型在单个 TypeScript 程序中组合多步骤操作,而非多次独立的工具调用,这种模式更适合需要精确控制执行流程的场景。极简模式(Minimal)是一个精简的双工具代理,仅包含持久化的 Bash 和字符串替换编辑器,DeepSeek 曾使用该模式进行官方模型基准测试,也可作为评估模型能力的干净环境。创造者模式(Creator)专为构建自定义 Agent 预设设计,包含标准模式的所有能力,额外支持运行时检查、内存中插件测试和预设创作指导,适合 Harness 插件开发者使用。

Harness 的另一大设计亮点是可追踪的运行日志(Session Log)。所有模型的交互内容——包括系统提示、推理过程、工具调用及其结果、子 Agent 调度、上下文压缩和权限变化——都被记录在追加式的会话日志中。这些日志构成单一事件流,支持对任意运行会话进行恢复、分叉、搜索和重播。这一设计对于调试 Agent 的异常行为至关重要:当 Agent 在某个任务上失败时,开发者可以精确重现模型当时看到的所有上下文,分析问题根源,而无需猜测或手动复现。从企业级应用的角度,这种可观测性也是安全审计和合规要求的基础。

在模型支持方面,DeepSeek Harness 并不局限于 DeepSeek 自家的模型。通过可配置的模型适配器,Harness 可以连接 Claude、GPT、Gemini 等第三方模型,甚至是本地部署的开源模型。这种开放性是 Harness 与 Claude Code、Codex 等封闭产品的关键区别。然而,不同模型的工具调用格式、图像支持、上下文窗口等特性存在差异,因此模型适配器需要针对每个模型进行精细调优,不能简单互换。截至 2026 年 8 月,Harness 的模型适配器仍在快速发展中,社区已经贡献了针对多种主流模型的适配插件。

## 社区生态:开源的力量与创新的涌现

DeepSeek Harness 的开源策略采用了最宽松的 MIT 许可证,允许任何人使用、修改并基于代码开发商业产品,与 React、Node.js 等基础工具采用相同许可协议。这一决策大大降低了开发者的准入门槛,也为 Harness 的快速传播奠定了基础。项目发布仅数天,GitHub 上带有 dsh-plugin 标签的公开仓库就超过 700 个,形成了一个活跃的开源生态。

社区开发的插件涵盖了从实用工具到个性化娱乐的广泛领域。在实用工具方面,dsh-agent-teams 插件允许在 Harness 中拉起多 Agent 团队,拆分任务、设置依赖并支持实时查看成员状态;DSH Better Sidebar 将文件管理、代码编辑、终端、Git 面板等功能整合进侧边栏,减少窗口切换;dsh-at-file 添加了类似 Codex 的 @file 能力,可在输入框中搜索并引用工作区文件内容;dsh-memory-evolve 为 Harness 增加跨会话长期记忆功能,可记录项目约定、架构决策等信息并支持归档。这些插件展示了社区对 Harness 架构的理解和扩展能力。

更具创意的是个性化和娱乐类插件。dsh-TUI 为 Harness 添加了 Claude Code 风格的全屏终端界面,包含实时工作状态、思考流展开等功能;dsh-web-ui 则增加了任务看板、Git 图谱、二次元电子宠物、皮肤中心等内容,风格类似千禧年贴吧与 QQ 空间;dsh-ads 为 Web UI 添加了 2005 年风格的中文互联网广告元素;dsh-minigames 内置了包括俄罗斯方块、坦克大战、贪吃蛇在内的 18 款小游戏,供用户在等待模型回复时游玩。这些看似"不务正业"的插件实际上展示了 Harness 插件系统的灵活性——既然"一切皆插件",那么用户体验的每一个细节都可以被社区重新定义。

DeepSeek Harness 的生态建设也吸引了企业级参与。腾讯 QQ 于 2026 年 8 月 15 日宣布,QQBot 现已支持接入 DeepSeek Harness 官方插件,普通用户和开发者可以快速给 QQ 机器人装上完整 AI 能力,私聊、群聊都能稳定运行。这一合作表明 Harness 的插件化架构不仅适用于个人开发者,也能够支撑大规模商业应用的集成需求。

然而,开源生态的繁荣也带来了挑战。Wavect 的企业级评测报告指出,目前 Harness 的插件质量和安全性参差不齐,企业在采用时需要完成额外的架构与威胁审查。文件系统沙箱仅管理文件系统层面的副作用,网络访问和进程可见性不在其控制范围内,且旧版 Landlock 环境与 Windows ACL 边界可能只提供部分强制执行。因此,尽管 Harness 的架构设计具有高度可扩展性,但在生产环境中的稳定运行仍需要团队投入大量工程努力进行配置、测试和监控。

## 竞争格局:AI Coding 赛道的全球博弈

DeepSeek Harness 的发布标志着 DeepSeek 正式进入 AI Coding 这一高度竞争的赛道。在这个领域,Anthropic 的 Claude Code 和 OpenAI 的 Codex 已经建立了显著的先发优势。Claude Code 凭借扎实的 Harness 设计成为开发者使用率最高的 AI 编程工具,而 Codex 则依托 OpenAI 的模型能力和广泛的生态系统获得了大量用户。DeepSeek Harness 的差异化竞争策略体现在三个维度:开放性、可组合性和成本效率。

首先,Harness 的完全开源和 MIT 许可协议与竞争对手的封闭或部分开放策略形成鲜明对比。Claude Code 是一个封闭的商业产品,虽然功能强大,但用户无法自定义其核心行为或审查其内部机制。Codex 虽然提供了 API 和一定程度的定制能力,但其核心架构仍由 OpenAI 控制。Harness 的"一切皆插件"架构赋予用户前所未有的控制权:模型、工具、循环、存储、策略,每一层都可以被替换或扩展。这种开放性对于需要满足特定合规要求或需要在私有环境中部署的企业客户尤为重要。

其次,Harness 基于 Cordis 的可组合架构为开发者提供了比竞争对手更高的灵活性。在 Claude Code 或 Codex 中,用户通常只能在预设的功能集内选择;而在 Harness 中,开发者可以精确地组合所需的能力组件,剔除不必要的功能,甚至重写核心逻辑。这种粒度化的控制能力使得 Harness 能够适应从个人 side project 到大型企业级应用的广泛场景。例如,一个只需要代码补全和简单重构功能的团队可以构建一个极简的 Harness 配置,而需要复杂多 Agent 协作的企业则可以启用完整的工具集和编排能力。

第三,DeepSeek 在模型成本方面的优势为 Harness 提供了潜在的竞争力。DeepSeek 的 API 定价一直显著低于 OpenAI 和 Anthropic 的同类模型,而 Harness 的设计理念正是"让便宜 token 变得有用"。通过优化上下文管理、工具调用策略和错误恢复机制,Harness 可以将低成本的模型包装进高价值的应用场景,从而进一步降低 AI Coding 的总体拥有成本。这对于价格敏感的个人开发者和中小企业具有重要吸引力。

然而,DeepSeek Harness 也面临着明显的挑战。Wavect 的评测报告指出,Harness 目前仍处于开发者预览阶段,迭代速度快,存在兼容性破坏性变更的可能,不建议直接用于生产环境。与 Claude Code 和 Codex 相比,Harness 的工具生态和稳定性仍有较大差距。此外,DeepSeek 在海外市场的影响力相对有限,Harness 的国际化推广面临品牌认知度和渠道资源的制约。

从更宏观的行业视角看,DeepSeek Harness 的发布反映了中国 AI 产业竞争焦点的转变。过去两年,中国 AI 公司的竞争主要集中在模型基准测试分数上,各家争相发布在各类榜单上的排名。而 Harness 的出现表明,DeepSeek 已经意识到基础模型能力趋同的趋势,竞争的下半场将转向"谁离用户的工作流更近"。Harness 作为模型与真实计算环境之间的"中间层",其重要性将随着模型能力的提升而愈发凸显。控制 Harness 意味着控制 AI Agent 的"执行-反馈-修改"闭环,这一闭环不仅是产品体验的保障,也是模型训练数据的重要来源。

## 项目里程碑与未来发展路径

自 2026 年 3 月崔添翼加入以来,DeepSeek Harness 项目经历了快速而密集的发展阶段。根据公开信息梳理,项目的关键里程碑包括:2026 年 5 月中下旬,DeepSeek 内部正式组建 Harness 团队,方向为代码智能体产品;2026 年 6 月 21 日,崔添翼在社交媒体上发起线上直招活动,招聘多个 Harness 相关岗位;2026 年 7 月 31 日,DeepSeek 发布 V4 Flash 正式版,其基准测试已使用"即将发布"的 DeepSeek Harness 极简模式作为测试框架;2026 年 8 月 2 日,崔添翼面向全球开发者启动内测招募,优先招募有 Agent 开发经验的开发者;2026 年 8 月 11 日,"DeepSeek Harness 团队"微信公众号完成注册,认证主体为北京深度求索人工智能基础技术研究有限公司;2026 年 8 月 13 日,DeepSeek-V4-Pro 正式版上线,同时 DeepSeek Harness v0.1 开发者预览版正式发布并开源。

展望未来,DeepSeek Harness 的发展将面临几个关键挑战和机遇。首先是产品化与工程化的平衡。目前 Harness 的定位更偏向于"平台"而非"产品"——它提供了强大的可扩展能力,但开箱即用的体验与 Claude Code 仍有差距。如何在保持开放性的同时,提供足够 polished 的默认配置和用户体验,是团队需要解决的核心问题。Wavect 的评测报告指出,对于"只需要一个 workflow 的产品团队",Harness 可能过于复杂,而更小的专用服务可能拥有更少的运维面。

其次是生态系统建设。虽然 Harness 的插件生态在发布初期就展现出活跃态势,但插件的质量、安全性和长期维护仍然是不确定性因素。DeepSeek 需要建立完善的插件审核机制、开发者认证体系和最佳实践指南,才能将社区的热情转化为可持续的生态繁荣。参考 VS Code 的插件市场或 npm 的生态演进历程,这一过程可能需要数年时间。

第三是商业化路径。目前 Harness 采用完全开源的 MIT 许可证,尚未显示直接的商业化计划。然而,参考 MongoDB、Elastic 等开源软件公司的经验,Harness 未来可能会通过提供托管服务、企业支持、高级功能或云服务来实现商业变现。DeepSeek 创始人梁文锋对融资和商业化一直保持谨慎态度,但 Harness 作为基础设施层产品,其商业模式的设计将直接影响 DeepSeek 的长期竞争力。

最后是全球化竞争。AI Coding 是一个全球性赛道,Claude Code 和 Codex 已经在美国和欧洲市场建立了强大的品牌认知。DeepSeek Harness 虽然技术上具有竞争力,但在国际市场推广、开发者关系建设和品牌影响力方面仍有显著差距。Harness 的国际化成功不仅取决于技术本身,还取决于 DeepSeek 能否建立起与全球开发者社区的有效沟通渠道。

崔添翼的职业生涯轨迹——从浙江大学算法竞赛选手,到 Jane Street 量化工程师,再到 DeepSeek Harness 团队负责人——勾勒出一条独特而连贯的技术发展路径。这条路径的每一个阶段都为他积累了特定的能力和视野:算法竞赛培养了他在极端约束下设计高效算法的能力和对问题本质的敏锐洞察;Jane Street 的九年经历让他深刻理解生产级系统的可靠性要求和量化交易的工程哲学;而量化创业的经历则锻炼了他的技术领导力和产品化思维。这些看似分散的经历,在 DeepSeek Harness 这一项目中实现了有机融合。

DeepSeek Harness 本身也代表着中国 AI 产业发展阶段的重要转变。过去两年,中国 AI 公司的竞争主要集中在基础模型能力的追赶和超越上,各家公司在各类基准测试榜单上争夺排名。而 Harness 的出现标志着竞争焦点的转移:从"谁的模型更聪明"转向"谁能让模型真正落地工作"。这种转变与全球 AI 产业的发展趋势高度同步——OpenAI 推出 Codex、Anthropic 推出 Claude Code、Google 推出 Jules,都表明行业领先者已经将战略重心从模型训练转向模型应用基础设施的建设。
