站长推荐的前两期写的都是人：智谱的[张昱轩](/collections/yuxuan-zhang)代表代码那一半，LobeHub 的[刘德泽](/collections/max-liu)代表增长那一半。从这一期开始，我们把项目也纳进来，方法不变——不看 star 榜，先把仓库的贡献者名单拉出来挨个过一遍评分引擎，再决定值不值得推荐。

第一个项目是 LobeHub（`lobehub/lobehub`）：8.1 万 star、1.58 万 fork、2023 年 5 月建仓、TypeScript。它现在的自我介绍是"你的首席 Agent 运营官"，但大多数人认识它的时候，它还叫 LobeChat——那个能一键部署到 Vercel 的开源 ChatGPT 客户端。

## 先看人：8.1 万 star 背后是谁在写

2026 年 8 月 4 日，我们抓了这个仓库 commit 数排名前 100 的贡献者。GitHub 明确标记的 3 个 bot（renovate、dependabot、gru-agent）之外，还藏着 3 个机器账号：semantic-release-bot、lobehubbot、actions-user。这三个账号合计提交了 4,220 次，比仓库里任何一位真人都多——一个高度自动化的发版流水线，这本身就是工程成熟度的一个侧写。去掉这 6 个，名单上剩 94 个真人。

其中 28 人已经在 ghfind 的库里有分数：

| 指标 | LobeHub 前 100 贡献者 | 全站基线（18,947 个账号） |
| --- | --- | --- |
| 评分中位数 | **85.3** | 42.5 |
| 顶级及以上占比 | **61%**（17/28） | 11.3% |
| 粉丝中位数 | 631 | 27 |
| 已合并 PR 中位数 | 245 | 20 |
| 账号年龄中位数 | 8.4 年 | 7.4 年 |

段位分布是夯 7、顶级 10、人上人 3、NPC 6、拉完了 2。在有完整画像数据的 13 个人里，没有一个账号注册不满两年，机器人嫌疑分 ≥3 的一个都没有（全站这个比例是 0.58%），触发红旗的只有 2 人，两人都命中"无原创作品"——也就是只给别人写代码、自己不开项目的那类人，在这里不算问题（其中一人还命中"仓库多为 fork"和"社交型休眠账号"）。全站的红旗命中率是 17%。

这份名单没有注水。对一个 8 万 star 量级的 AI 项目来说，这句话不是废话：我们扫过的[爆红 AI 仓库](/blog/who-builds-openclaw)里，贡献者名单挂着一堆新注册小号的情况并不少见。

（口径说明：以上只统计 commit 数前 100 的贡献者，只提过 PR、没进前 100 的人不在样本里。仓库的[站内档案页](/developers/repo/lobehub/lobehub)展示的是已进入榜单的那部分贡献者，样本更窄，数字会和这里不同。）

## 再看项目：三年，三次转身

LobeHub 值得推荐的另一半理由，在于它是少见的、公开记录了自己每一次架构反悔的项目。

**0.x（2023）：Local First。** 所有数据存在浏览器里，不要服务端数据库，一键部署，填个 API Key 就能用。代价是跨设备同步、知识库、定时任务全都做不了。

**1.0（2024 年 6 月）：加服务端。** 团队在 2024 年 3 月发文《迈向 LobeChat 1.0》说明了取舍，三个月后落地服务端数据库与鉴权。同一时间开源协议从 MIT 改成了自定义的 LobeHub Community License。

**2.0（2025 年 11 月宣布）：改名，回到 Server 为核心。** 创始人在 GitHub Discussion #10007 里做了一次相当坦率的复盘：1.x 的浏览器 / 服务端 / 桌面端三套并存造成了体验割裂，而早期引入的 RSC 在高频交互场景下"轻量操作也要走一趟服务器"，于是 2.0 全面回退到 SPA。Agent 的状态、记忆、知识库和任务执行统一收到服务端，产品也从 LobeChat 更名为 LobeHub。

**CAO（2026 年 5 月）：首席 Agent 运营官。** 一句话描述需求，它自己拆任务、组建子 Agent 小队、分派工作，只在需要拍板时停下来问你。

三次转身其实是同一条线：从"我操作 AI"，到"我和一队 AI 协作"，再到"我管理一队 AI"。用户的角色一路往上走，产品的重心就一路从客户端往服务端搬。

## 推荐它的三个理由

**一、模型中立 + 能自托管。** 它对接 OpenAI、Anthropic、Google、DeepSeek、GLM 等一长串供应商，自己带 key 的情况下没有中间抽成；官方云是可选项不是前提。对于"想要一个多模型工作台但不想把对话记录交给第三方"的团队，这条路目前没多少替代品。

**二、迭代速度是实打实的。** 过去 30 天有 **790 个 PR 被合并**（历史累计 7,498 个）；7 月 11 日至今发了 100 个版本，最近 7 天 38 个。这不是一个靠 star 数吃老本的仓库。

**三、设计工程的血统。** 创始人 arvinxx 出自 Ant Design 核心团队，另一位核心贡献者 canisminor1990（90.1 分）的简介里同时挂着 @lobehub 和 @ant-design。这个背景解释了为什么它在一堆功能相近的开源 AI 客户端里，UI 观感始终是最好的那一档——而在开源 AI 应用这个赛道，"好看且顺手"本身就是护城河。

## 也必须说清楚的四件事

**一、巴士系数很低。** 在 commit 前 100 的样本里，arvinxx 一个人写了 **43.1%** 的人类提交，前 3 名合计 62.6%，前 10 名 88.2%。再看最近 30 天：我们抽样了 400 个已合并 PR，作者只有 21 个人，前 5 名占 83.8%。翻译过来就是——这是一个公司团队仓库，不是分布式社区仓库。它跑得快，但快在几个人手上。（作为对比，同为 AI 明星项目的 [Dify](/blog/who-builds-dify)，commit 第一名只占 8.4%。）

**二、协议不是 MIT。** 从 1.0 起用的是 LobeHub Community License，基于 Apache 2.0 加两条补充条款，原文写得很清楚：不改源码、直接把它当前后端服务商用是允许的；但"如果你要基于它开发并分发衍生作品，必须获得商业授权"。同时贡献者需要同意"你贡献的代码可被用于商业用途，包括其云版本"。自用、内部部署、原样商用都没问题，改一改换个 logo 拿去卖不行。这不是坏事，但选型前必须知道。

**三、PR 队列比 issue 队列长得多。** 目前 245 个 issue 开着，其中只有 5 个超过 3 个月——分诊做得相当好。但 PR 有 428 个开着，其中 124 个超过 3 个月（renovate 只贡献了 31 个）。想给它提 PR 的人要有心理准备：核心团队在高速合并自己的分支，外部 PR 的等待时间是另一回事。

**四、CAO 还很年轻。** 36氪在 2026 年 5 月的实测标题是《组队 4 分钟，翻车一整天》——组建 Agent 团队这一步确实惊艳，长任务的实际执行稳定性还没到可以托付的程度。把它当成一个正在成型的方向去用，别当成已经交付的能力。

## 谁适合上手

**适合：** 想自托管一套多模型 AI 工作台的小团队；想找一个成熟的 Agent 平台底座做内部工具的（注意授权边界）；想在 Agent / MCP 生态里做插件、需要一个有真实用户量的宿主的开发者。

**先别急：** 需要的是稳定 API 而不是产品的；对协议有严格宽松性要求的；期待完全社区治理、希望自己的 PR 能快速进主干的。

## 我们会盯着的三个数字

推荐不是结论，是一个可以被后续数据推翻的判断。这个仓库我们会持续追踪三件事：arvinxx 的提交占比会不会随团队扩张下降；28 位已评分贡献者的中位数会不会随社区扩大而稀释；超过 3 个月的陈旧 PR 会不会继续堆积。三个数字都在往好的方向走，这个推荐才算站得住。
