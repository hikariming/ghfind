今回のおすすめは、2026年8月のAIオープンソース分野で最も注目すべき2つの Agent Harness プロジェクトに焦点を当てます。DeepSeek AI が公式にオープンソース化した DeepSeek Harness(略称 dsh)と、Apache ソフトウェア財団のインキュベーターに新たに受け入れられた Apache Maka(Incubating)です。両者は互いの複製ではなく、まったく異なるエンジニアリング哲学をもって同じ時代の問い——大規模モデルの能力が均質化する中で、エージェント(Agent)が真に「仕事をする」方法を誰が定義するのか——に答えています。DeepSeek Harness は「一切皆插件」(Everything is a Plugin)を旗印に、モデル、ツール、セッション、サンドボックス、さらには Agent ループそのものまで、すべてをプラグイン可能なコンポーネントに仕立て、オープンソース化から1か月足らずで GitHub 上に21万以上のスターを集め、史上最も急速に成長したリポジトリの一つとなりました。一方の Apache Maka は「ローカルファースト」と「The Log is the Runtime」(ログこそランタイム)という二つの旗を掲げ、Agent のモデルメッセージ、ツール呼び出し、権限決定、終了イベントのすべてを追記専用の RuntimeEvent ログとして記録し、同一モデル・同一公式検証器のもとで9つの Harness の横断スコアを公開、77.5% の通過率で DeepSeek Harness の 73.0% を抑えて2位につけました。この2つのプロジェクトは、まさに極めて緊張感のある組み合わせを構成しています。一方はベンダー主導・コミュニティ爆発のオープンエコシステム路線を、もう一方は財団ガバナンス・データ駆動の中立路線を代表しており、両者の同時対比そのものが、Agent インフラストラクチャ競争を理解する最良のサンプルです。

## 一、選定背景:なぜ「Harness」が2026年のキーワードになったのか

### 1.1 「モデル競争」から「フレームワーク競争」へのパラダイムシフト

2026年のAI技術ナラティブにおいて、明確なパラダイムシフトがすでに起こっています。業界の議論の重心は「どのモデルがより強いか」から「モデルがどのような Harness の中で動かされるか」へと移りつつあります。Agent Harness とは、業界で通用する定義によれば、モデルの外側にあるすべてのコード、設定、実行ロジックを指し、モデルを継続的に呼び出すループ、ツールリスト、サンドボックス環境、メモリ機構、そしてどの内容がコンテキストウィンドウに入るかを決めるルールを含みます。Winder.AI チームが2026年8月に発表した横断比較総説では、AI技術スタックをモデル、Harness、フレームワーク、プラットフォームの4層に分解し、Harness は「単一のエージェントを実行する」中間層として、その適合する技術スタックの層が機能リストよりも重要であると明確に指摘しています。この判断の背後には確かな実証的裏付けがあります。Vercel はエージェントのツールの80%を削除することで、同一モデルの成功率を80%から100%に引き上げました。LangChain は Harness を交換しただけで、コーディングエージェントの Terminal Bench でのスコアを52.8%から66.5%に向上させました。プリンストン大学の CORE-Bench テストでは、同一モデルが異なるスキャフォールド下で42%から78%までのスコアを示しました。モデルの基礎能力が収斂しつつある現在、Harness は「ラッパー」からエージェントの成否を決定づける重要なインフラストラクチャへと昇格したと言えます。

### 1.2 2つのプロジェクトの「同日の縁」と歴史的位置づけ

今回おすすめする2つのプロジェクトの間には、極めてニュース価値の高い偶然があります。2026年8月13日、DeepSeek AI は自社の Harness をオープンソース化すると同時に V4 Pro モデルの API 値上げ案を発表し、Apache ソフトウェア財団はちょうど同じ日に Maka をインキュベーターへ正式に受け入れました。この日付の節目は AI オープンソース史上において象徴的な意味を持ちます——ベンダー主導のオープンソースと財団ガバナンスのオープンソースが、同じ日にそれぞれ重要な一手を打ったのです。製品形態から見ると、DeepSeek Harness は純粋なランタイムフレームワークであり、公式には「Agent = モデル + Harness」という公式における後者として位置づけられ、DeepSeek V4 シリーズモデルと深く結びつき、複数のメディアによって Anthropic Claude Code に対抗するオープンソースで構築可能な代替案として解釈されています。一方の Apache Maka は完全なデスクトップワークベンチ製品であり、英語での位置づけは「high-performance agent workspace that keeps a complete record of everything it did」(高性能な Agent ワークベンチで、行ったことすべてを完全に記録する)です。リポジトリは2026年5月27日に作成され、インキュベーション時点ですでに約10週間の集中的な開発履歴がありました。一方は「フレームワーク」寄り、もう一方は「製品」寄り、一方は交換可能性を、もう一方は記録可能性を強調し、ちょうど Agent Harness スペクトルの両端をカバーしています。これこそが両者を同じ号のおすすめに並べる核心的な理由です。

## 二、DeepSeek Harness:一切皆插件のオープンソース Agent ランタイム

### 2.1 プロジェクト概要と爆発的な熱狂

DeepSeek Harness は DeepSeek AI が公式に開発し、MIT ライセンスでオープンソース化されており、コマンドラインのエントリーポイントは dsh です。公式プロジェクトページはその核心的な主張を一文に集約しています——一切皆插件。モデル、ツール、スキル、セッション、サンドボックス、ストレージ、ループ、スケジューリング、そしてユーザーインターフェースまで、すべての機能が交換または再構成可能です。プロジェクトの公式ドキュメントによれば、DeepSeek のモデルベンチマークは Harness のミニマルモードをフレームワークとして使用しており、DeepSeek シリーズモデルの Code Agent テキストタスクテストはすべて max 設定と temperature=1.0 のパラメータ組み合わせを採用しています。このプロジェクトの熱狂の軌跡はオープンソース史上でも稀に見るものです。博客园の実測記事は、オープンソース化当夜12時間で5万スターに到達したこと、公開当日に dsh-plugin タグを付けたサードパーティ製プラグインリポジトリが288個も現れたことを記録しています。Medium プラットフォームの報道は4日間で141,000スター獲得と伝え、Winder.AI の総説は2日間で95,386スター獲得を記録しています。なお、異なるメディアが異なる時点でサンプリングした数字には大きな差があり、また Wavect は「GitHub 史上最速の成長」という説が GitHub 公式の認定を受けていないことを特に注意喚起しています。引用する際は公式リポジトリのリアルタイムデータを基準とし、サンプリング時刻を明記すべきです。

### 2.2 コアアーキテクチャ:Cordis カーネルとプラグイン化ランタイム

DeepSeek Harness を理解する鍵は、その底層にある Cordis メタフレームワークにあります。公式プレビューページは Cordis を、プラグインのマウント、アンマウント、依存関係の管理を担う「カーネル」と説明しています。エージェントのすべての能力はプラグインとして存在し、Cordis のサービスとイベント機構によってプラグイン同士が連携し、開発者は設定を通じて任意の能力を選択、交換、拡張でき、フレームワークのソースコードを変更する必要はありません。Eigent AI の中国語による解説は、プラグイン化の境界をさらに明確にしています。ツールやスキルだけでなく、モデルアダプターそのもの、セッションと実行状態、サンドボックス環境、ストレージの場所、ループとスケジューリングロジック、さらには UI インターフェースそのものまでがプラグインなのです。このアーキテクチャの直接的な帰結は「パッチを当てる必要のある特権カーネルは存在しない」ということです——公式ドキュメントは、dsh を拡張する方法はプラグインを他のプラグインの隣にマウントすることであり、閉じたコアの周囲で外縁的な拡張を行うのではないと明確に述べています。DataCamp の比較記事はエンジニアリングの視点からこの設計を裏付けています。Cordis はプラグインにサービスを発見させイベントを交換させ、依存関係の変更はプラグインのロードまたはアンロードを引き起こし、ホットリロードは期限切れのリスナーとバックグラウンドジョブをクリーンアップし、デフォルトの profile はループを設定として表示します。Claude Code との対比がその違いを最も際立たせます。後者は固定された組み込みループを中心に skills、hooks、MCP などの外縁的拡張機構を提供するのに対し、Harness のプラグインはランタイムそのものの構成要素を直接定義できます。つまり「DeepSeek Harness は Claude を載せられるが、Claude Code は DeepSeek を載せられない」のです。

### 2.3 4つの実行モードと Agent プリセット体系

DeepSeek Harness には公式に設計された4つの実行モードが組み込まれており、本質的には同じプラグインライブラリの異なる組み合わせプリセットです。標準モードは機能完全なコーディング Agent で、ファイル編集、Shell、ファイルとウェブ検索、スキル(Skills)、プランモード、目標追跡、サブエージェント、ワークフローなどの全能力を網羅しています。コードモード(PTC モード)は標準モードを基盤に Code Mode SDK を追加し、モデルが TypeScript プログラムを書いて複数ステップの操作を組み合わせることを可能にします。複数回の独立したツール呼び出しを行う代わりに、バッチ操作のシナリオに適しています。ミニマルモードは永続化 bash と str_replace_editor の2つのツールのみを保持し、公式がベンチマークと最小化再現に用いるクリーンな環境であり、公式ドキュメントは DeepSeek シリーズモデルの公開ベンチマークがすべてこのモードを使用していることを確認しています。クリエイターモードは「Agent で Agent を作る」高度なシナリオを対象とし、標準モードの全能力の上にランタイム検査、プラグイン実験、プリセット作成ガイダンスを加え、ユーザーは現在のランタイムを検査し、メモリ内で Cordis プラグインをテストし、それらを新しいモードに組み合わせることができます。4つのモードの段階的関係は明確です。標準モードは作業をこなし、コードモードはオーケストレーションを行い、ミニマルモードは評価を行い、クリエイターモードは進化させる——この体系化されたプリセット設計そのものが、展開に値する製品ハイライトです。

### 2.4 オブザーバビリティ設計:トラジェクトリビューと追記式セッションログ

DeepSeek Harness のオブザーバビリティへの投資は、「トレーサビリティ」への高い重視を示しています。公式プレビューページは「すべての実行が追跡可能」と明確に約束しています。モデルが受け取るすべての内容が追記専用のセッションログに記録され、システムプロンプト、推論過程、ツール呼び出しと結果、サブエージェントのスケジューリング、すべてのコンテキスト注入が含まれます。トラジェクトリビュー(Trajectory view)により、ユーザーはこれらの記録を発生元別に閲覧でき、復元、分岐、検索、リプレイの操作はすべて同じイベントストリームに基づいています。36Kr がライセンス転載した量子位の体験記事は、この機能の実際の価値を詳しく描写しています。Agent の実行が長くなるほど、ツールチェーンが複雑になるほど、チャット要約はますますブラックボックス化しますが、トラジェクトリ機能は Agent を随時監視できるリプレイウィンドウを提供し、生のイベントレベルの記録を直接見ることができ、モデルがどのステップでつまずいたか、各環節でいくら費やしたかを直感的に特定できます。DataCamp の評価は「モデルに見えるものは記録される」(Model-visible means logged)であり、UI に表示される実行パスの詳細は Claude Code の JSONL 記録よりも豊富だと指摘しています。注目すべきは、この「追記式ログ」設計が Apache Maka の RuntimeEvent ログと思想的に同じ先端方向に属していることです。aiguide.cc の比較記事は両者を「記録こそ真実」路線の代表として並べています——2つの製品は異なる出発点から出発し、最終的に「ログを唯一の事実源とする」という原則で同じ結論にたどり着いたのです。

### 2.5 プラグインエコシステムとコミュニティの組織化

DeepSeek Harness のエコシステム構築戦略は、鮮明な「OS化」の特徴を呈しています。量子位の体験記事はこれを「Agent 時代の Android」に喩えています。公式はすでに100以上のプラグインを内蔵しており、コミュニティは『マインクラフト』に MOD を入れるようにサードパーティ製プラグインをインストールでき、リポジトリのドキュメントにはゼロからプラグインを構築し公式 Harness に接続する完全なチュートリアルさえ含まれており、Cordis を魔改造する Skill も内蔵されています。公式プレビューページはコミュニティプラグインインデックスの入り口(GitHub の dsh-plugin トピックタグ)を提供し、Harness 開発者が DSH プラグインエコシステムに参加することを歓迎するとともに、GitHub Discussions と Discord を通じてコミュニティの協働を支えています。博客园の実測はさらに重要な能力を明らかにしています。Harness には Claude Code と Codex をサブ Agent として呼び出す Provider が内蔵されており、PATH 内の対応するバイナリを解析することで委譲実行を実現します。これは、ユーザーが Harness を上位のオーケストレーションとして使い、競合ツールを置き換えるのではなく自分のワークフローに組み込めることを意味します。Winder.AI の総説もこの点を確認し、Zed Agent、OpenHands、DeepSeek Harness がいずれも Agent Client Protocol をサポートし互いに駆動できると指摘しています——Harness 間の相互運用性が業界のトレンドになりつつあります。

### 2.6 導入方法と開発者体験

DeepSeek Harness の導入ハードルは「5分で起動、深く使うには学習が必要」と要約できます。公式が提供する最速の起動方法は、Node.js がインストールされた環境で `npx @deepseek-ai/dsh web` を実行することで、デフォルトで http://127.0.0.1:3080 に Web UI を起動しブラウザを自動的に開き、SSH 経由で起動した場合はローカル転送用にホストアドレスのみを出力します。ソースコードから実行する場合は、リポジトリをクローンした後に `pnpm install`、`pnpm run build`、`pnpm dsh web` を順に実行します。初回使用時にはユーザー自身でモデルの API Key を設定する必要があります——公式プレビューページと36Kr の体験記事のいずれも、Harness が共有モデルアカウントを内蔵していないことを確認しており、ユーザーは DeepSeek オープンプラットフォームや他のプロバイダーのモデルに接続できます。博客园の実測は、現在の対話インターフェースがウェブ版中心で、ターミナルに慣れた開発者には十分に友好的でないと指摘していますが、Headless モードと公式 Python SDK がプログラムによるバッチ実行をサポートし、ファイル単位またはモジュール単位で無人タスクを実行でき、この能力はバッチコード移行などのシナリオで対話型ツールを大きく上回ります。DataCamp の比較表は、その使用インターフェースとしてローカル Web UI、ヘッドレス CLI、Python SDK を記録しています。2つのレビューの CLI の状態に関する記述には時間軸の違いがあります(博客园の記事は2026年8月20日公開、DataCamp の記事は8月24日公開)。稳妥な表現は「初期バージョンは Web UI 中心で、イテレーションの中でヘッドレス CLI と Python SDK が徐々に追加された」であり、読者にはこの製品のイテレーション速度が極めて速く、機能マトリックスがいつでも変わり得ることを注意喚起すべきです。

## 三、Apache Maka:すべてを記録するローカルファースト Agent ワークベンチ

### 3.1 プロジェクト概要と Apache インキュベーションの道のり

Apache Maka は、Apache ソフトウェア財団のインキュベーターが受け入れた初の Agent Harness を中核的位置づけとするプロジェクトです。インキュベーターの公式ページはこれを「ローカルファーストの AI エージェントランタイム兼ワークスペースであり、モデルメッセージ、ツール呼び出し、ツール結果、権限決定、終了イベントを追記専用ログに記録する」と説明しています。プロジェクトは Apache Incubator PMC が主催し、Champion は tison(Zili Chen)、4名のメンター(Mentors)が配置され、コミッター名簿には Kun Li、Jie Wen、Yuhan Lei ら7名が含まれます。プロジェクトリポジトリは2026年5月27日に作成され、7月14日にプロジェクト側が v2ex コミュニティに共有投稿をした時点ではわずか666スター、70フォークでしたが、8月13日にインキュベーター入りした後、注目度は急速に上昇しました——aiguide.cc は8月24日前後に約2,381スターを、agentconn.com は8月26日に3.6千スターを記録し、本稿執筆時点(2026年9月9日)の公式リポジトリはすでに5.1千スター、476フォーク、4507回のコミットを示しています。この成長曲線は DeepSeek Harness の爆発的軌跡にははるかに及びませんが、2026年8月23日に GitHub Trending の首位に登り、8月24日に TypeScript カテゴリの当日リポジトリスターを獲得した実績と合わせれば、「Apache エコシステムで最も注目される新 AI プロジェクトの一つ」というおすすめの位置づけを十分に支えるものです。

### 3.2 核心理念:The Log is the Runtime(ログこそランタイム)

Maka の製品哲学は、公式サイトに繰り返し登場する一つの公式に凝縮されています。State(t) = Project(Log[0…t])。すなわち、システムの任意の時点における状態は、順序付きログを射影した結果です。公式 README はこれを「ログこそランタイム」という原則として具体化しています。すべてのモデルメッセージ、ツール呼び出し、権限決定、終了イベントは追記専用の RuntimeEvent であり、インターフェース、次のターンの prompt、クラッシュリカバリはすべてこのログの射影であり、唯一のコピーではありません。古いツール出力は次のターンの prompt から離れることはできても、ログから離れることはありません。CSDN の技術解説記事は、分散システムの視点からこの設計の思想的由来を説明しています。これは log-first 思想の Agent 領域への実装であり、まず順序付きで曖昧さのない変更の事実を保存し、次にコンシューマーが自身の状態を再構築することで、「あるイベント境界の前にモデルが何を見ていたか、どのツールを呼び出したか、どの権限が要求または決定されたか」という重要な問いに確実に答えられるようにするものです。この設計の実際の価値は、v2ex のプロジェクト側共有投稿でより素朴に表現されています。市場には AI Desktop がすでに多く存在し、Maka が解決しようとしているのは「チャットインターフェースが美しいかどうか」ではなく、「Agent の実行過程を第一級の市民として保存すべきかどうか」であり、プロジェクトのスローガンは「Maka preserves experience as evidence」(Maka は経験を証拠として保存する)です。「ログこそランタイム」は、技術的深さと説明のしやすさを兼ね備えたナラティブの支点です——「監査可能、復元可能、再現可能」という3つの抽象的なセールスポイントを、一つの可視化可能な原理のもとに統一しています。

### 3.3 統一 Runtime Host と3エントリーアーキテクチャ

Maka のアーキテクチャ設計におけるもう一つのおすすめに値するハイライトは、「単一ランタイムホスト」(One Runtime Host)原則です。公式 README は明確に述べています。Desktop、TUI と CLI、Eval はすべて薄いクライアントであり、実行はこの一つの Runtime Host のみが担い、Eval は実験とスコアだけを所有します。これは、デスクトップのグラフィカルインターフェース、ターミナルの TUI/CLI、評価フレームワークが完全に同一の実行パスを共有し、評価結果をシームレスに本番シナリオへ移行できることを意味します。この設計は「評価環境と本番環境の不一致」という古典的なエンジニアリングの罠を排除します。aiguide.cc のレビューはこれを革新点として挙げています。デスクトップ、CLI、Eval が一つのランタイムを共有し、評価結果は再現可能で、実験と本番が同一の実行パスです。エントリー層では、デスクトップは Electron と React で構築されたローカルアプリケーションで、ストリーミングセッション、ツールタイムライン、ブランチと復元などの機能を提供します。ターミナルエントリーは `npm run cli` で TUI を起動するか単発の Turn を実行できます。Eval エントリーは宣言的な多腕実験(task × repetition × subject)をサポートし、スコア、使用量、コスト、所要時間などの結果カーネルを出力します。さらに、Maka には Read、Write、Edit、Bash、Glob、Grep の6つの基本ツールが内蔵され、プロバイダー非依存の Model Context Protocol クライアント統合を提供し、MCP ツールは既存の権限制御、ランタイムイベントログ、テレメトリ能力を自動的に獲得します。この「ワークベンチ + 評価フレームワーク」の完全な製品形態により、Maka は「純粋なフレームワーク」と「純粋なチャットツール」の間に差別化された位置を見出しています。

### 3.4 データで語る:Terminal-Bench 2.1 の9 Harness 横断評価

Maka の最も鋭い素材は、公開された横断評価データです。プロジェクト公式サイトのトップページの核心的なキャッチコピーは「Measured, not claimed」(測定による、主張によらず)であり、2組のテスト結果を公開展示しています。第1組は、DeepSeek V4 Flash 上で Terminal-Bench 2.1 の全89タスクを実行し、公式検証器で統一採点した9つの Harness の対比です。Codex が82.0%の通過率で1位、Maka が77.5%で2位、Pi が74.2%、DeepSeek Harness(ミニマルモード)が73.0%、ZCode が70.8%、Reasonix が67.4%、OpenCode が65.2%、Kimi Code が59.6%、Claude Code が55.1%で最下位でした。第2組は Maka と OpenCode のペアリング単発実行の対比で、McNemar 検定により差が有意であることが確認され(p = 0.0118)、Maka は68.5%対55.1%で13.5ポイントリードし、通過タスクあたりのコストはほぼ同じでした。知乎の記事のこのデータに対する解釈は極めて拡散力があります。同じモデル、同じ reasoning max 設定で、1位と最下位の差は26.9ポイント、ちょうど24問分です。89問のうち9つの Harness すべてが通過したのは28問のみ、すべてが間違えたのは5問で、残りの56問(約63%)は異なる Harness で異なる結果が出ました。同記事はさらに、Harness がモデル能力の外で最も重要かつ最も見落とされがちなインフラストラクチャ層になりつつあると指摘し、Maka が Apache に入ったのはまさにこの層をオープンで中立かつ長期に存続するコミュニティガバナンスに委ねるためだとしています。正直に明記すべきなのは、この横断評価は Maka プロジェクト側が主導して実施したものであり、テストレポート、問題ごとの結果、実験の基準はすべて公開され再現 PR も添付されているものの、独立した第三者による全面再現はまだ行われていないため、引用時には「プロジェクト側公開データ」という属性を注記すべきだということです。

### 3.5 セキュリティ、権限、ローカルファーストのプライバシー設計

Maka の3つ目の核心的なセールスポイントは、ローカルデータ主権を軸に構築されたセキュリティ設計です。公式 README は「データはあなたのマシンに、モデルはあなたが接続」と約束しています。セッション、設定、実行記録はローカルマシンに保存され、ユーザーはモデルを持ち込みます——クラウド API、ローカルモデル、互換ゲートウェイのいずれも可能です。ワークスペースデータはデフォルトで Electron の userData ディレクトリに保存され、runtime.sqlite、接続ディレクトリ、認証情報ボールト、設定ファイルが含まれます。API キーなどの機密は、システムアカウントのみが読み取れるローカルファイル credential-vault.json に保存され、レンダラープロセス(インターフェースプロセス)は平文を取得できません。ツール実行層では、ファイル書き込みや Shell 実行を行うツールはまずサンドボックス境界を通過しなければならず、境界を越える操作は権限承認を要求し、実行は中止可能で、失敗は分類されます。CSDN のアーキテクチャ解説はより細粒度のセキュリティ措置を補足しています。stdio はデフォルトで実行に必要な環境変数のホワイトリストのみを継承し、すべての MCP ツールは mutation として扱われ明示的な認可が必要で、メインプロセスは IPC ペイロードにランタイム検証を行い、設定ファイルは 0600/0700 の厳格なファイル権限を採用し、モデルのテキスト、画像数、総サイズに対して集約境界チェックを行います。agentconn.com のレビューは特に、Maka の追記式ログがクラッシュリカバリと中断タスクの復旧をネイティブにサポートすることを指摘し、これは「エージェントセッションのクラッシュで作業を失ったことのある」ユーザーにとって極めて魅力的ですが、ローカルファーストのアーキテクチャは組み込みのデバイス間同期機能がないことも意味しています。この一連の特性により、Maka はプライバシーに敏感なシナリオ(企業内部の機密コードベース、コンプライアンス監査要件など)における推奨の第一候補となり、DeepSeek Harness のクラウドモデル路線と明確な利用シナリオの棲み分けを形成しています。

### 3.6 コミュニティ協働の密度と速度

DeepSeek Harness のコミュニティの強みが規模にあるとすれば、Maka のコミュニティの強みは密度にあります。知乎の記事が引用するプロジェクト側の統計によれば、5月27日のリポジトリ作成後の約10週間で、Maka は約71万行の TypeScript(うち約35万行はテスト)、949のテストファイル、2,439回のコミット、1,218のマージ済み PR、93.8%の PR マージ率を蓄積し、PR マージ時間の中央値は約33.5分、7月だけで943の PR をマージしました。v2ex の共有投稿は別の初期データを補足しています。9日間で300のコミット(111の fix、103の feat)、1日平均33コミット、コアコントリビューターは2〜3人です。特に注目に値するのはコミュニティの自己組織化能力です。リリース前の2日間にコミュニティユーザーが models.dev の全量 provider サポートへの整合というニーズを提起し引き受けを申し出たところ、2日以内にコミュニティから20以上の provider サポートが続々と提出され、Cloudflare Workers AI、Hugging Face、Vercel AI Gateway、Cohere、Mistral、xAI、Together AI、および火山方舟、テンセント、StepFun など国内外のサービスをカバーしました。この高頻度の協働と迅速な検証という builder コミュニティの気質は、Apache インキュベーターではかなり稀な「新種」です。もちろん、もう一方の側面も正直に示す必要があります。プロジェクト側は v2ex の投稿で「Runtime 設計の先進性が、製品の完成度と初心者の導入体験を上回ってしまっており、初めて触れる開発者が5分以内に起動を完了し、一回の Agent Run の完全な流れを明確に確認するのは難しい」と率直に認めており、これは今後の優先的な最適化の方向です。

## 四、横断比較:同一ベンチマークと同一座標系における2製品のパフォーマンス

### 4.1 位置づけと設計哲学の差異

2つの製品の最も本質的な差異は、「Harness とは何であるべきか」への回答にあります。DeepSeek Harness の哲学は「交換可能性優先」です。公式プレビューページは「一切皆插件」を設計理念の第1条に掲げ、開発者が設定を通じて任意の能力を選択、交換、拡張できることを強調しています。そのメタファーは OS やブロックの底板です——Eigent AI はこれを「言語モデルを包むランタイム層」と位置づけ、量子位は「Agent 時代の Android」と直接呼んでいます。Maka の哲学は「記録可能性優先」です。公式 README の4つの核心的な特徴はすべて測定と記録を軸に展開しています——測定による、主張によらず、ログこそランタイム、データはあなたのマシンに、一つの Runtime Host。そのメタファーは台帳やブラックボックスであり、Agent の一つひとつの「行為取引」を改ざん不可能な方法でディスクに書き込みます。aiguide.cc の比較表はこの分岐を一文で的確に要約しています。Maka は「ローカルファースト Agent ワークスペース(記録こそ真実)」、DeepSeek Harness は「一切皆插件 Agent 実行フレームワーク」です。この哲学的差異を理解すれば、2製品の他の次元におけるパフォーマンスの差異には統一的な説明枠組みが得られます。DSH は交換可能性のために安定性の約束を犠牲にし(開発者プレビュー、破壊的変更の警告)、Maka は記録可能性のためにエコシステムの規模を犠牲にしました(インキュベーション期間中、正式リリースなし)。

### 4.2 同一ベンチマークでの性能とコストの直接対決

2つの製品の同一ベンチマークでの直接比較データは、最も説得力のある素材です。Terminal-Bench 2.1 の9 Harness 横断評価において、Maka は77.5%の通過率で DeepSeek Harness(ミニマルモード)の73.0%を約4.5ポイントリードしました。コストの次元では両者の差はほぼ無視できます。Maka の通過1問あたりのコストは約0.0263ドル、DSH は約0.0262ドルで、最下位の Claude Code は0.0537ドルと両者の2倍以上です。全グループで最もコストが低かったのは Pi の0.0197ドルでした。知乎の記事はこれに基づいて「通過率-コスト」の二次元図を作成し、Codex、Maka、Pi がパレートフロンティアを構成し、Maka は DSH に近いコストで2位の通過率を獲得しており、まさに「性能と経済性のバランスを取った」代表だと指摘しています。博客园の実測記事が引用する第三者の30タスク横断評価は、別の角度から Harness 路線のコスト優位性を裏付けています。Pi Agent の成功タスクあたりのコストは約0.028ドル、Claude Code は0.195ドルで、差はほぼ7倍です。読者に正直に注記すべきなのは、この比較で DSH は標準モードではなくミニマルモードを使用しており、テストは Maka プロジェクト側が主導し、レポートと問題ごとの CSV を公開しているものの独立した再現はこれからだということです。さらに、DSH と Maka の間のこの4.5ポイントの差が安定しているかどうかは、単発実行ではモデルのサンプリングのランダム性の干渉がありますが、89問中56問(63%)が Harness によって結果が変わるという構造的現象は、「Harness を選ぶこと自体が一つの性能決定である」という核心的な論点を十分に支えます。

### 4.3 ライセンス、ガバナンス、エコシステム構造の対照

ライセンスとガバナンスの次元から見ると、2つの製品はまったく異なるがそれぞれ自己完結した道を選んでいます。DeepSeek Harness は MIT ライセンスを採用しており、これは最も寛容なオープンソースライセンスの一つで、誰でもコードを使用、修正し、その上に商用製品を構築できます。そのガバナンスは DeepSeek という単一ベンダーが主導し、コミュニティは GitHub Discussions、Discord、dsh-plugin トピックタグを通じて参加し、公式は「コアプラグインと API は継続的に進化する」と明示しています。Maka は Apache License 2.0 を採用し、Apache ソフトウェア財団による中立ガバナンスが提供されます。意思決定は公開で行われ、コミュニティが共同で治理し、知的財産はインキュベータープロセスによる審査を経ます。インキュベーターページによれば、プロジェクトのインキュベーション入りからわずか約1か月であり、著作権確認、頒布権利の検証、コミッター契約など大量のプロセス作業がまだ必要で、インキュベーション状態は「プロジェクトがまだ ASF の完全な承認を得ていないことを示す」とされています。エコシステム構造では、DSH はすでにプラグインマーケットの雛形を形成しています——公開当日に288の dsh-plugin リポジトリ、公式内蔵100以上のプラグイン。Maka のエコシステムは models.dev の provider 接続とコミュニティ協働の貢献が中心で、2日間で20以上の provider サポートが代表的な成果です。これは典型的な「ベンダーの速度 vs 財団の信用」の対照です。前者は速いが変わり得る、後者は遅いが予測可能です。Apache インキュベーションのブランド裏付けが Maka にもたらす「長期的な信頼性」は aiguide.cc によって第一の長所に挙げられ、Winder.AI の DSH への評価は「イテレーション速度が極めて速く、現在すべての機能が不安定」というのがまさに開発者プレビュー期間の真の姿であることを思い出させてくれます。

### 4.4 成熟度、バージョン状態、リスク露出

2つの製品の成熟度はいずれも初期段階ですが、リスクの性質は異なります。DeepSeek Harness は明確に開発者プレビュー段階にあり、公式 README は「互換性を破壊する変更の可能性がある」と注意喚起し、実行前にセキュリティアドバイザリを確認する必要があります。Wavect のエンタープライズ級レビューの結論は「範囲を管理したエンジニアリングパイロットには非常に適しているが、熱狂だけを根拠に直接採用できる本番コントロールプレーンではない」です。Maka も同様に「まだ Apache の正式バージョンをリリースしたことがなく」、公式は main ブランチから毎日ビルドする Desktop Nightly(Windows と Linux のビルドは未署名プレビュー)とソースコードからのビルドの2つの経路のみを提供し、README は Nightly が「ASF release ではなく、本番利用に適さない」と明確に述べています。バージョン面では、SourceForge のミラーディレクトリに v0.2.0-dev.15.20260902 開発ビルドが存在することが示されており、GitHub Releases の v0.1.11(2026年8月18日)は ASF のリリースプロセスを経ていません。正直なリスク注意は欠かせません。どちらの製品も「安定を求める」本番環境のユーザーに推薦すべきではなく、それらの推薦価値は技術探索、学習、パイロットのシナリオにあります。

### 4.5 プラットフォームサポート、利用ハードル、導入パス

プラットフォームサポートと導入ハードルでは、2つの製品の現状にはそれぞれ長所と短所があります。DeepSeek Harness は純粋な Node.js プロジェクトで、npx の一つのコマンドで Node.js がインストールされたあらゆるプラットフォームで Web UI を起動でき、プラットフォームの縛りはありません。そのサンドボックスは Linux では bubblewrap または Landlock、macOS では Seatbelt、Windows では ACL 制限付きトークンを使用し、権限プリセットには read-only、workspace-write、danger-full-access が含まれます。Maka のデスクトップは Electron ベースで、公式 Nightly は macOS(Apple Silicon と Intel)、Windows x64、Linux x64 と arm64 をカバーしますが、Windows と Linux のビルドは未署名プレビューです。一部の第三者レビュー(aiguide.cc、agentconn.com)はより保守的なプラットフォーム現状を記録しています——macOS Apple Silicon のみが主要サポートプラットフォームで、Linux はまだ正式サポートされていない——これは公式 README の基準との時間差であり、稳妥な表現は「公式 Nightly はすでに3大プラットフォームをカバーしているが Windows/Linux は未署名プレビューであり、第三者レビューがより早い時点で記録した可用性はより限定的」です。利用ハードル面では、DSH の起動は一つのコマンドで済みますが、深く使うには Cordis プラグイン機構、Profile、組み合わせパッケージの概念を理解する必要があります。Maka の初回実行ではモデル接続を自分で設定する必要があり(設定に入って API、ローカルモデル、または接続済みのアカウント接続を追加してテストする)、ビルド環境は Node.js 22.19 以上、npm、Git、ripgrep を要求し、開発用 Peer モードにはさらに Rust 1.98 以上が必要です。プロジェクト側は Maka の「初心者の導入体験」が弱点であると自認しており、DSH の「設定学習コスト」も同様にレビュアーが繰り返し言及する不満点です——2つの製品は「初期ツールの持病」で意外にも一致しています。

## 五、強みと弱みの深掘り分析:評価証拠から推薦結論へ

### 5.1 DeepSeek Harness の強み

DeepSeek Harness の第一の強みは**アーキテクチャの開放度が同類製品の中で他を圧倒している**ことです。公式はモデル、ツール、スキル、セッション、サンドボックス、ストレージ、ループ、スケジューリング、さらには UI まで、すべてを交換可能なプラグインとして定義しており、この徹底性は、チームが既存製品の周辺にパッチを当てるのではなく、完全にカスタマイズされた Agent ランタイムを組み立てられることを意味します。博客园の実測における「Claude Code と Codex をサブ Agent として呼び出す」能力は、このアーキテクチャの実際の威力を証明しています——ユーザーは既存ツールへの投資を保持したまま、Harness を上位のオーケストレーションとして使えます。第二の強みは**コスト構造**です。同一モデルのもとで、DSH の通過1問あたりのコストは約0.0262ドルで、Claude Code の半分未満です。36Kr の体験記事が記録した99%前後のキャッシュヒット率(時折60-70%に変動)と Token 消費のリアルタイムダッシュボードと合わせ、価格に敏感な開発者にとって現実的な魅力を構成しています。第三の強みは**オブザーバビリティ**です。トラジェクトリビューが提供するイベントレベルのリプレイ、発生元別に記録を閲覧する能力、そして「モデルに見えるものは記録される」というログ原則により、Agent の挙動はブラックボックスから監査可能な対象へと変わります。第四の強みは**エコシステムの勢い**です。21.7万スターの注目度、公開当日の288のサードパーティ製プラグインリポジトリ、公式の100以上の内蔵プラグインは、開発者が遭遇する問題にはおそらくすでにコミュニティの先行者が遭遇済みであることを意味します。第五の強みは**Headless バッチ能力**です。公式 Python SDK はプログラムによるループでモジュール単位のタスク実行をサポートし、この能力はクロスリポジトリのコード移行、バッチテスト、無人パイプラインなどのシナリオで対話型ツールでは代替不可能な価値を持ちます。

### 5.2 DeepSeek Harness の弱みとリスク

強みと同じくらい明確なのがその短所です。まず**成熟度リスク**です。開発者プレビュー状態に公式が明示する破壊的変更の可能性が重なり、現在のバージョンに基づいて構築するあらゆる本番システムは移行コストを見込んでおく必要があります。Wavect は「バージョンを固定し移行コストを見込むこと」を勧め、「プレビュー版のデフォルト値で顧客向けの自律操作を本番稼働させないこと」と警告しています。次に**セキュリティ境界の完全性への疑念**です。Wavect のレビューは、ファイルシステムサンドボックスがネットワークアクセスとプロセスの可視性をカバーしていないこと、旧版 Landlock 環境と現在の Windows ACL 境界が部分的な強制しか提供しない可能性があることを明確に指摘しており、エンタープライズ展開ではネットワークポリシー、独立したアイデンティティ、プラグイン審査、敵対的テストなどの統制措置を自前で補完する必要があります。第三は**信頼性問題の実測記録**です。AtlasCloud のレビューでは、同じタスクを3回実行したところいずれも完了を主張したものの、正常に使えるページは一つだけでした。同レビューはまた、ドキュメントサイトに記載のない2行の YAML 設定(compat.thinkingFormat と maxTokens)がタスクを36ステップ422秒から15ステップ152秒に短縮することを発見し、ドキュメントと実装の同期の遅れを傍証しています。第四は**リソース占用の論争**です。AtlasCloud は npm インストールで531個のパッケージ計306 MB がダウンロードされたこと(パッケージ自体はわずか172 KB)を記録し、Hacker News ではビルド後に1.5 GB、アイドルセッションのメモリが500 MB などの報告があります。同レビューはアイドル時の Web サーバーが35-40 MB の RSS にとどまることも同時に指摘していますが、依存チェーンへのコミュニティの疑問は確かに存在します。第五は**設定の学習曲線**です。Cordis プラグイン機構、Profile、組み合わせパッケージの概念は「開けたらすぐ使える」ことを求めるユーザーにとってハードルとなり、博客园と DataCamp のレビューの双方がプロバイダーの設定と profile への習熟が必要な環節に言及しています。

### 5.3 Apache Maka の強み

Maka の第一の強みは**ガバナンスの信用**です。Apache ソフトウェア財団のインキュベーションの裏付けがもたらすのは長期的なガバナンスの約束です——プロジェクトはいかなるモデルベンダーにも属さず、意思決定は公開で行われ、知的財産はインキュベーターの審査を経て、ライセンスは Apache 2.0 です。aiguide.cc はこれを第一の長所「長期的信頼性が高い」とし、agentconn.com は「Apache 財団の支援が長期メンテナンスへの信頼を提供する」と評価しています。第二の強みは**公開評価の文化**です。プロジェクトは「測定による、主張によらず」を公式 README の第1条に書き込み、公開するすべての評価レポートにタスクごとの CSV を添付し、OpenCode とのペアリング対比の統計検定の詳細(McNemar 検定、p = 0.0118)も公開しています。評価の権限をマーケティングの文句ではなく再現可能なデータに委ねるこのやり方は、Agent ツールエコシステムでは実に稀であり、メディアの引用にも稀な「検証可能な」素材を提供します。第三の強みは**監査級の実行記録**です。append-only の RuntimeEvent ログはメッセージ、ツール呼び出し、権限決定、終了イベントをカバーし、「古いツール出力は次のターンの prompt から離れてもログからは離れない」というコンテキスト剪定戦略と合わせ、Agent セッションに再現可能、復元可能、監査可能の三重の属性を与え、「コンテキストが短くなることは履歴の削除を意味しない」ことで性能と証拠保全の矛盾を解決しています。第四の強みは**ローカルデータ主権**です。セッション、キー、実行記録はデフォルトでローカルマシンに残り、モデルはクラウドにもローカルにも接続でき、サンドボックス越境の承認、0600/0700 のファイル権限、IPC ペイロード検証などの設計と合わせ、プライバシーに敏感なシナリオの完全なソリューションを構成しています。第五の強みは**製品の完全性**です。デスクトップ、TUI/CLI、Eval の3エントリーが単一の Runtime Host を共有し、評価がそのまま本番パスである設計は環境のずれを回避し、「日常的に使いつつ評価もしたい」技術チームへの推薦において独特のセールスポイントとなります。

### 5.4 Apache Maka の弱みとリスク

Maka の弱みも率直に示す必要があります。まず**リリース状態の空白期間**です。プロジェクトにはまだ Apache の正式リリース版がなく、公式 README はプレビルドのダウンロードを推奨しておらず、ユーザーは不安定な Nightly プレビューを使うかソースコードからビルドするかのどちらかであり、この状態は一般ユーザーにとって実質的な利用障壁となっています。次に**プラットフォームカバーがまだ上り坂**であることです。公式 Nightly の Windows と Linux ビルドはいずれも未署名プレビューで、第三者レビューはより早い時点で「Linux はまだサポートされていない」とさえ記録しており、macOS 以外のユーザーの実際の体験には著しい不確実性があります。第三は**エコシステムの規模が限定的**であることです。5.1千スターと476フォーク(閲覧時点のデータ)の規模は DeepSeek Harness や Codex、OpenCode などの競合よりはるかに小さく、プラグインとサードパーティ統合はまだ蓄積期間にあり、aiguide.cc は「プロジェクトが新しく、エコシステム、プラグイン、サードパーティ統合はまだ蓄積中」と明確に指摘しています。第四は**導入ハードルが高め**であることです。プロジェクト側は「Runtime 設計の先進性が製品の完成度と初心者の導入体験を上回っている」と自認しており、ビルド環境は Node.js 22.19 以上、ripgrep、さらには Rust ツールチェーン(Peer モード)を要求し、初心者に十分に友好的ではありません。第五は**データフォーマットの安定性リスク**です。公式 README は「Maka はまだ活発な開発中であり、データフォーマット、CLI コマンド、実験能力はまだ変わり得る」と明確に述べており、アップグレード後に古い JSONL 記録はインポートされず、認証情報は再入力が必要で、すでに利用データを持つ初期ユーザーにとっては移行コストを意味します。総合すると、Maka の位置づけは「技術哲学は先進的、ガバナンスの信用は堅実、製品化はまだ早い」という三角に焦点を当てるべきであり、過度な約束は避けるべきです。

## 六、執筆ガイドと素材の抽出

### 6.1 ナラティブの主軸と構成の提案

今回のおすすめは「一つの問い、二つの路線、一場の同時対決」というナラティブの主軸を採用できます。冒頭では2026年8月13日の「同日の縁」でサスペンスを作ります。同じ日に、一つのベンダーが史上最速で成長した Agent フレームワークをオープンソース化し、一つの財団が初の Agent Harness プロジェクトを受け入れました。続いて全文を貫く問いを提示します。Harness がモデルよりも重要な変数になるとき、開発者は「交換可能なオープンな土台」と「記録するローカルワークベンチ」のどちらを選ぶべきか。DeepSeek Harness の紹介では「一切皆插件」の概念で展開し、4つの実行モードを骨格に、21.7万スターと288の初日プラグインリポジトリを熱狂の証左に、トラジェクトリビューとコストデータを実用価値の論証に据えます。Maka の紹介では「ログこそランタイム」の公式で開幕し、Terminal-Bench 2.1 の77.5%対73.0%のデータで対比の緊張感を作り、Apache ガバナンスとローカルファーストのナラティブで締めくくります。比較章では第四節の比較表をそのまま使用し、「同じモデルで、Harness を変えると63%の問題の結果が変わる」という最も拡散力のあるデータポイントを添えます。結尾は「ツールの選択」ではなく「哲学の選択」に落とし込みます。自前構築とオーケストレーションが必要なら DSH、記録と監査が必要なら Maka、そして両者は相互排他的ですらありません——DSH のプラグインアーキテクチャは理論上 Maka 式のログ戦略を載せることもでき、Maka の Eval フレームワークも同様に DSH を評価できます。

### 6.3 表現の落とし穴とファクトチェックの要点

執筆時には以下の表現の落とし穴に特に注意が必要です。その1、DSH のインターフェース形態について:博客园(2026年8月20日)は「現在はウェブ版のみで CLI はない」と述べ、DataCamp(8月24日)は「ローカル Web UI、ヘッドレス CLI、Python SDK」の併存を記録しています。製品のイテレーションが極めて速いため、「Web UI を主な入り口とし、ヘッドレス CLI と Python SDK はプレビュー期間内に徐々に追加された」という稳妥な表現を採用し、絶対的な判断として書くことを避けるべきです。その2、Maka のプラットフォームサポートについて:公式 README の Nightly マトリックス(macOS AS/Intel、Windows x64、Linux x64/arm64)と一部の第三者レビューの保守的な記録には時間差があり、公式の基準を主としつつ「第三者レビューの記録時点はより早い」と注記すべきです。その3、スター数について:異なるメディアが異なる時間にサンプリングした DSH のスター数には大きな差があります(2日で9.5万、4日で14.1万、12時間で5万など)。引用時には必ずサンプリング時刻を明記するか、「本稿閲覧時点」という表現に統一すべきです。その4、横断評価の帰属について:Terminal-Bench 2.1 の9 Harness データは公開透明ではありますが、Maka プロジェクト側が主導して実施したものであり、執筆時は「Maka プロジェクト側が公開した、問題ごとの CSV と再現 PR が添付された横断評価データ」と表現し、読者に「独立した第三者評価」という錯覚を与えないようにすべきです。その5、「史上最速」系の表現について:Wavect はこの説が GitHub 公式の認定を得ていないことを明確に注意喚起しており、「オープンソース史上稀に見る爆発的な速度」へと弱めることを推奨します。その6、v2ex の実測データ(6000万トークン、97.5%のキャッシュヒット、約4元のコスト、スコア0.8-0.9)について:これはプロジェクト側の自己申告であり、引用時には「プロジェクト側が公開した初期の実測」と明記する必要があります。

### 6.4 タイトルの方向と読者層別戦略

2つの製品の素材の特徴に基づき、3類のタイトル方向が考えられます。データインパクト型のタイトルは横断評価データで直接コントラストを作れます。例:「同じ DeepSeek V4 Flash で、Harness を変えるだけで24問の差——今回は4.5ポイント差のこの2つをおすすめする」。概念アンカー型のタイトルはそれぞれの核心的な主張を際立たせます。例:「一方はすべてをプラグインに、もう一方はすべてをログに:2026年に最もフォローすべき Agent Harness 双雄」。視点誘導型のタイトルは深く読む読者に適しています。例:「ベンダーの Android と財団の台帳:DeepSeek Harness と Apache Maka の路線対決」。読者の層別けでは、本文を「5分速読版」(核心的位置づけ一文、キーデータ一表、適した読者一段)と「深掘り展開版」(アーキテクチャ原理、評価詳細、リスクリスト)に分け、それぞれ汎テック読者と開発者読者に奉仕することを提案します。適した読者層の表現は次のように提案します。DeepSeek Harness は、オープンソースとカスタマイズを重視し、バッチ無人タスクが必要で、複数の AI ツールを一つのワークフローに統合オーケストレーションしたく、コストに敏感でプレビュー期間の変動を受け入れられる開発者とプラットフォームエンジニアリングチームに推薦。Apache Maka は、実行の監査可能性とデータ主権を重視し、ローカルで Agent を実行する必要があり、コンプライアンス要件があるかセッションクラッシュで作業を失った経験があり、インキュベーション期間とソースコードビルドのハードルを受け入れられるユーザーに推薦。記事の末尾には「本番環境への導入は慎重に」という統一の注意と、それぞれの公式リポジトリとドキュメントへのリンクを添えるべきです。これは専門性の体現であると同時に、両製品の公式がバージョン状態について自ら位置づけていることにも合致します。

## 七、結論と展望

今回おすすめした2つのプロジェクトは、いま起こりつつある業界の判断を共同で実証しています。モデル能力が収斂する時代において、Harness はすでにエージェント性能の決定的な変数の一つとなり、「どの哲学で Harness を構築するか」は「どの Harness を使うか」よりも考えるに値する問いです。DeepSeek Harness は、MIT ライセンス、21.7万スター、「一切皆插件」の徹底的な開放性をもって、ベンダー主導のオープンソースエコシステムが到達し得る動員速度と拡張の限界を示しました。Apache Maka は、Apache 2.0 ライセンス、中立ガバナンス、「ログこそランタイム」の記録哲学をもって、財団路線の Agent インフラストラクチャ層における実現可能性と差別化の価値を証明しました。同一ベンチマークでの直接対決——Maka 77.5% 対 DSH 73.0% の通過率、ほぼ互角の1問あたりコスト——は、両者が同世代の製品として技術水準が近いことを示すと同時に、「Harness 間の競争」が長期にわたって動的な綱引きの状態にあることを示唆しています。

将来を展望すると、継続的に追跡する価値のある3つの方向があります。その1、DeepSeek Harness がいつ最初の安定版をリリースするか。これは「現象級のプレビュー」から「本番級のプラットフォーム」へ進めるかどうかを直接決定づけ、公式ドキュメントは現行バージョンについて「当面は本番システムをこれにロックしないことを推奨」と明確にしています。その2、Apache Maka がインキュベーション期間内に最初の ASF 正式リリースを完了し、導入体験を改善できるかどうか。これは「記録哲学」が製品化・実装の能力を備えているかを検証するものであり、プロジェクト側は製品の完成度が初心者の導入体験の弱点であることを公に認めています。その3、2つの製品が代表する「プラグイン化」と「ログ化」の二つの路線が融合するかどうか。DSH の追記式セッションログと Maka の RuntimeEvent はすでに第三者から「同じ先端方向に属する」と評価されており、Harness 同士が Agent Client Protocol を通じて互いを駆動し、さらには互いのサブエージェントになるというトレンドは、「どちらか一方を選ぶ」ことを最終的に「両方を組み合わせる」ことに変えるかもしれません。この2つのリポジトリのバージョンページと公式アナウンスを四半期ごとに再訪し続けることが、本稿の生命力を継続させる最も低コストの戦略となるでしょう——なぜなら、この2つのプロジェクトの今後のすべてのリリースが、それ自体新しいテーマになり得るからです。
