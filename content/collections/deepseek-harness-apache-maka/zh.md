本期推荐聚焦 2026 年 8 月 AI 开源领域最值得关注的两款 Agent Harness 项目:DeepSeek AI 官方开源的 DeepSeek Harness(简称 dsh)与 Apache 软件基金会孵化器新接纳的 Apache Maka(Incubating)。两者并非彼此复制,而是以截然不同的工程哲学回答了同一个时代问题——当大模型的能力趋于同质化,谁来定义智能体(Agent)真正"干活"的方式。DeepSeek Harness 以"一切皆插件"(Everything is a Plugin)为旗号,将模型、工具、会话、沙箱甚至 Agent 循环本身全部做成可插拔组件,开源不到一个月即在 GitHub 上积累了超过 21 万星标,成为史上增长最快的仓库之一。Apache Maka 则高举"本地优先"与"日志即运行时"(The Log is the Runtime)两面旗帜,将 Agent 的每一次模型消息、工具调用、权限决定与终止事件全部记录为只追加的 RuntimeEvent 日志,并在同一模型、同一官方验证器下公开了九个 Harness 的横向跑分,以 77.5% 的通过率力压 DeepSeek Harness 的 73.0% 位居第二。这两个项目恰好构成一个极具张力的组合:一个代表厂商驱动、社区爆发的开放生态路线,另一个代表基金会治理、数据驱动的中立路线,二者的同台对比本身就是理解 Agent 基础设施竞争的最佳样本。

## 一、选题背景:为什么"Harness"成了 2026 年的关键词

### 1.1 从"模型之争"到"框架之争"的范式转移

在 2026 年的 AI 技术叙事中,一个清晰的范式转移已经发生:业界讨论的重心正从"哪个模型更强"转向"模型被放在怎样的 Harness 里运行"。所谓 Agent Harness,按照行业通行的定义,指的是模型之外的所有代码、配置与执行逻辑,包括持续调用模型的循环、工具清单、沙箱环境、记忆机制以及决定哪些内容进入上下文窗口的规则。Winder.AI 团队在 2026 年 8 月发布的横向对比综述中将 AI 技术栈拆解为模型、Harness、框架、平台四层,明确指出 Harness 作为"运行单个代理"的中间层,其适配的技术栈层级比功能列表更重要。这一判断背后有扎实的实证支撑:Vercel 通过移除代理 80% 的工具,使同一模型的成功率从 80% 提升至 100%;LangChain 仅更换 Harness 就将编码代理在 Terminal Bench 上的得分从 52.8% 提升至 66.5%;普林斯顿大学的 CORE-Bench 测试显示同一模型在不同脚手架下的得分从 42% 到 78% 不等。可以说,在模型基础能力趋近的当下,Harness 已经从"套壳"升格为决定智能体成败的关键基础设施。

### 1.2 两个项目的"同日之缘"与历史定位

本期推荐的两个项目之间存在一个极具新闻价值的巧合:2026 年 8 月 13 日,DeepSeek AI 在开源其 Harness 的同时发布了 V4 Pro 模型的 API 涨价方案,而 Apache 软件基金会恰在同一天正式接纳 Maka 进入孵化器。这个日期节点在 AI 开源史上具有象征意义——厂商驱动的开源与基金会治理的开源在同一天各自落下重要一子。从产品形态看,DeepSeek Harness 是一个纯运行时框架,官方定位为"Agent = 模型 + Harness"公式中的后者,与 DeepSeek V4 系列模型深度绑定,被多家媒体解读为对标 Anthropic Claude Code 的开源可构建替代方案。Apache Maka 则是一个完整的桌面工作台产品,其英文定位为"high-performance agent workspace that keeps a complete record of everything it did"(高性能的 Agent 工作台,完整记录它做过的每一件事),仓库创建于 2026 年 5 月 27 日,入孵时已有约十周的密集开发历史。两者一个偏"框架"、一个偏"产品",一个强调可替换、一个强调可记录,恰好覆盖了 Agent Harness 光谱的两端,这正是将它们放在同一期推荐中的核心理由。

## 二、DeepSeek Harness:一切皆插件的开源 Agent 运行时

### 2.1 项目速览与爆发式热度

DeepSeek Harness 由 DeepSeek AI 官方开发,以 MIT 许可证开源,命令行入口为 dsh,官方项目主页将其核心主张概括为一句话——一切皆为插件:模型、工具、技能、会话、沙箱、存储、循环、调度以及用户界面,所有能力都可以被替换或重新组合。项目官方文档指出,DeepSeek 的模型基准测试即使用 Harness 的极简模式作为框架,DeepSeek 系列模型的 Code Agent 文本任务测试均采用 max 档位与 temperature=1.0 的参数组合。这个项目的热度轨迹在开源史上极为罕见:博客园的一篇实测文章记录其开源当晚 12 小时即冲到 5 万星标,发布当天标着 dsh-plugin 标签的第三方插件仓库就冒出了 288 个;Medium 平台的报道称其四天内获得 141,000 星标;而 Winder.AI 的综述则记录其两天内获得 95,386 星标。需要说明的是,不同媒体在不同时间点采样的数字差异较大,且 Wavect 特别提示"GitHub 历史上增长最快"的说法未得到 GitHub 官方认证,引用时应以官方仓库实时数据为准并标注采样时间。

### 2.2 核心架构:Cordis 内核与插件化运行时

理解 DeepSeek Harness 的关键在于其底层的 Cordis 元框架。官方预览页将 Cordis 描述为负责管理插件挂载、卸载以及依赖关系的"内核",代理的所有能力都以插件形式存在,Cordis 的服务与事件机制让插件之间协同工作,开发人员通过配置即可选择、替换或扩展任何能力,无需修改框架源代码。Eigent AI 的中文解读进一步澄清了插件化的边界:不仅工具与技能是插件,模型适配器本身、会话与运行状态、沙箱环境、存储位置、循环与调度逻辑乃至 UI 界面本身都是插件。这一架构的直接推论是"不存在需要打补丁的特权内核"——官方文档明确表述扩展 dsh 的方式是把插件挂载到其他插件旁边,而非围绕一个封闭核心做外围扩展。DataCamp 的对比文章从工程视角印证了这一设计:Cordis 让插件发现服务并交换事件,依赖变更会加载或卸载插件,热重载会清理过期监听器与后台作业,默认 profile 将循环展示为配置。与 Claude Code 的对比最能凸显差异:后者围绕固定内置循环提供 skills、hooks、MCP 等外围扩展机制,而 Harness 的插件可以直接定义运行时本身的组成部分,即"DeepSeek Harness 可承载 Claude,但 Claude Code 不能承载 DeepSeek"。

### 2.3 四种运行模式与 Agent 预设体系

DeepSeek Harness 内置了四种经过官方设计的运行模式,本质上是同一套插件库的不同组合预设。标准模式是功能完整的编码 Agent,涵盖文件编辑、Shell、文件与网页检索、技能(Skills)、计划模式、目标追踪、子代理和工作流等全部能力。代码模式(PTC 模式)在标准模式基础上额外提供 Code Mode SDK,允许模型编写 TypeScript 程序来组合多步操作,而非发起多次独立工具调用,适合批量操作场景。极简模式仅保留持久化 bash 和 str_replace_editor 两个工具,是官方用于基准测试与最小化复现的干净环境,官方文档确认 DeepSeek 系列模型的公开基准测试均使用该模式。创建者模式则面向"用 Agent 造 Agent"的进阶场景,在标准模式全部能力之上加入运行时检查、插件实验和预设创作指导,用户可以检查当前运行时、在内存中测试 Cordis 插件并将其组合成新的模式。四种模式的递进关系清晰:标准模式做事、代码模式编排、极简模式评测、创建者模式进化——这一体系化的预设设计本身就是值得展开的产品亮点。

### 2.4 可观测性设计:轨迹视图与追加式会话日志

DeepSeek Harness 在可观测性上的投入体现了其对"可追溯"的高度重视。官方预览页明确承诺"每次运行均可追溯":模型接收的所有内容都会被记录在仅追加的会话日志中,包括系统提示、推理过程、工具调用和结果、子代理调度以及所有上下文注入,轨迹视图(Trajectory view)允许用户按来源查看这些记录,恢复、分叉、搜索和重播操作都基于同一个事件流。36 氪授权转载的量子位体验文章详细描述了这一功能的实际价值:随着 Agent 运行越久、工具链越复杂,聊天摘要会越来越黑盒,而轨迹功能提供了一个随时监控 Agent 的回放窗口,能直接看到原始事件级记录,直观定位模型在哪一步栽了跟头、每个环节烧了多少钱。DataCamp 的评价是"模型所见即所录"(Model-visible means logged),并指出其在 UI 中呈现的运行路径细节比 Claude Code 的 JSONL 记录更丰富。值得注意的是,这一"追加式日志"设计与 Apache Maka 的 RuntimeEvent 日志在思路上同属前沿方向,aiguide.cc 的对比文章将两者并列为"记录即真相"路线的代表——两款产品从不同起点出发,最终在"日志作为唯一事实源"这一原则上殊途同归。

### 2.5 插件生态与社区组织方式

DeepSeek Harness 的生态建设策略呈现出鲜明的"操作系统化"特征。量子位的体验文章将其比喻为"Agent 时代的安卓":官方已内置一百多个插件,社区可以像《我的世界》装模组一样安装第三方插件,甚至仓库文档中包含手把手从零构建插件、接入官方 Harness 的完整教程,还内置了一个魔改 Cordis 的 Skill。官方预览页提供了社区插件索引入口(GitHub 的 dsh-plugin 话题标签),并欢迎 Harness 开发者加入 DSH 插件生态系统,同时通过 GitHub Discussions 和 Discord 承载社区协作。博客园的实测进一步揭示了一个关键能力:Harness 内置了把 Claude Code 和 Codex 作为子 Agent 调用的 Provider,通过解析 PATH 中的对应二进制文件实现委托执行,这意味着用户可以用 Harness 做上层编排,把竞品工具纳入自己的工作流而非取代它们。Winder.AI 的综述也确认了这一点,并指出 Zed Agent、OpenHands 与 DeepSeek Harness 均支持 Agent Client Protocol 可互相驱动——Harness 之间的互操作性正在成为行业趋势。

### 2.6 上手方式与开发者体验

DeepSeek Harness 的上手门槛可用"五分钟启动、深入需学习"来概括。官方提供的最快启动方式是在装有 Node.js 的环境下执行 `npx @deepseek-ai/dsh web`,默认在 http://127.0.0.1:3080 启动 Web UI 并自动打开浏览器,通过 SSH 启动时仅打印主机地址以便本地转发。从源码运行则需要克隆仓库后依次执行 `pnpm install`、`pnpm run build` 与 `pnpm dsh web`。首次使用需要用户自行配置模型 API Key——官方预览页与 36 氪体验文章均确认 Harness 不内置共享模型账号,用户可接入 DeepSeek 开放平台或其他供应商的模型。博客园实测指出目前交互界面以网页版为主,对习惯终端的开发者不够友好,但 Headless 模式与官方 Python SDK 支持程序化批量运行,可逐文件或逐模块执行无人值守任务,这一能力在批量代码迁移等场景下显著优于交互式工具。DataCamp 的对比表则记录其使用界面包括本地 Web UI、无头 CLI 与 Python SDK。两篇评测对 CLI 状态的描述存在时间口径差异(博客园文章发布于 2026 年 8 月 20 日,DataCamp 文章发布于 8 月 24 日),稳妥的表述是"早期版本以 Web UI 为主,迭代中逐步补充无头 CLI 与 Python SDK",并提醒读者该产品迭代速度极快,功能矩阵可能随时变化。

## 三、Apache Maka:记录一切的本地优先 Agent 工作台

### 3.1 项目速览与 Apache 孵化之路

Apache Maka 是 Apache 软件基金会孵化器接纳的首个以 Agent Harness 为核心定位的项目。孵化器官方页面将其描述为"一款本地优先的 AI 代理运行时与工作空间,将模型消息、工具调用、工具结果、权限决策和终止事件记录在仅追加日志中"。项目由 Apache Incubator PMC 主办,Champion 为 tison(Zili Chen),配备四名导师(Mentors),提交者名单包括 Kun Li、Jie Wen、Yuhan Lei 等七人。项目仓库创建于 2026 年 5 月 27 日,7 月 14 日时项目方在 v2ex 社区发布分享帖时仅有 666 星标、70 复刻,8 月 13 日进入孵化器后关注度快速攀升——aiguide.cc 在 8 月 24 日前后记录约 2,381 星标,agentconn.com 在 8 月 26 日记录 3.6 千星标,而本文写作时(2026 年 9 月 9 日)官方仓库已显示 5.1 千星标、476 复刻与 4507 次提交。这一增长曲线虽然远不及 DeepSeek Harness 的爆发式轨迹,但配合 2026 年 8 月 23 日登顶 GitHub Trending 榜首、8 月 24 日拿下 TypeScript 分类当日仓库之星的表现,足以支撑"Apache 生态中最受关注的 AI 新项目之一"的推荐定位。

### 3.2 核心理念:日志即运行时(The Log is the Runtime)

Maka 的产品哲学浓缩在其官网上反复出现的一个公式中:State(t) = Project(Log[0…t]),即系统在任意时刻的状态,都是有序日志经过投影之后的结果。官方 README 将其具象化为"日志就是运行时"原则:每条模型消息、工具调用、权限决定和终止事件都是一条只追加的 RuntimeEvent,界面、下一轮 prompt 和崩溃恢复都是这份日志的投影,从不是唯一副本;旧的工具输出可以离开下一轮 prompt 而不会离开日志。CSDN 的技术解析文章从分布式系统视角解释了这一设计的思想来源:这是 log-first 思想在 Agent 领域的落地,即先保存有序、不可含糊的变化事实,再让消费者重建自己的状态,从而可靠地回答"在某事件边界之前模型看到了什么、调用过什么工具、哪些权限被请求或决定"等关键问题。这一设计的实际价值在 v2ex 的项目方分享帖中有更朴素的表达:市面上 AI Desktop 已经很多,Maka 想解决的不是"聊天界面好不好看",而是"Agent 执行的过程要不要被当作一等公民保留下来",项目标语为"Maka preserves experience as evidence"(Maka 将经验保存为证据)。"日志即运行时"是一个既有技术深度又易于讲清楚的叙事支点——它把"可审计、可恢复、可复现"这三个抽象卖点统一到了一个可视化原理之下。

### 3.3 统一 Runtime Host 与三入口架构

Maka 的架构设计中另一个值得推荐的亮点是"单一运行时宿主"(One Runtime Host)原则。官方 README 明确:Desktop、TUI 和 CLI、Eval 都是薄客户端,执行只由这一个 Runtime Host 说了算,Eval 只拥有实验和分数。这意味着桌面端的图形界面、终端的 TUI/CLI 与评测框架共享完全相同的执行路径,评测结果可以无缝迁移到生产场景。这一设计消除了"评测环境与生产环境不一致"的经典工程陷阱。aiguide.cc 的评测将此列为创新点:桌面、CLI、Eval 共享一个运行时,评测结果可复现,实验与生产同一执行路径。在入口层面,桌面端是基于 Electron 加 React 构建的本地应用,提供流式会话、工具时间线、分支与恢复等功能;终端入口支持 `npm run cli` 启动 TUI 或执行单次 Turn;Eval 入口则支持声明式多臂实验(task × repetition × subject),输出分数、用量、成本、时长等结果内核。此外,Maka 内置 Read、Write、Edit、Bash、Glob、Grep 六个基础工具,并提供与提供商无关的 Model Context Protocol 客户端集成,MCP 工具会自动获得现有权限控制、运行时事件日志与遥测能力。这一套"工作台 + 评测框架"的完整产品形态,使 Maka 在"纯框架"与"纯聊天工具"之间找到了差异化位置。

### 3.4 用数据说话:Terminal-Bench 2.1 九 Harness 横评

Maka 最锋利的素材是其公开的横向评测数据。项目官网首页的核心宣传语是"Measured, not claimed"(靠测量,不靠宣称),并公开展示了两组测试结果。第一组是在 DeepSeek V4 Flash 上跑完 Terminal-Bench 2.1 全部 89 道任务、由官方验证器统一判分的九 Harness 对比:Codex 以 82.0% 的通过率排名第一,Maka 以 77.5% 位居第二,Pi 为 74.2%,DeepSeek Harness(极简模式)为 73.0%,ZCode 为 70.8%,Reasonix 为 67.4%,OpenCode 为 65.2%,Kimi Code 为 59.6%,Claude Code 以 55.1% 垫底。第二组是 Maka 与 OpenCode 的配对单次运行对比,经 McNemar 检验确认差距显著(p = 0.0118),Maka 以 68.5% 对 55.1% 领先 13.5 个百分点,且每个通过任务的成本基本相同。知乎文章对这组数据的解读极具传播力:同一个模型、同样的 reasoning max 档位,第一名与最后一名相差 26.9 个百分点、整整 24 道题;89 道题中仅 28 道被九个 Harness 全部通过、5 道全部做错,剩下 56 道(约 63%)在不同 Harness 上出现了不同结果。该文进一步指出,Harness 正在成为模型能力之外最重要、也最容易被忽视的一层基础设施,而 Maka 选择进入 Apache 正是为了把这一层交给一个开放、中立、长期存在的社区治理。需要诚实标注的是:该横评由 Maka 项目方主导实施,虽然测试报告、逐题结果与实验口径均已公开并附有复现 PR,独立第三方尚未全面复现,引用时应注明"项目方公开数据"这一属性。

### 3.5 安全、权限与本地优先的隐私设计

Maka 的第三个核心卖点是围绕本地数据主权构建的安全设计。官方 README 承诺"数据在你的机器上,模型由你接":会话、设置和运行记录保存在本机,用户自带模型——云 API、本地模型或兼容网关均可。工作区数据默认存放在 Electron userData 目录下,包括 runtime.sqlite、连接目录、凭据保险库与设置文件;API 密钥等机密存放在仅系统账号可读的本地文件 credential-vault.json 中,渲染进程(界面进程)拿不到明文。工具执行层面,写文件、跑 Shell 的工具必须先过沙箱边界,越界操作必须请求权限审批,运行可中止,失败会被分类。CSDN 的架构解析补充了更细粒度的安全措施:stdio 默认只继承运行所需的环境变量白名单,所有 MCP 工具按 mutation 处理需要明确授权,主进程对 IPC 载荷做运行时验证,配置文件采用 0600/0700 的严格文件权限,对模型文本、图像数量和总大小做聚合边界检查。agentconn.com 的评测特别指出,Maka 的追加式日志天然支持崩溃恢复与中断任务恢复,这对"曾因代理会话崩溃而丢失工作"的用户极具吸引力,但其本地优先架构也意味着没有内置的跨设备同步功能。这一组特性使 Maka 成为隐私敏感场景(如企业内部敏感代码库、合规审计需求)下的推荐首选,与 DeepSeek Harness 的云模型路线形成了清晰的使用场景分流。

### 3.6 社区协作的密度与速度

如果说 DeepSeek Harness 的社区优势在于规模,Maka 的社区优势则在于密度。知乎文章援引项目方统计,从 5 月 27 日建仓后约十周内,Maka 积累了约 71 万行 TypeScript(其中约 35 万行是测试)、949 个测试文件、2,439 次提交、1,218 个已合并 PR、93.8% 的 PR 合并率,PR 合并时间中位数约 33.5 分钟,仅 7 月就合并了 943 个 PR。v2ex 的分享帖补充了另一组早期数据:9 天内 300 个 commit(111 个 fix、103 个 feat),日均 33 个 commit,核心贡献者两三人。尤为值得注意的是社区的自组织能力:发布前两日有社区用户提出对齐 models.dev 全量 provider 支持的需求并发起认领,两天内社区陆续提交了 20 多个 provider 支持,覆盖 Cloudflare Workers AI、Hugging Face、Vercel AI Gateway、Cohere、Mistral、xAI、Together AI 以及火山方舟、腾讯、StepFun 等国内外服务。这种高频协作、快速验证的 builder 社区气质,是 Apache 孵化器中相当罕见的"新物种"。当然,也需要诚实呈现另一面:项目方在 v2ex 帖中坦承"Runtime 设计的先进性超过了产品闭环和新手上手体验,首次接触的开发者难以在五分钟内完成启动并清晰查看一次 Agent Run 的完整流程",这是后续优先优化的方向。

## 四、横向对比:两款产品在同一基准与同一坐标系下的表现

### 4.1 定位与设计哲学的差异

两款产品最本质的差异在于它们对"Harness 应该是什么"的回答。DeepSeek Harness 的哲学是"可替换性优先":官方预览页将"一切皆为插件"列为设计理念第一条,强调开发人员通过配置即可选择、替换或扩展任何能力。它的隐喻是操作系统或积木底板——Eigent AI 将其定位为"包裹语言模型的运行时层",量子位则直接称之为"Agent 时代的安卓"。Maka 的哲学则是"可记录性优先":官方 README 的四条核心特点全部围绕测量与记录展开——靠测量不靠宣称、日志就是运行时、数据在你的机器上、一个 Runtime Host。它的隐喻是账本或黑匣子——把 Agent 的每一笔"行为交易"都以不可篡改的方式落盘。aiguide.cc 的对比表格用一句话精准概括了这一分野:Maka 是"本地优先 Agent 工作区(记录即真相)",DeepSeek Harness 是"一切皆插件 Agent 运行框架"。理解了这个哲学差异,两款产品在其他维度上的表现差异就有了统一的解释框架:DSH 为可替换而牺牲了稳定承诺(开发者预览、破坏性变更警告),Maka 为可记录而牺牲了生态规模(孵化期、无正式发布版)。

### 4.2 性能与成本的同基准直接交锋

两款产品在同一基准下的直接对比数据,是最具说服力的素材。在 Terminal-Bench 2.1 的九 Harness 横评中,Maka 以 77.5% 的通过率领先 DeepSeek Harness(极简模式)的 73.0% 约 4.5 个百分点。成本维度上两者的差距几乎可以忽略:Maka 每通过一题的成本约 0.0263 美元,DSH 约 0.0262 美元,而垫底的 Claude Code 高达 0.0537 美元,约为两者的两倍以上;全组成本最低的 Pi 为 0.0197 美元。知乎文章据此绘制了"通过率-成本"二维图,指出 Codex、Maka 和 Pi 构成帕累托前沿,而 Maka 用接近 DSH 的成本取得了第二名的通过率,正是"在性能与经济性之间取得平衡"的代表。博客园实测文章引用的第三方 30 任务横评则从另一个角度佐证了 Harness 路线的成本优势:Pi Agent 每个成功任务成本约 0.028 美元,Claude Code 是 0.195 美元,相差近 7 倍。需要向读者诚实标注的是:这组对比中 DSH 使用的是极简模式而非其标准模式,且测试由 Maka 项目方主导、公开了报告与逐题 CSV 但独立复现尚待展开。此外,DSH 与 Maka 之间的这 4.5 个百分点差异是否稳定,在单次运行中存在模型采样随机性的干扰,但 89 道题中 56 道(63%)随 Harness 改变结果这一结构性现象,足以支撑"选择 Harness 本身就是一种性能决策"的核心论点。

### 4.3 许可证、治理与生态结构的对照

从许可证与治理维度看,两款产品选择了截然不同但各自自洽的路径。DeepSeek Harness 采用 MIT 许可证,这是最宽松的开源许可证之一,允许任何人使用、修改代码并在此基础上构建商业产品。其治理由 DeepSeek 单一厂商主导,社区通过 GitHub Discussions、Discord 与 dsh-plugin 话题标签参与,官方明示"核心插件与 API 将持续演进"。Maka 采用 Apache License 2.0,并由 Apache 软件基金会提供中立治理:决策公开做出、社区共同治理、知识产权经过孵化器流程审查。孵化器页面显示该项目进入孵化仅约一个月,仍需完成版权确认、分发权利验证、提交者协议等大量流程性工作,且孵化状态"表明该项目尚未得到 ASF 的完全认可"。生态结构上,DSH 已形成插件市场的雏形——发布当天 288 个 dsh-plugin 仓库、官方内置 100 多个插件;Maka 的生态则以 models.dev 的 provider 接入与社区协作贡献为主,两天内 20 多个 provider 支持是其代表性成果。这是一个典型的"厂商速度 vs 基金会信用"对照:前者快而可能变,后者慢而可预期。Apache 孵化的品牌背书给 Maka 带来的"长期可信度"被 aiguide.cc 列为第一优点,而 Winder.AI 对 DSH 的评价则提醒我们"迭代速度极快,目前所有功能均不稳定"正是其开发者预览期的真实状态。

### 4.4 成熟度、版本状态与风险敞口

两款产品的成熟度都处于早期,但风险的性质不同。DeepSeek Harness 明确处于开发者预览阶段,官方 README 提醒"存在兼容性破坏变更的可能",运行前需查看安全公告;Wavect 的企业级评测结论是"很适合做范围受控的工程试点,但还不是可以仅凭热度直接采用的生产控制平面"。Maka 同样"尚未发布过 Apache 正式版本",官方只提供每日从 main 分支构建的 Desktop Nightly(Windows 和 Linux 构建为未签名预览)与源码构建两条路径,README 明确 Nightly"不是 ASF release,不适合生产使用"。版本方面,SourceForge 镜像目录显示存在 v0.2.0-dev.15.20260902 开发构建,GitHub Releases 上的 v0.1.11(2026 年 8 月 18 日)未经 ASF 发布流程。诚实的风险提示必不可少:两款产品都不应被推荐给"求稳"的生产环境用户,它们的推荐价值在于技术探索、学习与试点场景。

### 4.5 平台支持、使用门槛与上手路径

在平台支持与上手门槛上,两款产品的现状各有长短。DeepSeek Harness 是纯 Node.js 项目,通过 npx 一行命令即可在任何装有 Node.js 的平台启动 Web UI,无平台绑定;其沙箱在 Linux 上使用 bubblewrap 或 Landlock、macOS 上使用 Seatbelt、Windows 上使用受 ACL 限制的令牌,权限预设包括 read-only、workspace-write 与 danger-full-access。Maka 的桌面端基于 Electron,官方 Nightly 覆盖 macOS(Apple Silicon 与 Intel)、Windows x64、Linux x64 与 arm64,但 Windows 与 Linux 构建为未签名预览;部分第三方评测(aiguide.cc、agentconn.com)记录了更保守的平台现状——仅 macOS Apple Silicon 为主要支持平台,Linux 尚未正式支持,与官方 README 的口径存在时间差,稳妥的表述是"官方 Nightly 已覆盖三大平台但 Windows/Linux 为未签名预览,第三方评测在更早时间点记录的可用性更有限"。使用门槛方面,DSH 的启动只需一条命令但深入使用需理解 Cordis 插件机制、Profile 与组合包概念;Maka 的首次运行需自行配置模型连接(进入设置添加 API、本地模型或已接通的账号连接并测试),构建环境要求 Node.js 22.19 以上、npm、Git 与 ripgrep,开发 Peer 模式还需 Rust 1.98 以上。项目方自认 Maka 的"新手上手体验"是其短板,而 DSH 的"配置学习成本"同样是评测者反复提及的槽点——两款产品在"早期工具的通病"上意外地达成了一致。

## 五、优劣势深度剖析:从评测证据到推荐结论

### 5.1 DeepSeek Harness 的优势

DeepSeek Harness 的第一项优势是**架构开放度在同类产品中无出其右**。官方将模型、工具、技能、会话、沙箱、存储、循环、调度乃至 UI 全部定义为可替换插件,这种彻底性意味着团队可以组装出完全定制化的 Agent 运行时,而非在既有产品外围打补丁。博客园实测中"把 Claude Code 和 Codex 作为子 Agent 调用"的能力证明了这一架构的实际威力——用户可以保留对既有工具的投资,用 Harness 做上层编排。第二项优势是**成本结构**:在同一模型下,DSH 每通过一题的成本约 0.0262 美元,不到 Claude Code 的一半,配合 36 氪体验文章中记录的 99% 左右缓存命中率(偶有 60-70% 波动)与 Token 消耗实时仪表盘,构成了对价格敏感开发者的现实吸引力。第三项优势是**可观测性**:轨迹视图提供的事件级回放、按来源查看的记录能力以及"模型所见即所录"的日志原则,使 Agent 行为从黑盒变为可审计对象。第四项优势是**生态势能**:21.7 万星标的关注度、发布当天 288 个第三方插件仓库、官方 100 多个内置插件,意味着开发者遇到的问题大概率已有社区先行者踩过。第五项优势是 **Headless 批量能力**:官方 Python SDK 支持程序化循环逐模块执行任务,这一能力在跨仓库代码迁移、批量测试、无人值守流水线等场景中具有交互式工具无法替代的价值。

### 5.2 DeepSeek Harness 的劣势与风险

与优势同样清晰的是其短板。首先是**成熟度风险**:开发者预览状态叠加官方明示的破坏性变更可能,意味着任何基于当前版本构建的生产系统都需预留迁移成本,Wavect 建议"固定版本并预留迁移成本",并警告"不要使用预览版默认值上线面向客户的自主操作"。其次是**安全边界的完整性存疑**:Wavect 评测明确指出其文件系统沙箱不覆盖网络访问与进程可见性,旧版 Landlock 环境与当前 Windows ACL 边界还可能只提供部分强制执行,企业部署需自行补充网络策略、独立身份、插件审查与对抗测试等控制措施。第三是**可靠性问题的实测记录**:AtlasCloud 的评测中,三次相同任务运行均声称完成但仅一个页面可正常使用;该评测还发现两行未在文档网站说明的 YAML 配置(compat.thinkingFormat 与 maxTokens)可将任务从 36 步 422 秒缩短至 15 步 152 秒,侧面反映文档与实现的同步滞后。第四是**资源占用争议**:AtlasCloud 记录 npm 安装下载 531 个包共 306 MB(包本身仅 172 KB),Hacker News 上有用户反馈构建后 1.5 GB、空闲会话内存 500 MB 等情况,虽然该评测同时指出空闲时 Web 服务器仅占 35-40 MB RSS,但社区对依赖链的质疑确实存在。第五是**配置学习曲线**:Cordis 插件机制、Profile 与组合包概念对只想"开箱即用"的用户构成门槛,博客园与 DataCamp 的评测都提到需要配置提供方并熟悉 profile 的环节。

### 5.3 Apache Maka 的优势

Maka 的第一项优势是**治理信用**:Apache 软件基金会的孵化背书带来的是长期治理承诺——项目不属于任何模型厂商,决策公开做出、知识产权经孵化器审查、许可证为 Apache 2.0。aiguide.cc 将其列为第一优点"长期可信度高",agentconn.com 则评价"Apache 基金会的支持为其长期维护提供了信心"。第二项优势是**公开测评文化**:项目将"靠测量不靠宣称"写进官方 README 第一条,发布的每份评测报告都附逐任务 CSV,并公开了与 OpenCode 配对对比的统计检验细节(McNemar 检验,p = 0.0118)。这种把评价权交给可复现数据而非营销话术的做法,在 Agent 工具生态中实属罕见,也为媒体引用提供了罕见的"可核验"素材。第三项优势是**审计级执行记录**:append-only RuntimeEvent 日志覆盖消息、工具调用、权限决策与终止事件,配合"旧工具输出可离开下一轮 prompt 而不离开日志"的上下文裁剪策略,使 Agent 会话具备可重现、可恢复、可审计三重属性,且"更短的上下文不等于删除历史"解决了性能与证据留存的矛盾。第四项优势是**本地数据主权**:会话、密钥与运行记录默认留在本机,模型可接云端也可接本地,配合沙箱越界审批、0600/0700 文件权限、IPC 载荷验证等设计,构成隐私敏感场景的完整方案。第五项优势是**产品完整性**:桌面端、TUI/CLI、Eval 三入口共享单一 Runtime Host,评测即生产路径的设计避免了环境偏差,这在推荐给"既要日常用又要做评测"的技术团队时是一个独特卖点。

### 5.4 Apache Maka 的劣势与风险

Maka 的劣势同样需要坦诚呈现。首先是**发布状态的空窗**:项目尚无 Apache 正式发布版本,官方 README 不推荐预构建下载,用户要么用不稳定的 Nightly 预览、要么从源码构建,这一状态对普通用户构成了实质性使用障碍。其次是**平台覆盖仍在爬坡**:官方 Nightly 的 Windows 与 Linux 构建均为未签名预览,第三方评测在更早时间点甚至记录"Linux 尚未支持",对非 macOS 用户的实际体验存在显著不确定性。第三是**生态体量有限**:5.1 千星标与 476 复刻的规模(阅读时数据)远小于 DeepSeek Harness 与 Codex、OpenCode 等竞品,插件与第三方集成仍在积累期,aiguide.cc 明确指出"项目较新,生态、插件与第三方集成仍在积累"。第四是**上手门槛偏高**:项目方自认"Runtime 设计的先进性超过了产品闭环和新手上手体验",构建环境要求 Node.js 22.19 以上、ripgrep 乃至 Rust 工具链(Peer 模式),对新手不够友好。第五是**数据格式稳定性风险**:官方 README 明确"Maka 仍在活跃开发中,数据格式、CLI 命令和实验能力仍可能变化",且升级后旧 JSONL 记录不会被导入、凭据需重新填写,对已有使用数据的早期用户意味着迁移成本。综合来看,Maka 的定位应聚焦"技术哲学先进、治理信用扎实、产品化尚早"的三角,避免过度承诺。

## 六、写作指南与素材提炼

### 6.1 叙事主线与结构建议

本期推荐可采用"一个问题、两条路线、一场同台对决"的叙事主线。开篇用 2026 年 8 月 13 日的"同日之缘"制造悬念:同一天里,一家厂商开源了历史上增长最快的 Agent 框架,一个基金会接纳了首个 Agent Harness 项目。继而提出贯穿全文的问题:当 Harness 成为比模型更重要的变量,开发者该选择"可替换的开放底座"还是"可记录的本地工作台"。介绍 DeepSeek Harness 时,以"一切皆插件"的概念展开,用四种运行模式做骨架、以 21.7 万星标与 288 个首日插件仓库做热度佐证、以轨迹视图与成本数据做实用价值论证。介绍 Maka 时,以"日志即运行时"的公式开场,用 Terminal-Bench 2.1 的 77.5% 对 73.0% 数据制造对比张力,再用 Apache 治理与本地优先叙事收束。对比章可直接使用第四节的对比表,配以"同一个模型,换一个 Harness,63% 的题目结果会改变"这一传播力最强的数据点。结尾落到"选择哲学"而非"选择工具":需要自建与编排选 DSH,需要记录与审计选 Maka,两者甚至不互斥——DSH 的插件架构理论上也能承载 Maka 式的日志策略,而 Maka 的 Eval 框架同样可以评测 DSH。

### 6.2 核心数据点与金句素材库

下列经过多源验证的数据点与表述可放心引用并标注来源。热度类数据:DeepSeek Harness 官方仓库 21.7 万星标、2.57 万复刻、16089 次提交(2026 年 9 月 9 日阅读时数据),发布后三个日历日内星标超 12.1 万;Maka 仓库 5.1 千星标、476 复刻、4507 次提交,2026 年 8 月 23 日登顶 GitHub Trending。性能类数据:Terminal-Bench 2.1 九 Harness 通过率从 Codex 82.0% 到 Claude Code 55.1% 的完整排名,Maka 77.5% 第二、DSH 73.0% 第四,89 道题中 56 道(约 63%)结果随 Harness 改变;成本方面 Maka 约 0.0263 美元/题、DSH 约 0.0262 美元/题、Claude Code 0.0537 美元/题。金句类素材:"Agent 时代的安卓"(量子位对 DSH 的比喻);"Measured, not claimed"与"State(t) = Project(Log[0…t])"(Maka 官方宣传语);"模型是大脑,Harness 是手脚和神经系统"(博客园对官方定义的转述);"Claude Code 是精装房,Harness 是连施工图都开源的毛坯加预制件"。社区类数据:Maka 十周内 71 万行 TypeScript、35 万行测试、93.8% PR 合并率、33.5 分钟合并中位数;DSH 发布当天 288 个 dsh-plugin 仓库。使用这些素材时,应将"数据时间点"一并写入(如"截至 9 月 9 日"),因为两款产品的星标与版本数据均在快速变动。

### 6.3 表述陷阱与事实核查要点

写作时需特别注意以下表述陷阱。其一,关于 DSH 的界面形态:博客园(2026 年 8 月 20 日)称"目前只有网页版,没有 CLI",而 DataCamp(8 月 24 日)记录"本地 Web UI、无头 CLI、Python SDK"并存。由于产品迭代极快,宜采用"以 Web UI 为主入口,无头 CLI 与 Python SDK 在预览期内逐步补充"的稳妥表述,避免写成绝对判断。其二,关于 Maka 的平台支持:官方 README 的 Nightly 矩阵(macOS AS/Intel、Windows x64、Linux x64/arm64)与部分第三方评测的保守记录存在时间差,应以官方口径为主并注明"第三方评测记录的时间点更早"。其三,关于星标数字:不同媒体在不同时间采样得到的 DSH 星标数差异巨大(两天 9.5 万、四天 14.1 万、12 小时 5 万等),引用时必须注明采样时间或统一采用"截至本文阅读时"的表述。其四,关于横评归属:Terminal-Bench 2.1 九 Harness 数据虽公开透明,但由 Maka 项目方主导实施,写作时应表述为"Maka 项目方公开的、附逐题 CSV 与复现 PR 的横评数据",避免给读者"独立第三方测评"的错觉。其五,关于"史上最快"类表述:Wavect 明确提示该说法未获 GitHub 官方认证,建议弱化为"开源史上罕见的爆发速度"。其六,关于 v2ex 的实测数据(6000 万 token、97.5% 缓存命中、约 4 元成本、得分 0.8-0.9)为项目方自述,引用时需标注"项目方公开的早期实测"。

### 6.4 标题方向与读者分层策略

基于两款产品的素材特征,可考虑三类标题方向。数据冲击型标题可直接使用横评数据制造反差,例如"同一个 DeepSeek V4 Flash,换一个 Harness 差了 24 道题——这期我们推荐了相差 4.5 个百分点的这两位"。概念锚定型标题则可突出各自的核心主张,例如"一个把一切做成插件,一个把一切写成日志:2026 年最值得跟进的 Agent Harness 双雄"。观点引导型标题则适合深度读者,例如"厂商的安卓与基金会的账本:DeepSeek Harness 与 Apache Maka 的路线之争"。在读者分层上,建议将正文分为"五分钟速读版"(核心定位一句话、关键数据一表、适合人群一段)与"深度展开版"(架构原理、评测细节、风险清单),分别服务泛科技读者与开发者读者。适合人群的表述建议如下:DeepSeek Harness 推荐给重视开源与自定义、需要批量无人值守任务、想把多个 AI 工具统一编排进一个工作流、对成本敏感且能接受预览期波动的开发者与平台工程团队;Apache Maka 推荐给重视执行可审计性与数据主权、需要在本地运行 Agent、有合规要求或曾因会话崩溃丢失工作、愿意接受孵化期与源码构建门槛的用户。文章尾部应附上"生产环境慎入"的统一提示与各自官方仓库、文档链接,这既是专业性的体现,也符合两款产品官方对版本状态的自我定位。

## 七、结论与展望

本期推荐的两个项目共同印证了一个正在发生的行业判断:在模型能力趋同的时代,Harness 已成为智能体性能的决定性变量之一,而"用什么哲学构建 Harness"则是比"用哪个 Harness"更值得思考的问题。DeepSeek Harness 以 MIT 许可证、21.7 万星标与"一切皆插件"的彻底开放,展示了厂商驱动的开源生态所能达到的动员速度与扩展极限;Apache Maka 以 Apache 2.0 许可证、中立治理与"日志即运行时"的记录哲学,证明了基金会路线在 Agent 基础设施层的可行性与差异化价值。同一基准下的直接交锋——Maka 77.5% 对 DSH 73.0% 的通过率、几乎持平的每题成本——既说明了两者作为同代产品的技术水准接近,也提示着"Harness 之间的竞争"将长期处于动态拉锯之中。

展望未来,有三个值得持续追踪的方向:其一,DeepSeek Harness 何时发布首个稳定版本,将直接决定其能否从"现象级预览"走向"生产级平台",官方文档已明确当前版本"暂不建议将生产系统锁定于此";其二,Apache Maka 能否在孵化期内完成首个 ASF 正式发布并改善上手体验,将检验"记录哲学"是否具备产品化落地的能力,项目方已公开承认产品闭环是新手上手体验的短板;其三,两款产品所代表的"插件化"与"日志化"两条路线是否会融合——DSH 的追加式会话日志与 Maka 的 RuntimeEvent 已被第三方评价为"同属前沿方向",而 Harness 之间通过 Agent Client Protocol 互相驱动、甚至互为子代理的趋势,可能让"选择一方"最终变成"组合双方"。保持对这两个仓库版本页与官方公告的季度性回访,将是延续本文生命力的最低成本策略——因为这两个项目接下来的每一次发版,都可能成为新的选题本身。
