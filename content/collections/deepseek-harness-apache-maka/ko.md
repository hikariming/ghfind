이번 추천은 2026년 8월 AI 오픈소스 분야에서 가장 주목할 만한 두 개의 Agent Harness 프로젝트에 초점을 맞춥니다: DeepSeek AI가 공식 오픈소스로 공개한 DeepSeek Harness(약칭 dsh)와 Apache 소프트웨어 재단 인큐베이터에 새로 받아들여진 Apache Maka(Incubating)입니다. 둘은 서로를 복제한 것이 아니라, 완전히 다른 엔지니어링 철학으로 같은 시대적 질문에 답하고 있습니다 — 대규모 모델의 능력이 동질화되어 갈 때, 누가 에이전트(Agent)가 진짜로 "일하는 방식"을 정의할 것인가. DeepSeek Harness는 "모든 것이 플러그인"(Everything is a Plugin)을 기치로 모델, 도구, 세션, 샌드박스, 심지어 Agent 루프 자체까지 모두 플러그 가능한 컴포넌트로 만들었고, 오픈소스 공개 한 달도 안 돼 GitHub에서 21만 개 이상의 스타를 모으며 역사상 가장 빠르게 성장한 저장소 중 하나가 되었습니다. Apache Maka는 "로컬 우선"과 "로그가 곧 런타임"(The Log is the Runtime)이라는 두 깃발을 높이 들고, Agent의 모든 모델 메시지, 도구 호출, 권한 결정, 종료 이벤트를 추가 전용(append-only) RuntimeEvent 로그로 기록했으며, 동일 모델·동일 공식 검증기 아래에서 9개 Harness의 횡단 벤치마크를 공개해 77.5%의 통과율로 DeepSeek Harness의 73.0%를 제치고 2위를 차지했습니다. 이 두 프로젝트는 마침 매우 큰 긴장감을 가진 조합을 이룹니다: 하나는 벤더 주도·커뮤니티 폭발의 개방 생태계 노선을 대표하고, 다른 하나는 재단 거버넌스·데이터 중심의 중립 노선을 대표하며, 둘의 나란한 비교 자체가 Agent 인프라 경쟁을 이해하는 최고의 표본입니다.

## 1. 기획 배경: 왜 "Harness"가 2026년의 키워드가 되었는가

### 1.1 "모델 경쟁"에서 "프레임워크 경쟁"으로의 패러다임 전환

2026년 AI 기술 서사에서 하나의 뚜렷한 패러다임 전환이 이미 일어났습니다: 업계 논의의 중심이 "어떤 모델이 더 강한가"에서 "모델이 어떤 Harness 안에서 실행되는가"로 옮겨가고 있는 것입니다. 업계 통용 정의에 따르면 Agent Harness란 모델 바깥의 모든 코드, 설정, 실행 로직을 가리키며, 여기에는 모델을 지속적으로 호출하는 루프, 도구 목록, 샌드박스 환경, 메모리 메커니즘, 그리고 어떤 내용이 컨텍스트 윈도우에 들어갈지를 결정하는 규칙이 포함됩니다. Winder.AI 팀이 2026년 8월에 발표한 횡단 비교 종합 리뷰는 AI 기술 스택을 모델, Harness, 프레임워크, 플랫폼의 4계층으로 분해하며, "단일 에이전트를 실행하는" 중간 계층으로서의 Harness는 기능 목록보다 자신이 적합한 기술 스택 계층이 더 중요하다고 명확히 지적했습니다. 이 판단 뒤에는 탄탄한 실증적 뒷받침이 있습니다: Vercel은 에이전트 도구의 80%를 제거해 같은 모델의 성공률을 80%에서 100%로 높였고, LangChain은 Harness만 교체해 코딩 에이전트의 Terminal Bench 점수를 52.8%에서 66.5%로 끌어올렸으며, 프린스턴 대학의 CORE-Bench 테스트는 같은 모델이 서로 다른 스캐폴딩 아래에서 42%에서 78%까지 다른 점수를 기록함을 보여주었습니다. 모델의 기본 능력이 수렴하는 지금, Harness는 "껍데기 씌우기"에서 에이전트의 성패를 결정하는 핵심 인프라로 격상되었다고 말할 수 있습니다.

### 1.2 두 프로젝트의 "같은 날의 인연"과 역사적 위치

이번에 추천하는 두 프로젝트 사이에는 매우 뉴스 가치가 높은 우연이 있습니다: 2026년 8월 13일, DeepSeek AI가 자사 Harness를 오픈소스로 공개하는 동시에 V4 Pro 모델의 API 가격 인상안을 발표했고, Apache 소프트웨어 재단은 바로 같은 날 Maka를 인큐베이터에 정식으로 받아들였습니다. 이 날짜는 AI 오픈소스 역사에서 상징적인 의미를 갖습니다 — 벤더 주도의 오픈소스와 재단 거버넌스의 오픈소스가 같은 날 각각 중요한 수를 두었기 때문입니다. 제품 형태로 보면, DeepSeek Harness는 순수한 런타임 프레임워크로, 공식 포지셔닝은 "Agent = 모델 + Harness"라는 공식에서 후자이며, DeepSeek V4 시리즈 모델과 깊이 결합되어 여러 매체에서 Anthropic Claude Code에 대응하는 오픈소스 구축 가능 대안으로 해석됩니다. Apache Maka는 완성된 데스크톱 워크벤치 제품으로, 영문 포지셔닝은 "high-performance agent workspace that keeps a complete record of everything it did"(고성능 Agent 워크벤치, 자신이 한 모든 일을 완전하게 기록하는)이며, 저장소는 2026년 5월 27일에 생성되어 입후(인큐베이터 진입) 시점에 이미 약 10주간의 집중적인 개발 이력이 있었습니다. 하나는 "프레임워크"에 치우치고 다른 하나는 "제품"에 치우치며, 하나는 교체 가능성을 강조하고 다른 하나는 기록 가능성을 강조하여, 마침 Agent Harness 스펙트럼의 양 끝을 커버합니다 — 이것이 이 둘을 같은 회차의 추천에 담은 핵심 이유입니다.

## 2. DeepSeek Harness: 모든 것이 플러그인인 오픈소스 Agent 런타임

### 2.1 프로젝트 개요와 폭발적 인기

DeepSeek Harness는 DeepSeek AI가 공식 개발했으며 MIT 라이선스로 오픈소스화되었고, 명령줄 진입점은 dsh입니다. 공식 프로젝트 홈페이지는 핵심 주장을 한 문장으로 요약합니다 — 모든 것이 플러그인: 모델, 도구, 스킬, 세션, 샌드박스, 스토리지, 루프, 스케줄링, 그리고 사용자 인터페이스까지, 모든 능력이 교체되거나 재조합될 수 있습니다. 공식 문서에 따르면 DeepSeek의 모델 벤치마크 테스트는 Harness의 미니멀 모드를 프레임워크로 사용하며, DeepSeek 시리즈 모델의 Code Agent 텍스트 작업 테스트는 모두 max 등급과 temperature=1.0의 파라미터 조합을 채택합니다. 이 프로젝트의 인기 궤적은 오픈소스 역사에서 극히 드뭅니다: 보커위안(博客园)의 한 실측 기사는 오픈소스 공개 당일 밤 12시간 만에 5만 스타를 돌파했고, 공개 당일 dsh-plugin 태그가 달린 서드파티 플러그인 저장소가 288개나 생겨났다고 기록했습니다; Medium 플랫폼의 보도는 나흘 만에 141,000개의 스타를 얻었다고 전했고, Winder.AI의 종합 리뷰는 이틀 만에 95,386개의 스타를 얻었다고 기록했습니다. 다만 서로 다른 매체가 서로 다른 시점에 샘플링한 숫자의 차이가 크고, Wavect는 "GitHub 역사상 가장 빠른 성장"이라는 주장이 GitHub 공식 인증을 받지 않았다고 특별히 주의를 환기했으므로, 인용 시에는 공식 저장소의 실시간 데이터를 기준으로 하되 샘플링 시간을 명시해야 합니다.

### 2.2 핵심 아키텍처: Cordis 커널과 플러그인화 런타임

DeepSeek Harness를 이해하는 열쇠는 그 밑바닥의 Cordis 메타 프레임워크에 있습니다. 공식 프리뷰 페이지는 Cordis를 플러그인의 마운트, 언마운트, 의존 관계를 관리하는 "커널"로 묘사하며, 에이전트의 모든 능력은 플러그인 형태로 존재하고, Cordis의 서비스와 이벤트 메커니즘이 플러그인 간 협업을 가능하게 하며, 개발자는 설정만으로 어떤 능력이든 선택·교체·확장할 수 있어 프레임워크 소스 코드를 수정할 필요가 없다고 설명합니다. Eigent AI의 중국어 해설은 플러그인화의 경계를 더 명확히 했습니다: 도구와 스킬만 플러그인인 것이 아니라, 모델 어댑터 자체, 세션과 실행 상태, 샌드박스 환경, 스토리지 위치, 루프와 스케줄링 로직, 심지어 UI 인터페이스 자체까지 모두 플러그인입니다. 이 아키텍처의 직접적인 귀결은 "패치가 필요한 특권 커널이 존재하지 않는다"는 것입니다 — 공식 문서는 dsh를 확장하는 방식이 플러그인을 다른 플러그인 옆에 마운트하는 것이지, 폐쇄된 코어를 중심으로 주변부 확장을 하는 것이 아니라고 명확히 밝힙니다. DataCamp의 비교 기사는 엔지니어링 관점에서 이 설계를 확인해 줍니다: Cordis는 플러그인이 서비스를 발견하고 이벤트를 교환하게 하고, 의존 변경은 플러그인을 로드하거나 언로드하며, 핫 리로드는 만료된 리스너와 백그라운드 작업을 정리하고, 기본 profile은 루프를 설정으로 드러내 보여줍니다. Claude Code와의 비교가 차이를 가장 잘 부각합니다: 후자는 고정된 내장 루프를 중심으로 skills, hooks, MCP 등 주변 확장 메커니즘을 제공하는 반면, Harness의 플러그인은 런타임 자체의 구성 요소를 직접 정의할 수 있습니다. 즉 "DeepSeek Harness는 Claude를 담을 수 있지만, Claude Code는 DeepSeek를 담을 수 없다"입니다.

### 2.3 네 가지 실행 모드와 Agent 프리셋 체계

DeepSeek Harness에는 공식적으로 설계된 네 가지 실행 모드가 내장되어 있으며, 본질적으로 같은 플러그인 라이브러리의 서로 다른 조합 프리셋입니다. 표준 모드는 기능이 완전한 코딩 Agent로, 파일 편집, Shell, 파일 및 웹 검색, 스킬(Skills), 계획 모드, 목표 추적, 서브 에이전트, 워크플로 등 모든 능력을 망라합니다. 코드 모드(PTC 모드)는 표준 모드에 더해 Code Mode SDK를 추가로 제공하여, 모델이 여러 번의 독립적인 도구 호출 대신 TypeScript 프로그램을 작성해 다단계 작업을 조합할 수 있게 하며, 배치 작업 시나리오에 적합합니다. 미니멀 모드는 영속 bash와 str_replace_editor 두 개의 도구만 남긴 것으로, 공식이 벤치마크 테스트와 최소 재현에 사용하는 깨끗한 환경이며, 공식 문서는 DeepSeek 시리즈 모델의 공개 벤치마크가 모두 이 모드를 사용한다고 확인합니다. 크리에이터 모드는 "Agent로 Agent를 만드는" 고급 시나리오를 겨냥하며, 표준 모드의 모든 능력 위에 런타임 검사, 플러그인 실험, 프리셋 창작 가이드를 추가하여, 사용자가 현재 런타임을 검사하고 메모리에서 Cordis 플러그인을 테스트한 뒤 이를 새로운 모드로 조합할 수 있습니다. 네 모드의 점진 관계는 분명합니다: 표준 모드는 일을 하고, 코드 모드는 오케스트레이션하고, 미니멀 모드는 평가하고, 크리에이터 모드는 진화합니다 — 이 체계화된 프리셋 설계 자체가 자세히 다룰 가치가 있는 제품 하이라이트입니다.

### 2.4 관측 가능성 설계: 궤적 뷰와 추가식 세션 로그

DeepSeek Harness의 관측 가능성에 대한 투자는 "추적 가능성"에 대한 높은 중시를 보여줍니다. 공식 프리뷰 페이지는 "모든 실행이 추적 가능하다"고 명확히 약속합니다: 모델이 받은 모든 내용이 추가 전용 세션 로그에 기록되며, 여기에는 시스템 프롬프트, 추론 과정, 도구 호출과 결과, 서브 에이전트 스케줄링, 그리고 모든 컨텍스트 주입이 포함되고, 궤적 뷰(Trajectory view)를 통해 사용자는 출처별로 이 기록들을 볼 수 있으며, 복구, 포크, 검색, 리플레이 작업은 모두 같은 이벤트 스트림을 기반으로 합니다. 36Kr가 라이선스를 받아 전재한 큐비트AI 체험 기사는 이 기능의 실제 가치를 상세히 묘사했습니다: Agent가 오래 실행될수록, 도구 체인이 복잡해질수록 채팅 요약은 점점 블랙박스가 되는데, 궤적 기능은 언제든 Agent를 모니터링할 수 있는 리플레이 창을 제공하여 원시 이벤트 수준의 기록을 직접 보고, 모델이 어느 단계에서 넘어졌는지, 각 단계에서 얼마의 비용이 들었는지를 직관적으로 파악할 수 있습니다. DataCamp의 평가는 "모델이 본 것은 곧 기록된다"(Model-visible means logged)이며, UI에 표시되는 실행 경로의 세부 사항이 Claude Code의 JSONL 기록보다 더 풍부하다고 지적했습니다. 주목할 점은, 이 "추가식 로그" 설계가 Apache Maka의 RuntimeEvent 로그와 사고방식 면에서 같은 최전선 방향에 속한다는 것입니다. aiguide.cc의 비교 기사는 둘을 "기록이 곧 진실" 노선의 대표로 나란히 놓았습니다 — 두 제품은 서로 다른 출발점에서 시작해 최종적으로 "로그를 유일한 사실의 원천으로 삼는다"는 원칙에서 만났습니다.

### 2.5 플러그인 생태계와 커뮤니티 조직 방식

DeepSeek Harness의 생태계 구축 전략은 선명한 "운영체제화" 특징을 보입니다. 큐비트AI의 체험 기사는 이를 "Agent 시대의 안드로이드"에 비유했습니다: 공식이 이미 100개 이상의 플러그인을 내장했고, 커뮤니티는 《마인크래프트》에 모드를 설치하듯 서드파티 플러그인을 설치할 수 있으며, 심지어 저장소 문서에는 처음부터 플러그인을 구축해 공식 Harness에 연결하는 전 과정의 튜토리얼이 포함되어 있고, Cordis를 개조하는 Skill도 내장되어 있습니다. 공식 프리뷰 페이지는 커뮤니티 플러그인 인덱스 입구(GitHub의 dsh-plugin 토픽 태그)를 제공하고 Harness 개발자들이 DSH 플러그인 생태계에 참여하는 것을 환영하며, GitHub Discussions와 Discord로 커뮤니티 협업을 지원합니다. 보커위안(博客园)의 실측은 또 하나의 핵심 능력을 드러냈습니다: Harness에는 Claude Code와 Codex를 서브 Agent로 호출하는 Provider가 내장되어, PATH에서 해당 바이너리를 파싱해 위임 실행을 구현합니다. 이는 사용자가 Harness를 상위 오케스트레이션으로 쓰면서 경쟁 도구를 대체하는 대신 자신의 워크플로에 편입할 수 있다는 뜻입니다. Winder.AI의 종합 리뷰도 이 점을 확인하며, Zed Agent, OpenHands, DeepSeek Harness가 모두 Agent Client Protocol을 지원해 서로를 구동할 수 있다고 지적했습니다 — Harness 간 상호운용성이 업계 트렌드가 되어 가고 있습니다.

### 2.6 시작 방법과 개발자 경험

DeepSeek Harness의 시작 장벽은 "5분 시작, 깊이 들어가려면 학습 필요"로 요약할 수 있습니다. 공식이 제공하는 가장 빠른 시작 방법은 Node.js가 설치된 환경에서 `npx @deepseek-ai/dsh web`을 실행하는 것으로, 기본적으로 http://127.0.0.1:3080에서 Web UI를 시작하고 브라우저를 자동으로 열며, SSH로 시작할 때는 로컬 포워딩을 위해 호스트 주소만 출력합니다. 소스에서 실행하려면 저장소를 클론한 뒤 `pnpm install`, `pnpm run build`, `pnpm dsh web`을 차례로 실행하면 됩니다. 첫 사용에는 사용자가 직접 모델 API Key를 설정해야 합니다 — 공식 프리뷰 페이지와 36Kr 체험 기사 모두 Harness가 공유 모델 계정을 내장하지 않으며, 사용자가 DeepSeek 오픈 플랫폼이나 다른 공급업체의 모델을 연결할 수 있다고 확인합니다. 보커위안(博客园) 실측은 현재 인터랙션 인터페이스가 웹 버전 위주라 터미널에 익숙한 개발자에게 충분히 친화적이지 않다고 지적했지만, Headless 모드와 공식 Python SDK가 프로그래매틱 배치 실행을 지원해 파일별·모듈별 무인 작업을 수행할 수 있으며, 이 능력은 대량 코드 마이그레이션 같은 시나리오에서 인터랙티브 도구보다 뚜렷이 우수하다고 평가했습니다. DataCamp의 비교표는 사용 인터페이스로 로컬 Web UI, 헤드리스 CLI, Python SDK를 기록했습니다. 두 리뷰의 CLI 상태 묘사에는 시점 차이가 있습니다(보커위안 기사는 2026년 8월 20일, DataCamp 기사는 8월 24일 발행). 안전한 표현은 "초기 버전은 Web UI 위주였고, 반복 개선 과정에서 헤드리스 CLI와 Python SDK를 점차 보강했다"이며, 이 제품의 이터레이션 속도가 매우 빨라 기능 매트릭스가 언제든 바뀔 수 있음을 독자에게 상기시켜야 합니다.

## 3. Apache Maka: 모든 것을 기록하는 로컬 우선 Agent 워크벤치

### 3.1 프로젝트 개요와 Apache 인큐베이션의 길

Apache Maka는 Apache 소프트웨어 재단 인큐베이터가 받아들인 최초의 Agent Harness 중심 포지셔닝 프로젝트입니다. 인큐베이터 공식 페이지는 이를 "모델 메시지, 도구 호출, 도구 결과, 권한 결정, 종료 이벤트를 추가 전용 로그에 기록하는 로컬 우선 AI 에이전트 런타임이자 워크스페이스"로 묘사합니다. 프로젝트는 Apache Incubator PMC가 주관하고, Champion은 tison(Zili Chen)이며, 4명의 멘토(Mentors)가 배정되었고, 커미터 명단에는 Kun Li, Jie Wen, Yuhan Lei 등 7명이 포함되어 있습니다. 프로젝트 저장소는 2026년 5월 27일에 생성되었고, 7월 14일 프로젝트 측이 v2ex 커뮤니티에 공유 글을 올렸을 때는 666개의 스타와 70개의 포크에 불과했으며, 8월 13일 인큐베이터 진입 후 관심이 빠르게 상승했습니다 — aiguide.cc는 8월 24일 무렵 약 2,381개의 스타를 기록했고, agentconn.com은 8월 26일에 3.6천 개의 스타를 기록했으며, 이 글을 쓰는 시점(2026년 9월 9일) 공식 저장소는 이미 5.1천 개의 스타, 476개의 포크, 4507회의 커밋을 보여주고 있습니다. 이 성장 곡선은 DeepSeek Harness의 폭발적 궤적에는 크게 못 미치지만, 2026년 8월 23일 GitHub Trending 1위 등극, 8월 24일 TypeScript 카테고리 당일 저장소 스타 획득이라는 성과와 맞물려 "Apache 생태계에서 가장 주목받는 신규 AI 프로젝트 중 하나"라는 추천 포지셔닝을 뒷받침하기에 충분합니다.

### 3.2 핵심 이념: 로그가 곧 런타임(The Log is the Runtime)

Maka의 제품 철학은 공식 사이트에서 반복적으로 등장하는 하나의 공식에 응축되어 있습니다: State(t) = Project(Log[0…t]), 즉 임의 시점의 시스템 상태는 모두 순서 있는 로그를 프로젝션한 결과라는 것입니다. 공식 README는 이를 "로그가 곧 런타임" 원칙으로 구체화합니다: 모든 모델 메시지, 도구 호출, 권한 결정, 종료 이벤트는 하나의 추가 전용 RuntimeEvent이며, 인터페이스, 다음 라운드의 prompt, 크래시 복구는 모두 이 로그의 프로젝션이지 결코 유일한 사본이 아닙니다; 오래된 도구 출력은 다음 라운드의 prompt에서 빠질 수 있지만 로그에서는 빠지지 않습니다. CSDN의 기술 분석 기사는 분산 시스템 관점에서 이 설계의 사상적 기원을 설명했습니다: 이는 log-first 사상이 Agent 분야에 착지한 것으로, 먼저 순서 있고 모호하지 않은 변화의 사실을 저장한 뒤 소비자가 자신의 상태를 재구축하게 함으로써, "어떤 이벤트 경계 이전에 모델이 무엇을 보았는지, 어떤 도구를 호출했는지, 어떤 권한이 요청되거나 결정되었는지" 같은 핵심 질문에 신뢰성 있게 답할 수 있습니다. 이 설계의 실제 가치는 v2ex의 프로젝트 측 공유 글에서 더 소박하게 표현됩니다: 시중에 AI Desktop은 이미 많지만, Maka가 해결하려는 것은 "채팅 인터페이스가 예쁜가"가 아니라 "Agent의 실행 과정을 일급 시민으로 보존할 것인가"이며, 프로젝트 슬로건은 "Maka preserves experience as evidence"(Maka는 경험을 증거로 보존한다)입니다. "로그가 곧 런타임"은 기술적 깊이가 있으면서도 설명하기 쉬운 서사의 지지점입니다 — "감사 가능, 복구 가능, 재현 가능"이라는 세 가지 추상적 셀링 포인트를 하나의 가시화 가능한 원리 아래로 통일했기 때문입니다.

### 3.3 통합 Runtime Host와 3개 진입점 아키텍처

Maka 아키텍처 설계에서 추천할 만한 또 다른 하이라이트는 "단일 런타임 호스트"(One Runtime Host) 원칙입니다. 공식 README는 명확히 밝힙니다: Desktop, TUI와 CLI, Eval은 모두 얇은 클라이언트이며, 실행은 오직 이 하나의 Runtime Host가 결정하고, Eval은 실험과 점수만 소유합니다. 이는 데스크톱의 그래픽 인터페이스, 터미널의 TUI/CLI, 평가 프레임워크가 완전히 동일한 실행 경로를 공유하며, 평가 결과가 프로덕션 시나리오로 매끄럽게 이전될 수 있음을 의미합니다. 이 설계는 "평가 환경과 프로덕션 환경의 불일치"라는 고전적인 엔지니어링 함정을 제거합니다. aiguide.cc의 리뷰는 이를 혁신 포인트로 꼽았습니다: 데스크톱, CLI, Eval이 하나의 런타임을 공유하고, 평가 결과가 재현 가능하며, 실험과 프로덕션이 같은 실행 경로라는 것입니다. 진입점 차원에서, 데스크톱은 Electron과 React로 구축된 로컬 애플리케이션으로 스트리밍 세션, 도구 타임라인, 브랜치와 복구 등의 기능을 제공하고; 터미널 진입점은 `npm run cli`로 TUI를 시작하거나 단일 Turn을 실행할 수 있으며; Eval 진입점은 선언적 다중 암 실험(task × repetition × subject)을 지원하고 점수, 사용량, 비용, 소요 시간 등의 결과 커널을 출력합니다. 또한 Maka는 Read, Write, Edit, Bash, Glob, Grep 여섯 개의 기본 도구를 내장하고, 제공업체에 무관한 Model Context Protocol 클라이언트 통합을 제공하며, MCP 도구는 자동으로 기존 권한 제어, 런타임 이벤트 로그, 텔레메트리 능력을 얻습니다. 이 "워크벤치 + 평가 프레임워크"의 완전한 제품 형태는 Maka가 "순수 프레임워크"와 "순수 채팅 도구" 사이에서 차별화된 위치를 찾게 해줍니다.

### 3.4 데이터로 말하기: Terminal-Bench 2.1 9개 Harness 횡단 평가

Maka의 가장 날카로운 소재는 공개된 횡단 평가 데이터입니다. 프로젝트 공식 사이트 첫 페이지의 핵심 홍보 문구는 "Measured, not claimed"(측정으로, 주장으로가 아니라)이며, 두 세트의 테스트 결과를 공개적으로 전시하고 있습니다. 첫 번째 세트는 DeepSeek V4 Flash에서 Terminal-Bench 2.1의 전체 89개 과제를 완주하고 공식 검증기로 통일 채점한 9개 Harness 비교입니다: Codex가 82.0%의 통과율로 1위, Maka가 77.5%로 2위, Pi가 74.2%, DeepSeek Harness(미니멀 모드)가 73.0%, ZCode가 70.8%, Reasonix가 67.4%, OpenCode가 65.2%, Kimi Code가 59.6%, Claude Code가 55.1%로 최하위를 기록했습니다. 두 번째 세트는 Maka와 OpenCode의 페어링 단일 실행 비교로, McNemar 검정으로 차이가 유의함을 확인했고(p = 0.0118), Maka가 68.5% 대 55.1%로 13.5%포인트 앞섰으며, 통과 과제당 비용은 기본적으로 동일했습니다. 지후 기사의 이 데이터에 대한 해석은 매우 전파력이 강합니다: 같은 모델, 같은 reasoning max 등급에서 1위와 최하위가 26.9%포인트, 정확히 24개 과제 차이가 났고; 89개 과제 중 단 28개만 9개 Harness가 모두 통과했고 5개는 모두 틀렸으며, 나머지 56개(약 63%)가 Harness에 따라 다른 결과를 보였습니다. 이 글은 나아가 Harness가 모델 능력 이외에 가장 중요하면서도 가장 간과되기 쉬운 인프라 계층이 되어 가고 있으며, Maka가 Apache를 선택한 것은 바로 이 계층을 개방적이고 중립적이며 장기적으로 존재하는 커뮤니티 거버넌스에 맡기기 위해서라고 지적했습니다. 정직하게 명시해야 할 점은: 이 횡단 평가는 Maka 프로젝트 측이 주도해 실시했고, 테스트 보고서, 과제별 결과, 실험 조건이 모두 공개되어 재현 PR도 첨부되었지만, 독립적인 제3자가 아직 전면적으로 재현하지는 않았으므로 인용 시 "프로젝트 측 공개 데이터"라는 속성을 밝혀야 한다는 것입니다.

### 3.5 보안, 권한, 로컬 우선의 프라이버시 설계

Maka의 세 번째 핵심 셀링 포인트는 로컬 데이터 주권을 중심으로 구축된 보안 설계입니다. 공식 README는 "데이터는 당신의 머신에, 모델은 당신이 연결한다"고 약속합니다: 세션, 설정, 실행 기록은 로컬 머신에 저장되고, 사용자가 모델을 직접 가져옵니다 — 클라우드 API, 로컬 모델, 호환 게이트웨이 모두 가능합니다. 워크스페이스 데이터는 기본적으로 Electron userData 디렉터리에 저장되며, runtime.sqlite, 연결 디렉터리, 자격 증명 볼트, 설정 파일이 포함됩니다; API 키 같은 비밀은 시스템 계정만 읽을 수 있는 로컬 파일 credential-vault.json에 저장되어 렌더러 프로세스(인터페이스 프로세스)는 평문을 얻을 수 없습니다. 도구 실행 차원에서, 파일을 쓰거나 Shell을 실행하는 도구는 반드시 샌드박스 경계를 통과해야 하고, 경계를 넘는 작업은 권한 승인을 요청해야 하며, 실행은 중단 가능하고 실패는 분류됩니다. CSDN의 아키텍처 분석은 더 세밀한 보안 조치를 보충했습니다: stdio는 기본적으로 실행에 필요한 환경 변수 화이트리스트만 상속하고, 모든 MCP 도구는 mutation으로 처리되어 명시적 승인이 필요하며, 메인 프로세스는 IPC 페이로드에 런타임 검증을 수행하고, 설정 파일에는 0600/0700의 엄격한 파일 권한을 적용하며, 모델 텍스트, 이미지 수, 총 크기에 대해 집계 경계 검사를 합니다. agentconn.com의 리뷰는 특히 Maka의 추가식 로그가 크래시 복구와 중단된 작업 복구를 자연스럽게 지원해 "에이전트 세션 크래시로 작업을 잃은 적이 있는" 사용자에게 매우 매력적이라고 지적했지만, 로컬 우선 아키텍처는 내장된 크로스 디바이스 동기화 기능이 없음을 의미한다고도 했습니다. 이 일련의 특성은 Maka를 프라이버시 민감 시나리오(예: 기업 내부 민감 코드베이스, 컴플라이언스 감사 요구)에서 추천할 첫 번째 선택지로 만들며, DeepSeek Harness의 클라우드 모델 노선과 뚜렷한 사용 시나리오 분화를 이룹니다.

### 3.6 커뮤니티 협업의 밀도와 속도

DeepSeek Harness의 커뮤니티 강점이 규모에 있다면, Maka의 커뮤니티 강점은 밀도에 있습니다. 지후 기사가 인용한 프로젝트 측 통계에 따르면, 5월 27일 저장소 생성 후 약 10주 동안 Maka는 약 71만 줄의 TypeScript(그중 약 35만 줄은 테스트), 949개의 테스트 파일, 2,439회의 커밋, 1,218개의 머지된 PR, 93.8%의 PR 머지율을 축적했고, PR 머지 시간 중앙값은 약 33.5분이며, 7월 한 달에만 943개의 PR을 머지했습니다. v2ex의 공유 글은 또 다른 초기 데이터를 보충합니다: 9일 동안 300개의 커밋(111개 fix, 103개 feat), 일평균 33개 커밋, 핵심 기여자 2~3명. 특히 주목할 점은 커뮤니티의 자기 조직화 능력입니다: 공개 이틀 전 한 커뮤니티 사용자가 models.dev 전체 provider 지원 정렬을 요구하며 담당을 자청했고, 이틀 만에 커뮤니티가 잇달아 20개 이상의 provider 지원을 제출해 Cloudflare Workers AI, Hugging Face, Vercel AI Gateway, Cohere, Mistral, xAI, Together AI와 Volcano Ark(火山方舟), Tencent, StepFun 등 국내외 서비스를 커버했습니다. 이런 고빈도 협업과 빠른 검증의 builder 커뮤니티 기질은 Apache 인큐베이터에서 상당히 드문 "신종"입니다. 물론 다른 한 면도 정직하게 보여야 합니다: 프로젝트 측은 v2ex 글에서 "Runtime 설계의 선진성이 제품 완결성과 초보자 온보딩 경험을 앞질러, 처음 접하는 개발자가 5분 안에 시작을 완료하고 한 번의 Agent Run의 전체 흐름을 명확히 보기 어렵다"고 인정했고, 이것이 향후 우선 최적화 방향이라고 밝혔습니다.

## 4. 횡단 비교: 같은 벤치마크와 같은 좌표계 아래에서의 두 제품의 성과

### 4.1 포지셔닝과 설계 철학의 차이

두 제품의 가장 본질적인 차이는 "Harness는 무엇이어야 하는가"에 대한 답에 있습니다. DeepSeek Harness의 철학은 "교체 가능성 우선"입니다: 공식 프리뷰 페이지는 "모든 것이 플러그인"을 설계 이념 첫 번째 항목으로 꼽으며, 개발자가 설정만으로 어떤 능력이든 선택·교체·확장할 수 있음을 강조합니다. 그 은유는 운영체제 또는 블록 베이스판입니다 — Eigent AI는 이를 "언어 모델을 감싸는 런타임 계층"으로 포지셔닝했고, 큐비트AI는 직접 "Agent 시대의 안드로이드"라고 불렀습니다. Maka의 철학은 "기록 가능성 우선"입니다: 공식 README의 네 가지 핵심 특징이 모두 측정과 기록을 중심으로 전개됩니다 — 측정으로, 주장으로가 아니라; 로그가 곧 런타임; 데이터는 당신의 머신에; 하나의 Runtime Host. 그 은유는 장부 또는 블랙박스입니다 — Agent의 모든 "행위 거래"를 변조 불가능한 방식으로 디스크에 기록하는 것입니다. aiguide.cc의 비교표는 이 분기점을 한 문장으로 정확히 요약했습니다: Maka는 "로컬 우선 Agent 워크스페이스(기록이 곧 진실)", DeepSeek Harness는 "모든 것이 플러그인인 Agent 실행 프레임워크". 이 철학적 차이를 이해하면 두 제품의 다른 차원에서의 성과 차이에 통일된 설명 프레임이 생깁니다: DSH는 교체 가능성을 위해 안정성 약속을 희생했고(개발자 프리뷰, 파괴적 변경 경고), Maka는 기록 가능성을 위해 생태계 규모를 희생했습니다(인큐베이션 기간, 정식 릴리스 없음).

### 4.2 성능과 비용의 같은 벤치마크 직접 대결

두 제품의 같은 벤치마크 아래에서의 직접 비교 데이터가 가장 설득력 있는 소재입니다. Terminal-Bench 2.1의 9개 Harness 횡단 평가에서 Maka는 77.5%의 통과율로 DeepSeek Harness(미니멀 모드)의 73.0%를 약 4.5%포인트 앞섰습니다. 비용 차원에서 둘의 격차는 거의 무시할 수 있는 수준입니다: Maka는 통과 과제당 약 0.0263달러, DSH는 약 0.0262달러인 반면, 최하위인 Claude Code는 0.0537달러로 둘의 두 배 이상이었고; 전체 그룹에서 비용이 가장 낮은 것은 0.0197달러인 Pi였습니다. 지후 기사는 이를 바탕으로 "통과율-비용" 2차원 차트를 그려 Codex, Maka, Pi가 파레토 프런티어를 이루며, Maka가 DSH에 가까운 비용으로 2위의 통과율을 달성한 것이 바로 "성능과 경제성 사이의 균형"의 대표라고 지적했습니다. 보커위안(博客园) 실측 기사가 인용한 제3자 30개 과제 횡단 평가는 다른 각도에서 Harness 노선의 비용 우위를 뒷받침합니다: Pi Agent는 성공 과제당 비용이 약 0.028달러, Claude Code는 0.195달러로 거의 7배 차이가 났습니다. 독자에게 정직하게 명시해야 할 점은: 이 비교에서 DSH는 표준 모드가 아닌 미니멀 모드를 사용했고, 테스트는 Maka 프로젝트 측이 주도해 보고서와 과제별 CSV를 공개했지만 독립 재현은 아직 진행되어야 한다는 것입니다. 또한 DSH와 Maka 사이의 이 4.5%포인트 차이가 안정적인지는 단일 실행에서 모델 샘플링 무작위성의 간섭이 있지만, 89개 과제 중 56개(63%)가 Harness에 따라 결과가 바뀐다는 구조적 현상은 "Harness를 선택하는 것 자체가 하나의 성능 결정"이라는 핵심 논점을 뒷받침하기에 충분합니다.

### 4.3 라이선스, 거버넌스, 생태계 구조의 대조

라이선스와 거버넌스 차원에서 보면, 두 제품은 완전히 다르지만 각자 자기완결적인 길을 선택했습니다. DeepSeek Harness는 MIT 라이선스를 채택했으며, 이는 가장 관대한 오픈소스 라이선스 중 하나로 누구든 코드를 사용·수정하고 그 위에 상용 제품을 구축할 수 있습니다. 거버넌스는 DeepSeek 단일 벤더가 주도하고, 커뮤니티는 GitHub Discussions, Discord, dsh-plugin 토픽 태그로 참여하며, 공식은 "핵심 플러그인과 API가 지속적으로 진화할 것"이라고 명시했습니다. Maka는 Apache License 2.0을 채택하고 Apache 소프트웨어 재단이 중립적 거버넌스를 제공합니다: 의사결정은 공개적으로 이루어지고, 커뮤니티가 공동으로 거버넌스하며, 지식재산권은 인큐베이터 프로세스 심사를 거칩니다. 인큐베이터 페이지는 이 프로젝트가 인큐베이션에 들어온 지 약 한 달에 불과하며 저작권 확인, 배포 권리 검증, 커미터 협약 등 대량의 절차적 작업을 완료해야 하고, 인큐베이션 상태가 "해당 프로젝트가 아직 ASF의 완전한 인정을 받지 않았음을 나타낸다"고 보여줍니다. 생태계 구조상, DSH는 이미 플러그인 마켓의 초기 형태를 갖췄습니다 — 공개 당일 288개의 dsh-plugin 저장소, 공식 내장 100개 이상의 플러그인; Maka의 생태계는 models.dev의 provider 연결과 커뮤니티 협업 기여 위주로, 이틀 만의 20개 이상의 provider 지원이 대표적 성과입니다. 이것은 전형적인 "벤더 속도 vs 재단 신용"의 대조입니다: 전자는 빠르지만 변할 수 있고, 후자는 느리지만 예측 가능합니다. Apache 인큐베이션의 브랜드 보증이 Maka에 가져다준 "장기 신뢰성"은 aiguide.cc가 첫 번째 장점으로 꼽은 것이고, Winder.AI의 DSH 평가는 "이터레이션 속도가 극히 빠르고 현재 모든 기능이 불안정하다"는 것이 바로 개발자 프리뷰 기간의 실제 상태임을 상기시켜 줍니다.

### 4.4 성숙도, 버전 상태, 리스크 노출

두 제품의 성숙도는 모두 초기 단계이지만 리스크의 성질이 다릅니다. DeepSeek Harness는 명확히 개발자 프리뷰 단계에 있으며, 공식 README는 "호환성 파괴 변경의 가능성이 있다"고 주의하고 실행 전에 보안 공지를 확인해야 한다고 합니다; Wavect의 엔터프라이즈급 평가 결론은 "범위가 통제된 엔지니어링 파일럿에는 매우 적합하지만, 아직 인기만으로 바로 채택할 수 있는 프로덕션 컨트롤 플레인은 아니다"입니다. Maka 역시 "아직 Apache 정식 버전을 릴리스한 적이 없으며", 공식은 main 브랜치에서 매일 빌드하는 Desktop Nightly(Windows와 Linux 빌드는 서명되지 않은 프리뷰)와 소스 빌드 두 가지 경로만 제공하고, README는 Nightly가 "ASF release가 아니며 프로덕션 사용에 적합하지 않다"고 명확히 합니다. 버전 측면에서, SourceForge 미러 디렉터리에는 v0.2.0-dev.15.20260902 개발 빌드가 존재하며, GitHub Releases의 v0.1.11(2026년 8월 18일)은 ASF 릴리스 프로세스를 거치지 않았습니다. 정직한 리스크 안내가 반드시 필요합니다: 두 제품 모두 "안정을 추구하는" 프로덕션 환경 사용자에게 추천되어서는 안 되며, 이들의 추천 가치는 기술 탐구, 학습, 파일럿 시나리오에 있습니다.

### 4.5 플랫폼 지원, 사용 장벽, 시작 경로

플랫폼 지원과 시작 장벽에서 두 제품의 현황은 각각 장단점이 있습니다. DeepSeek Harness는 순수 Node.js 프로젝트로, npx 한 줄 명령이면 Node.js가 설치된 어떤 플랫폼에서도 Web UI를 시작할 수 있어 플랫폼 종속이 없습니다; 샌드박스는 Linux에서 bubblewrap 또는 Landlock, macOS에서 Seatbelt, Windows에서 ACL 제한 토큰을 사용하며, 권한 프리셋은 read-only, workspace-write, danger-full-access를 포함합니다. Maka의 데스크톱은 Electron 기반이며, 공식 Nightly는 macOS(Apple Silicon과 Intel), Windows x64, Linux x64와 arm64를 커버하지만 Windows와 Linux 빌드는 서명되지 않은 프리뷰입니다; 일부 제3자 리뷰(aiguide.cc, agentconn.com)는 더 보수적인 플랫폼 현황을 기록했습니다 — macOS Apple Silicon만 주요 지원 플랫폼이고 Linux는 아직 정식 지원되지 않는다는 것으로, 공식 README와 시점 차이가 있으므로 안전한 표현은 "공식 Nightly는 이미 3대 플랫폼을 커버하지만 Windows/Linux는 서명되지 않은 프리뷰이며, 제3자 리뷰가 더 이른 시점에 기록한 가용성은 더 제한적이었다"입니다. 사용 장벽 측면에서, DSH는 한 줄 명령으로 시작할 수 있지만 깊이 있는 사용에는 Cordis 플러그인 메커니즘, Profile, 조합 패키지 개념의 이해가 필요합니다; Maka의 첫 실행은 모델 연결을 직접 설정해야 하고(설정에 들어가 API, 로컬 모델 또는 이미 연결된 계정 연결을 추가하고 테스트), 빌드 환경은 Node.js 22.19 이상, npm, Git, ripgrep을 요구하며, 개발 Peer 모드는 Rust 1.98 이상도 필요합니다. 프로젝트 측 스스로 Maka의 "초보자 온보딩 경험"이 약점이라고 인정했고, DSH의 "설정 학습 비용" 역시 리뷰어들이 반복적으로 언급하는 불만 포인트입니다 — 두 제품은 "초기 도구의 고질병"에서 뜻밖에 의견 일치를 이뤘습니다.

### 4.6 비교 총람표

다음 표는 두 제품의 본문에서 다룬 각 차원의 핵심 차이를 집계한 것입니다(데이터는 2026년 9월 9일 열람 시 스냅샷):

## 5. 장단점 심층 분석: 평가 증거에서 추천 결론까지

### 5.1 DeepSeek Harness의 장점

DeepSeek Harness의 첫 번째 장점은 **아키텍처 개방도가 동류 제품 중 최고**라는 점입니다. 공식은 모델, 도구, 스킬, 세션, 샌드박스, 스토리지, 루프, 스케줄링, 심지어 UI까지 모두 교체 가능한 플러그인으로 정의했으며, 이런 철저함은 팀이 기존 제품 주변부에 패치를 하는 것이 아니라 완전히 커스터마이즈된 Agent 런타임을 조립할 수 있음을 의미합니다. 보커위안(博客园) 실측에서 "Claude Code와 Codex를 서브 Agent로 호출"하는 능력은 이 아키텍처의 실제 위력을 증명합니다 — 사용자는 기존 도구에 대한 투자를 유지하면서 Harness로 상위 오케스트레이션을 할 수 있습니다. 두 번째 장점은 **비용 구조**입니다: 같은 모델에서 DSH의 통과 과제당 비용은 약 0.0262달러로 Claude Code의 절반에 못 미치며, 36Kr 체험 기사가 기록한 99% 안팎의 캐시 적중률(간헐적으로 60-70% 변동)과 Token 소비 실시간 대시보드가 더해져 가격에 민감한 개발자에게 현실적인 매력을 구성합니다. 세 번째 장점은 **관측 가능성**입니다: 궤적 뷰가 제공하는 이벤트 수준 리플레이, 출처별 조회 능력, "모델이 본 것은 곧 기록된다"는 로그 원칙은 Agent 행위를 블랙박스에서 감사 가능한 대상으로 바꿉니다. 네 번째 장점은 **생태계 잠재력**입니다: 21.7만 스타의 관심도, 공개 당일 288개의 서드파티 플러그인 저장소, 공식 100개 이상의 내장 플러그인은 개발자가 마주치는 문제에 이미 커뮤니티 선구자가 부딪혀 봤을 확률이 높다는 뜻입니다. 다섯 번째 장점은 **Headless 배치 능력**입니다: 공식 Python SDK가 프로그래매틱 루프로 모듈별 작업 실행을 지원하며, 이 능력은 크로스 저장소 코드 마이그레이션, 대량 테스트, 무인 파이프라인 등의 시나리오에서 인터랙티브 도구가 대체할 수 없는 가치를 갖습니다.

### 5.2 DeepSeek Harness의 단점과 리스크

장점만큼 명확한 것이 그 약점입니다. 첫째, **성숙도 리스크**: 개발자 프리뷰 상태에 공식이 명시한 파괴적 변경 가능성이 겹쳐, 현재 버전을 기반으로 구축하는 모든 프로덕션 시스템은 마이그레이션 비용을 예비해야 하며, Wavect는 "버전을 고정하고 마이그레이션 비용을 예비하라"고 조언하고 "프리뷰 버전 기본값으로 고객 대면 자율 작업을 온라인에 올리지 말라"고 경고합니다. 둘째, **보안 경계의 완전성에 대한 의문**: Wavect 평가는 파일 시스템 샌드박스가 네트워크 접근과 프로세스 가시성을 커버하지 않으며, 구버전 Landlock 환경과 현재 Windows ACL 경계는 부분적인 강제만 제공할 수 있다고 명확히 지적했고, 엔터프라이즈 배포는 네트워크 정책, 독립 신원, 플러그인 심사, 적대적 테스트 등의 통제 조치를 스스로 보충해야 합니다. 셋째, **신뢰성 문제의 실측 기록**: AtlasCloud의 평가에서 같은 작업을 세 번 실행한 결과 모두 완료를 주장했지만 하나의 페이지만 정상 사용 가능했고; 해당 평가는 또 문서 사이트에 설명되지 않은 두 줄의 YAML 설정(compat.thinkingFormat과 maxTokens)이 작업을 36단계 422초에서 15단계 152초로 단축할 수 있음을 발견해, 문서와 구현의 동기화 지연을 방증합니다. 넷째, **리소스 점유 논란**: AtlasCloud는 npm 설치가 531개 패키지 총 306 MB를 다운로드했다고 기록했고(패키지 자체는 겨우 172 KB), Hacker News에는 빌드 후 1.5 GB, 유휴 세션 메모리 500 MB 등의 피드백이 있었습니다. 해당 평가가 동시에 유휴 시 Web 서버가 35-40 MB RSS만 점유한다고 지적했지만, 의존 체인에 대한 커뮤니티의 의문은 실재합니다. 다섯째, **설정 학습 곡선**: Cordis 플러그인 메커니즘, Profile과 조합 패키지 개념은 "그냥 꺼내 쓰고 싶은" 사용자에게 장벽이 되며, 보커위안(博客园)과 DataCamp의 평가 모두 제공자를 설정하고 profile에 익숙해지는 단계가 필요하다고 언급했습니다.

### 5.3 Apache Maka의 장점

Maka의 첫 번째 장점은 **거버넌스 신용**입니다: Apache 소프트웨어 재단의 인큐베이션 보증이 가져오는 것은 장기 거버넌스 약속입니다 — 프로젝트는 어떤 모델 벤더에도 속하지 않고, 의사결정은 공개적으로 이루어지며, 지식재산권은 인큐베이터 심사를 거치고, 라이선스는 Apache 2.0입니다. aiguide.cc는 이를 첫 번째 장점 "장기 신뢰성이 높다"로 꼽았고, agentconn.com은 "Apache 재단의 지원이 장기 유지보수에 대한 신뢰를 준다"고 평가했습니다. 두 번째 장점은 **공개 측정 문화**입니다: 프로젝트는 "측정으로, 주장으로가 아니라"를 공식 README 첫 번째 항목에 적었고, 발표하는 모든 평가 보고서에 과제별 CSV를 첨부하며, OpenCode와의 페어링 비교의 통계 검정 세부 사항(McNemar 검정, p = 0.0118)도 공개했습니다. 평가권을 마케팅 수사가 아닌 재현 가능한 데이터에 맡기는 이런 방식은 Agent 도구 생태계에서 실로 드물며, 미디어 인용에 드물게 "검증 가능한" 소재를 제공합니다. 세 번째 장점은 **감사급 실행 기록**입니다: append-only RuntimeEvent 로그가 메시지, 도구 호출, 권한 결정, 종료 이벤트를 커버하고, "오래된 도구 출력은 다음 라운드 prompt에서 빠질 수 있지만 로그에서는 빠지지 않는" 컨텍스트 절삭 전략과 결합해 Agent 세션에 재현 가능, 복구 가능, 감사 가능의 삼중 속성을 부여하며, "더 짧은 컨텍스트가 히스토리 삭제를 의미하지 않는다"는 점에서 성능과 증거 보존의 모순을 해결합니다. 네 번째 장점은 **로컬 데이터 주권**입니다: 세션, 키, 실행 기록이 기본적으로 로컬 머신에 남고, 모델은 클라우드도 로컬도 연결 가능하며, 샌드박스 경계 초과 승인, 0600/0700 파일 권한, IPC 페이로드 검증 등의 설계와 결합해 프라이버시 민감 시나리오의 완전한 솔루션을 구성합니다. 다섯 번째 장점은 **제품 완결성**입니다: 데스크톱, TUI/CLI, Eval 세 진입점이 단일 Runtime Host를 공유하고, 평가가 곧 프로덕션 경로인 설계는 환경 편차를 피하며, 이는 "일상 사용도 하고 평가도 해야 하는" 기술 팀에 추천할 때 독특한 셀링 포인트입니다.

### 5.4 Apache Maka의 단점과 리스크

Maka의 단점 역시 솔직하게 보여야 합니다. 첫째, **릴리스 상태의 공백**: 프로젝트는 아직 Apache 정식 릴리스 버전이 없고, 공식 README는 사전 빌드 다운로드를 권하지 않으며, 사용자는 불안정한 Nightly 프리뷰를 쓰거나 소스에서 빌드해야 하고, 이 상태는 일반 사용자에게 실질적인 사용 장애를 구성합니다. 둘째, **플랫폼 커버리지는 아직 상승 중**: 공식 Nightly의 Windows와 Linux 빌드는 모두 서명되지 않은 프리뷰이며, 제3자 리뷰는 더 이른 시점에 심지어 "Linux가 아직 지원되지 않는다"고 기록했으므로, 비macOS 사용자의 실제 경험에는 상당한 불확실성이 존재합니다. 셋째, **생태계 규모의 한계**: 5.1천 스타와 476 포크의 규모(열람 시 데이터)는 DeepSeek Harness와 Codex, OpenCode 등 경쟁 제품보다 훨씬 작고, 플러그인과 서드파티 통합은 아직 축적기이며, aiguide.cc는 "프로젝트가 비교적 새롭고, 생태계·플러그인·서드파티 통합이 아직 축적 중"이라고 명확히 지적했습니다. 넷째, **높은 시작 장벽**: 프로젝트 측 스스로 "Runtime 설계의 선진성이 제품 완결성과 초보자 온보딩 경험을 앞질렀다"고 인정했고, 빌드 환경은 Node.js 22.19 이상, ripgrep, 심지어 Rust 툴체인(Peer 모드)을 요구해 초보자에게 충분히 친화적이지 않습니다. 다섯째, **데이터 형식 안정성 리스크**: 공식 README는 "Maka는 아직 활발히 개발 중이며, 데이터 형식, CLI 명령, 실험 능력이 변할 수 있다"고 명확히 하고, 업그레이드 후 구 JSONL 기록은 임포트되지 않으며 자격 증명은 다시 입력해야 하므로, 기존 사용 데이터가 있는 초기 사용자에게는 마이그레이션 비용을 의미합니다. 종합하면, Maka의 포지셔닝은 "기술 철학은 선진적, 거버넌스 신용은 탄탄, 제품화는 아직 이르다"는 삼각형에 초점을 맞추고 과도한 약속을 피해야 합니다.

## 6. 글쓰기 가이드와 소재 추출

### 6.1 서사 주선과 구조 제안

이번 추천은 "하나의 질문, 두 갈래 노선, 한 번의 무대 위 대결"이라는 서사 주선을 채택할 수 있습니다. 서두는 2026년 8월 13일의 "같은 날의 인연"으로 서스펜스를 만듭니다: 같은 날, 한 벤더는 역사상 가장 빠르게 성장한 Agent 프레임워크를 오픈소스로 공개했고, 한 재단은 최초의 Agent Harness 프로젝트를 받아들였습니다. 이어서 글 전체를 관통하는 질문을 제기합니다: Harness가 모델보다 더 중요한 변수가 될 때, 개발자는 "교체 가능한 개방 기반"과 "기록 가능한 로컬 워크벤치" 중 무엇을 선택해야 하는가. DeepSeek Harness를 소개할 때는 "모든 것이 플러그인" 개념으로 전개하고, 네 가지 실행 모드를 뼈대로 삼고, 21.7만 스타와 첫날 288개의 플러그인 저장소를 인기의 증거로 삼고, 궤적 뷰와 비용 데이터를 실용 가치의 논증으로 삼습니다. Maka를 소개할 때는 "로그가 곧 런타임" 공식으로 시작하고, Terminal-Bench 2.1의 77.5% 대 73.0% 데이터로 대비의 긴장감을 만들고, Apache 거버넌스와 로컬 우선 서사로 마무리합니다. 비교 장에서는 4절의 비교표를 그대로 사용하고, "같은 모델에서 Harness를 바꾸면 63%의 과제 결과가 바뀐다"는 가장 전파력이 강한 데이터 포인트를 곁들입니다. 결말은 "도구 선택"이 아닌 "철학 선택"에 닿습니다: 자체 구축과 오케스트레이션이 필요하면 DSH를, 기록과 감사가 필요하면 Maka를 선택하고, 둘은 심지어 상호 배타적이지도 않습니다 — DSH의 플러그인 아키텍처는 이론적으로 Maka식 로그 전략을 담을 수 있고, Maka의 Eval 프레임워크 역시 DSH를 평가할 수 있습니다.

### 6.2 핵심 데이터 포인트와 명문장 소재 라이브러리

다음은 다중 소스 검증을 거친 데이터 포인트와 표현으로, 안심하고 인용하고 출처를 표기할 수 있습니다. 인기 관련 데이터: DeepSeek Harness 공식 저장소 21.7만 스타, 2.57만 포크, 16089회 커밋(2026년 9월 9일 열람 시 데이터), 공개 후 3일(역일 기준) 안에 스타 12.1만 초과; Maka 저장소 5.1천 스타, 476 포크, 4507회 커밋, 2026년 8월 23일 GitHub Trending 1위 등극. 성능 관련 데이터: Terminal-Bench 2.1 9개 Harness 통과율이 Codex 82.0%에서 Claude Code 55.1%까지의 전체 순위, Maka 77.5%로 2위, DSH 73.0%로 4위, 89개 과제 중 56개(약 63%)의 결과가 Harness에 따라 변경; 비용 측면에서 Maka 약 0.0263달러/과제, DSH 약 0.0262달러/과제, Claude Code 0.0537달러/과제. 명문장 소재: "Agent 시대의 안드로이드"(DSH에 대한 큐비트AI의 비유); "Measured, not claimed"와 "State(t) = Project(Log[0…t])"(Maka 공식 홍보 문구); "모델은 뇌이고, Harness는 손발과 신경계다"(공식 정의에 대한 보커위안(博客园)의 재서술); "Claude Code가 마감된 신축 아파트라면, Harness는 시공 도면까지 오픈소스인 조립식 건물이다". 커뮤니티 관련 데이터: Maka의 10주 동안 71만 줄 TypeScript, 35만 줄 테스트, 93.8% PR 머지율, 33.5분 머지 중앙값; DSH 공개 당일 288개의 dsh-plugin 저장소. 이 소재들을 사용할 때는 "데이터 시점"을 함께 기입해야 합니다(예: "9월 9일 기준"). 두 제품의 스타와 버전 데이터가 모두 빠르게 변동하고 있기 때문입니다.

### 6.3 표현 함정과 팩트체크 요점

글을 쓸 때 다음 표현 함정에 특히 주의해야 합니다. 첫째, DSH의 인터페이스 형태에 관하여: 보커위안(2026년 8월 20일)은 "현재 웹 버전만 있고 CLI가 없다"고 했고, DataCamp(8월 24일)는 "로컬 Web UI, 헤드리스 CLI, Python SDK"가 병존한다고 기록했습니다. 제품 이터레이션이 극히 빠르므로 "Web UI를 주 진입점으로 하고, 헤드리스 CLI와 Python SDK가 프리뷰 기간에 점차 보강되었다"는 안전한 표현을 쓰고 절대적 판단으로 쓰는 것을 피해야 합니다. 둘째, Maka의 플랫폼 지원에 관하여: 공식 README의 Nightly 매트릭스(macOS AS/Intel, Windows x64, Linux x64/arm64)와 일부 제3자 리뷰의 보수적 기록 사이에 시점 차이가 있으므로, 공식 입장을 기준으로 하되 "제3자 리뷰가 기록한 시점이 더 이르다"고 명시해야 합니다. 셋째, 스타 숫자에 관하여: 서로 다른 매체가 서로 다른 시간에 샘플링한 DSH 스타 수는 차이가 매우 큽니다(이틀 9.5만, 나흘 14.1만, 12시간 5만 등). 인용 시 반드시 샘플링 시간을 명시하거나 "본문 열람 시점 기준" 표현을 통일해서 사용해야 합니다. 넷째, 횡단 평가의 귀속에 관하여: Terminal-Bench 2.1 9개 Harness 데이터는 공개적이고 투명하지만 Maka 프로젝트 측이 주도해 실시했으므로, 글에서는 "Maka 프로젝트 측이 공개한, 과제별 CSV와 재현 PR이 첨부된 횡단 평가 데이터"로 표현해 독자에게 "독립 제3자 평가"라는 착각을 주지 않아야 합니다. 다섯째, "역사상 가장 빠른"류 표현에 관하여: Wavect는 이 주장이 GitHub 공식 인증을 받지 않았다고 명확히 지적했으므로 "오픈소스 역사에서 드문 폭발적 속도"로 약화할 것을 권합니다. 여섯째, v2ex의 실측 데이터(6000만 token, 97.5% 캐시 적중, 약 4위안 비용, 점수 0.8-0.9)는 프로젝트 측 자체 진술이므로 인용 시 "프로젝트 측이 공개한 초기 실측"이라고 표기해야 합니다.

### 6.4 제목 방향과 독자 계층화 전략

두 제품의 소재 특성에 기초해 세 가지 유형의 제목 방향을 고려할 수 있습니다. 데이터 충격형 제목은 횡단 평가 데이터로 대비를 직접 만들 수 있습니다. 예: "같은 DeepSeek V4 Flash인데 Harness를 바꿨더니 24개 과제 차이 — 이번 회에는 4.5%포인트 차이의 이 두 사람을 추천합니다". 개념 앵커형 제목은 각자의 핵심 주장을 부각할 수 있습니다. 예: "하나는 모든 것을 플러그인으로, 하나는 모든 것을 로그로: 2026년 가장 따라가 볼 가치가 있는 Agent Harness 쌍웅". 관점 유도형 제목은 깊이 있는 독자에게 적합합니다. 예: "벤더의 안드로이드와 재단의 장부: DeepSeek Harness와 Apache Maka의 노선 경쟁". 독자 계층화에서는 본문을 "5분 속독 버전"(핵심 포지셔닝 한 문장, 핵심 데이터 한 표, 적합한 대상 한 단락)과 "심층 전개 버전"(아키텍처 원리, 평가 세부, 리스크 목록)으로 나누어 각각 일반 테크 독자와 개발자 독자에게 서비스할 것을 제안합니다. 적합한 대상 표현은 다음과 같이 제안합니다: DeepSeek Harness는 오픈소스와 커스터마이즈를 중시하고, 배치 무인 작업이 필요하고, 여러 AI 도구를 하나의 워크플로로 통합 오케스트레이션하고 싶고, 비용에 민감하면서 프리뷰 기간의 변동을 받아들일 수 있는 개발자와 플랫폼 엔지니어링 팀에 추천; Apache Maka는 실행의 감사 가능성과 데이터 주권을 중시하고, 로컬에서 Agent를 실행해야 하고, 컴플라이언스 요구가 있거나 세션 크래시로 작업을 잃은 적이 있고, 인큐베이션 기간과 소스 빌드 장벽을 받아들일 의향이 있는 사용자에게 추천. 글의 끝에는 "프로덕션 환경에서는 신중하게"라는 통일된 안내와 각자의 공식 저장소·문서 링크를 첨부해야 합니다. 이는 전문성의 구현이자 두 제품 공식이 버전 상태에 대해 스스로 정한 포지셔닝에도 부합합니다.

## 7. 결론과 전망

이번에 추천한 두 프로젝트는 함께 지금 일어나고 있는 하나의 업계 판단을 증명합니다: 모델 능력이 수렴하는 시대에 Harness는 이미 에이전트 성능의 결정적 변수 중 하나가 되었고, "어떤 철학으로 Harness를 구축하는가"가 "어떤 Harness를 쓰는가"보다 더 생각할 가치가 있는 질문이라는 것입니다. DeepSeek Harness는 MIT 라이선스, 21.7만 스타, "모든 것이 플러그인"의 철저한 개방으로 벤더 주도의 오픈소스 생태계가 도달할 수 있는 동원 속도와 확장 한계를 보여주었고; Apache Maka는 Apache 2.0 라이선스, 중립 거버넌스, "로그가 곧 런타임"의 기록 철학으로 재단 노선이 Agent 인프라 계층에서 갖는 실현 가능성과 차별화 가치를 증명했습니다. 같은 벤치마크 아래에서의 직접 대결 — Maka 77.5% 대 DSH 73.0%의 통과율, 거의 같은 과제당 비용 —은 둘이 같은 세대 제품으로서 기술 수준이 가까움을 보여주는 동시에, "Harness 간의 경쟁"이 장기적으로 역동적인 줄다리기 상태에 있을 것임을 시사합니다.

미래를 내다보면, 지속적으로 추적할 가치가 있는 세 가지 방향이 있습니다: 첫째, DeepSeek Harness가 언제 첫 안정 버전을 릴리스하는가는 이것이 "현상급 프리뷰"에서 "프로덕션급 플랫폼"으로 갈 수 있는지를 직접 결정하며, 공식 문서는 이미 현재 버전에 대해 "프로덕션 시스템을 이에 고정하는 것을 당분간 권하지 않는다"고 명확히 했습니다; 둘째, Apache Maka가 인큐베이션 기간 안에 첫 ASF 정식 릴리스를 완료하고 온보딩 경험을 개선할 수 있는가는 "기록 철학"이 제품화 착지 능력을 갖췄는지를 검증할 것이며, 프로젝트 측은 이미 제품 완결성이 초보자 온보딩 경험의 약점임을 공개적으로 인정했습니다; 셋째, 두 제품이 대표하는 "플러그인화"와 "로그화" 두 노선이 융합될 것인가 — DSH의 추가식 세션 로그와 Maka의 RuntimeEvent는 이미 제3자에 의해 "같은 최전선 방향"으로 평가받았고, Harness 간에 Agent Client Protocol을 통해 서로를 구동하고 심지어 서로의 서브 에이전트가 되는 트렌드는 "한쪽을 선택"하는 것이 최종적으로 "양쪽을 조합"하는 것으로 바뀌게 할 수 있습니다. 이 두 저장소의 버전 페이지와 공식 공지에 분기별로 재방문하는 것이 본문의 생명력을 이어가는 최저 비용 전략이 될 것입니다 — 이 두 프로젝트의 앞으로의 모든 릴리스가 그 자체로 새로운 기획 소재가 될 수 있기 때문입니다.
