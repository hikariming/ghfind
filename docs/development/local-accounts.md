# 本地测试账号与登录态

第一次运行 `pnpm run init`。初始化会自动生成测试身份和本地签名密钥、应用 D1 migrations、写入明确标注为合成资料的个人页数据，并保存 Playwright 登录态。不需要注册真实 GitHub 账号或提供第三方密码。

```sh
pnpm run init
pnpm dev:local
# 另一个终端，按角色打开已登录的浏览器：
pnpm local:open owner
```

本地应用固定使用 http://127.0.0.1:4390。不要替换为 localhost：测试 cookie 仅对 127.0.0.1 生效。端口被占用时启动失败，不会停止占用进程。

| 角色别名 | 实际权限及用途 |
| --- | --- |
| `owner` | 普通 GitHub 身份，默认被查看资料的所有者 |
| `other` | 第二个普通 GitHub 身份，验证同组数据隔离 |
| `internal` | Discover 内部白名单 GitHub 身份 |
| `social` | 仅 Google 站点身份，不具有 GitHub 权限 |
| `guest` | 无登录态 |

站点目前没有统一管理员用户组。`ADMIN_SECRET` 是运维凭据，不生成所谓“管理员用户”去替代它；GitHub App 仓库管理员权限仍需独立的安装授权验证。账号名和 ID 首次随机生成后保留，用户只需使用角色别名。

## 日常使用

- `pnpm local:open other`：打开独立浏览器并加载指定角色会话，默认进入 owner 个人页。关闭浏览器即结束命令。
- `pnpm local:verify`：使用真实本地 `/api/me`、Discover 权限接口和个人页，检查全部角色的身份、权限及真实个人页，并保存截图；同时验证目标账号切换、用户名大小写、无效签名、过期会话及清除 cookie 后的匿名状态。
- `pnpm local:renew`：重新签发有效期七天的本地会话。启动、打开和验证命令也会自动重新签发；已经打开的浏览器需重新打开以载入新会话。
- 再次 `pnpm run init`：保留账号 ID、密钥和已有数据，补缺失身份及数据，应用新增迁移。不会清空数据库。

所有账号、密钥、会话、截图及独立 D1 状态保存在 `.local/dev/`，整个 `.local/` 已被 Git 忽略。目录权限 0700，账号和会话文件 0600。不要上传或在终端输出其内容。

需要清空这套开发环境时，先停止 `pnpm dev:local` 和测试浏览器，明确确认不再需要本地数据后删除 `.local/dev/`，再运行 init；这会重新生成账号与密钥。日常开发不要这样重置。

`pnpm local:check` 单独检查工具类型，根目录 `pnpm typecheck` 也会运行该检查。

## 验证边界

`dev:local` 使用独立 Wrangler 配置和本地 D1，不使用远端存储。启动环境屏蔽项目 dotenv 中的既有服务配置，并禁用第三方 OAuth 入口。正常 `pnpm dev` 和 Astro 的启动命令不会自动加载本套测试环境；本套验收使用 Next 本地完整页面及 API。

会话通过项目现有签名实现生成，由真实后端校验，不拦截 `/api/me`。生产鉴权实现不作放宽，代码中不添加测试登录路由。这里只验证本地用户态与权限，不代表第三方 OAuth 或 GitHub App 安装流程已通过。外部 API、邮件、LLM、扫描任务等集成应按各自流程另行配置和验证。
