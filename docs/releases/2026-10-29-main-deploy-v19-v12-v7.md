## Why #606 used admin merge

`versions:check --base-ref` forbids multi-component formal releases
(`maxComponentsPerPullRequest: 1`). The `dev → main` tip changed **score and
collection** together versus `0ba10dec`, and `previousRelease` on tip did not
carry that prior target forward, so PR #606 CI failed Verify release /
Application checks at the versions gate only.

Owner approved admin merge of #606 (`bc1b1d65`, match-head `82d6cb41`) with
pre-merge `main` recorded as `0ba10dec` for rollback. Same-SHA push CI on `dev`
and local typecheck/lint/test/go/build substitutes were green; only the
multi-component / previousRelease gate failed.

Push CI on `main` for `bc1b1d65` then failed the same gate against
`github.event.before = 0ba10dec`, so **Deploy production (Cloudflare)** and
**Deploy apps (production)** skipped (they require successful main CI). Code was
on `main`; production Workers / apps / D1 apply from those workflows had **not**
run.
